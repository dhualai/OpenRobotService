## 一句话概览

移动端优先的机器人运维工单 + AI 诊断工作台。三大视角收口在一个底部 Tab 工作台里：
**我要摇人**（AI 诊断 + 提单）｜ **系统任务**（AI 任务助手 + 工单列表）｜ **后台管理**（项目/风险/人员/权限等看板）。

## 路由架构（核心，2026-07-16 重构）

所有业务页统一收口到 `/app`，由 `AuthGuard` 包裹的 `MainLayout`（底部三 Tab）承载：

```
/login, /no-permission                          # 无守卫
/app  → AuthGuard > MainLayout（底部 TabBar）
  ├─ /app/call            → CallView      （我要摇人）
  ├─ /app/call/ticket/:id → TicketDetailPage（摇人「历史工单」详情操作页，全屏）
  ├─ /app/tasks           → TasksView     （系统任务，列表+详情）
  ├─ /app/tasks/:id       → TasksView     （直接打开工单详情）
  └─ /app/admin           → AdminView（入口卡片网格）
       └─ AdminLayout（顶部 Navbar + ☰ 抽屉菜单，无底部 Tab）
            ├─ dashboard / project-manage / project-edit/:id?
            ├─ progress / personnel / project-hr / project-auth
            ├─ risks / risk-edit/:id? / reports
            ├─ data-import / operation-logs
            ├─ users / roles / permissions / resources
            └─ daily-reports                       # 共 17 个 admin 子页
```

**旧路由（`/`、`/home`、`/call`、`/tasks`、`/admin` 及其子路径、`*`）全部 `Navigate` 重定向到 `/app/call`。**
HomePage（旧临时导航页）已移除。路由定义见 `src/router/index.tsx`。

### 历史工单列表浮层右滑关闭（2026-08-01）
- **背景**：`HistoryTickets` 历史工单列表是 `CallView` 内的覆盖层（由 `showHistory` state 控制显示），路由始终是 `/call`（顶层）。此前尝试的全局 `history.back()` 拦截方案已回滚（会影响其它一级 Tab 的右滑语义），改为更局部、可控的方案。
- **方案**：新增 `shared/utils/useSwipeToClose.ts` 的 `useSwipeToClose(onClose)` hook，挂在 `CallView` 历史工单覆盖层容器上；用户在该浮层内横向右滑（位移 > 50px 且横向 > 纵向）即 `setShowHistory(false)` 关闭浮层，**不回滚路由、不退出应用**。
- **手势隔离**：`useSwipeToClose` 仅读 touch 坐标、不 `preventDefault`，与浮层内 `PullToRefresh` 的纵向滚动互不干扰（纵向滑动 |dy| > dx，不会误触发）。
- **系统边缘右滑拦截**：`useSwipeToClose` 只能拦浮层区域内的 touch 右滑，拦不住 iOS 微信屏幕最左边缘的系统级返回手势（系统在页面 touch 之前就消费）。故 `CallView` 额外用 `useEffect`：浮层打开时 `pushState` 一层占位历史（复制 react-router 当前 `history.state` 保持兼容），使边缘右滑先 pop 占位层（触发 `popstate`）而非退出 webview；`popstate` 时 `setShowHistory(false)` 关闭浮层，占位层被自然消费、history 深度恢复。浮层区域内 touch 右滑与边缘系统右滑二者互补，均转为关闭浮层。

## 三大视角与跨视图联动（workbench store）

第二个全局 store `src/stores/workbench.ts` 是三视角数据流转中枢（**全局不止 auth 一个 store**）：

| 字段 | 流向 | 作用 |
|------|------|------|
| `ticketDraft` | Call → Tasks | AI 诊断结果打包成草稿，`goToTab('tasks', {ticketDraft})` 后 TasksView 消费并自动建单 |
| `chatContext` | Tasks → Call | 工单「讨论」按钮带标题/描述回到 AI 对话注入引导语 |
| `selectedTicketId` | — | 建单/跳转后自动展开详情 |
| `tasksRefreshKey` | — | +1 触发 TasksView / HistoryTickets 重新拉取 |
| `activeTab` | — | 与路由 + TabBar 双向同步高亮 |

统一入口 `goToTab(tab, payload)`。消费型字段用 `consumeXxx()`（取出即清空）。

### 三视角页面构成
- **CallView（我要摇人）**：上 60% `ChatPanel`（全屏）+ 下 40% `HistoryTickets`（我提交的工单，虚拟滚动）。
- **TasksView（系统任务）**：上 `ChatPanel compact` + 下工单卡片列表（搜索/状态筛选/分页）+ 右侧 Popup 工单详情（催办/修改/讨论/升级上报）。
- **AdminView**：按角色（`isAdmin`）渲染入口卡片，点击进 AdminLayout 子页。

## AI 模块（`src/api/ai.ts`，走 `/api/ai/qa/*` 与 `/api/ai/memory/*`，本地开发后端）

诊断 Agent 接口走 `/qa/*`；历史工单列表走 `/memory/tickets/all`（`/chat/*` 纯对话此前未接线，已移除）：
- `qaAskStream`（SSE 流式，`data.token` 增量）、`qaSubmit`（转工单）、`qaGetTicket`、`qaTicketAck`（派单回执）、`qaUpload`（附件 FormData）。
- `qaListTickets(skip, limit, filters?)`（历史工单列表，GET `/api/ai/memory/tickets/all`；按角色：admin 全部/其余仅本人；`filters` 可选 `status`/`type` 筛选）。

- `session_id` 由前端生成（`generateSessionId`）并存 localStorage（`ai_sessions`，最多 50 个）。
- SSE 用原生 `fetch` + `ReadableStream` 读取（`fetchWithAuth` 带 Bearer token），**不走** `api/client.ts`。
- `ChatPanel`（`src/shared/components/ChatPanel.tsx`）是对接 SSE 的可复用对话面板，call/tasks 两场景共用，功能：流式输出、点赞点踩、复制、修改重发、语音、上传/拍照、ENTER 发送、call 场景转工单。**对话历史 DB 持久化**：经 `api/conversation.ts`（`/api/call/conversations` + `/messages`）每轮 user/assistant 消息落库，挂载时按"当前用户+场景"恢复最近一条会话（含 ai_session_id）。**流式断连恢复**：后端 SSE 采用 producer-consumer 解耦（pipeline 在独立后台任务运行，SSE 断连不取消生成）；前端刷新后 `mapDbMessages` 检测到最后一条 assistant 消息 content 空（producer 仍在生成）时标记 `streaming` 占位，会话加载 effect 每 2s 轮询 `getConversation`，producer 落库完整回复后自动替换占位气泡。**call 场景转工单**有两条触发路径，**统一走「二次确认弹窗」**（字段齐全不自动入库，弹窗核对/修改 → `POST /qa/ticket/confirm` → `confirm_submit` 入库），建单后留在摇人页（不再跳系统任务）：
  - ① 外层「转工单」按钮：`handleSubmitTicket` 调 `qaPrepareTicket` → `stage=draft_ready`/`need_fields` 弹 `ticketConfirm` → `handleConfirmTicket` 调 `qaConfirmTicket` 入库 → `refreshTasks()`。
  - ② 对话内输入「转工单」等关键词：`pipeline.run_stream` 字段齐全时发 SSE `event:status + stage:review`（含 draft，**不直接 submit**）；`ChatPanel.processLine` 收到 review 事件 → 弹 `ticketConfirm`（复用按钮路径的弹窗/确认逻辑）→ `qaConfirmTicket` 入库 → `refreshTasks()`。

## 渲染与安全

- **`MarkdownRenderer.tsx`**：AI 流式返回内容的 GFM 解析 + 媒体渲染。`react-markdown` + `remark-gfm`（**已重新引入**，不要按旧文档删除）。管线：`stripCodeFences`（剥掉 LLM 把整段回复用 ``` 包裹、避免渲染成黑底代码块）→ `preprocessMediaUrls`（裸 URL→图片/视频）→ `react-markdown` 解析 → 自定义 `img/a/pre/code/table/p`；`AuthImage` 对同源/相对路径图片做 Bearer token 鉴权加载（blob URL）。外层 `MdErrorBoundary` + `simpleMarkdownToHtml` 兜底：react-markdown 异常时降级为简易 HTML，不白屏。
- **`AuthImage` 点击预览**：markdown 内渲染的图片（`md-image--clickable`）点击即通过 `ImageLightbox` 全屏放大预览，灯箱内提供「复制」「下载」按钮与左上角关闭按钮（移动端/PC 端通用，通过 Portal 挂载到 body）。复制走 `ClipboardItem`（需安全上下文），不支持时降级提示「长按图片保存」。
- **`ImageLightbox.tsx`**：通用图片灯箱组件（点击放大 + 复制 + 下载），零外部 UI 依赖，`ChatPanel` 用户气泡图片与 `MarkdownRenderer` 内 AI 回复图片共用此组件，保证预览/复制/下载体验一致。
- **`AttachmentViewer.tsx`**：统一附件预览组件（Portal 挂载 body）。图片走 `ImageLightbox`（灯箱 + 下载）；PDF 走 `<iframe>` 内联（`/api/tasks/files/{path}` 返回 `Content-Disposition: inline`，可直接预览）；Markdown 用 `fetch` 取文本后经 `react-markdown + remark-gfm` 渲染（`md-content` 样式，刻意不加 `rehype-raw` 避免附件 HTML 的 XSS）；其它格式给出「暂不支持预览」提示并提供下载。组件带「下载」按钮（主附件走带 token 的 `/attachments/download`，评论附件走内联 URL）；**微信 UA 下优先调 JS-SDK 原生预览**（`wx.previewImage` 图片 / `wx.previewFile` PDF·Office，复用既有 `/api/wechat/config/js-sdk-config` 签名、扩展 `jsApiList` 注入 `previewImage`/`previewFile`，URL 走后端 `/api/tasks/files/{path}` 同域代理），调起失败回退 H5 预览并提示「点右上角 … 在浏览器打开」。系统任务工单详情页主附件区（`pages/tasks/TaskDetailPage`）、摇人历史工单详情页主附件区（`pages/call/TicketDetailPage`）、讨论区评论附件（`DiscussionPanel`）三处共用此组件，替换原「主附件只能下载 / 评论非图片只能 window.open」的旧逻辑。
- **`SafeHtml.tsx`**：dompurify 清洗后渲染可信 HTML（工单详情/评论），用于非 AI 的用户内容。
- XSS：MarkdownRenderer 输出 React 虚拟 DOM，不叠 dompurify；SafeHtml 才用 dompurify。

## 认证架构（三层）

1. **API 客户端层** `src/api/client.ts`：`createRequest(baseUrl, serviceName)` 工厂；全局 token（`setToken`/`clearToken`/`initToken`）；GET 5 分钟缓存（`skipCache` 跳过）；401 自动刷新（pub-sub 防并发）；500+ 重试 2 次指数退避；30s 超时映射 408；`skipAuth` 跳过 token；统一 `ApiError`。
2. **Zustand 层** `src/stores/auth.ts`：`isLoggedIn/username/token/isAdmin/roles`；`checkLoginStatus`（启动恢复）、`login/logout/refreshAuthToken/fetchUserDetails`。`main.tsx` 启动时先 `checkUrlTokens()` 再 `checkLoginStatus()`——**必须在 `RouterProvider` 渲染前提取 URL token**：访问 `/p/app/call?token=...`（微信菜单链接，单层 `/app`）会命中旧路由 `<Navigate>` 重定向到 `/app/call` 而丢 query，若不在路由匹配前取出，AuthGuard 里的 `checkUrlTokens` 就再也拿不到 token；提前取出存 localStorage 后，带 token 直链可直接登录（会硬刷新一次去掉 URL 上的 token）。
3. **路由守卫层** `src/shared/utils/authGuard.tsx`：`AuthGuard` 包裹 `/app`；未登录时按 `WECHAT_CONFIG.loginEnabled` 决定跳转——**启用微信登录则跳微信 OAuth 授权页**（先尝试 `checkUrlTokens` 从 URL 恢复 token，再 `buildWechatAuthUrl` 构造 `open.weixin.qq.com` 授权链接，state 由 `buildStateFromPath()` 把**完整目标地址**（`origin + 部署前缀 + 路由路径`）做 base64url 编码，后端解码后原样回跳，避免丢失 `/p/app` 前缀）；否则跳 `/login` 账密页。`requireAdmin` 跳 `/no-permission`；`VITE_DISABLE_AUTH_GUARD=true` 可跳过（测试用）。登录页 `pages/Login.tsx` 在启用微信登录且非 `?debug=true` 时也会直接跳微信（`?debug=true` 保留账密表单，供后台人员登录）；`VITE_WECHAT_REDIRECT_URI` 显式覆盖回调地址（生产必须带 `/p/api` 前缀）。

## 后端与代理（`vite.config.ts` + `src/config/api.ts`）

后端拆为两个独立服务（与 `deploy/nginx/conf/conf.d/app_gateway.conf` 对齐）：
- **业务后端** `backend/main.py` @**8400**：`/api/auth|admin|tasks|call|wechat`
- **AI 服务** `ai/run.py` @**8401**：`/api/ai/*`（诊断/对话/记忆，含 SSE 流式）

| 服务 | BASE_URL | 用途 |
|------|----------|------|
| AUTH | `${API_ROOT}/auth` | 登录/注册/刷新/用户信息 |
| CALL | `${API_ROOT}/call` | AI 对话/会话/消息/我的任务（业务后端侧） |
| **AI** | `${API_ROOT}/ai` | 诊断 Agent / LLM 对话 / 会话记忆（**独立 AI 服务 @8401**） |
| TASKS | `${API_ROOT}/tasks` | 工单 CRUD/评论/附件/状态流转 |
| ADMIN | `${API_ROOT}/admin` | 项目/风险/日报/用户/角色/权限/资源 |

`API_ROOT` 由 `config/api.ts` 据 vite `base` 自动推导，**dev 与打包天然一致**：
- **dev**（`base='/'`）：`API_ROOT='/api'`。`vite.config.ts` 代理拆分——`/api/ai/*`→AI(8401)、其余 `/api/*`→业务后端(8400)；本地需同时启动 `backend/main.py` 与 `ai/run.py`。目标可用环境变量 `VITE_DEV_BACKEND_TARGET` / `VITE_DEV_AI_TARGET` 覆盖。
- **打包**（无 vite 代理，靠 nginx 按环境前缀分发）：`npm run build:test`（`base='/t/app/'`→`API_ROOT='/t/api'`）或 `build:prod`（`'/p/app/'`→`'/p/api'`）；nginx 最长前缀把 `/t/api/ai/*` 转给 AI、`/t/api/*` 转给业务后端，前端无需感知分流。

## 重要约定

1. **路径别名** `@/` → `src/`（vite + tsconfig 均配置）。
2. **导出** 统一 `export default function`；页面懒加载 `React.lazy` + `<Suspense>`。
3. **每个页面左上角返回按钮**：`<Navbar leftArrow onLeftClick={() => navigate(-1)} />`（TDesign `leftArrow` 须显式 `true`）。
4. **`AuthGuard` 仅包裹 `/app`**；`/login`、`/no-permission` 自身无 `AuthGuard`。但 `/login` 在 `VITE_WECHAT_LOGIN_ENABLED=true` 且非 `?debug=true` 时，会由 `Login` 组件直接跳微信 OAuth（与受守卫页行为一致），仅 `?debug=true` 才显示账密表单；`VITE_DISABLE_AUTH_GUARD=true` 时全站跳过守卫。
