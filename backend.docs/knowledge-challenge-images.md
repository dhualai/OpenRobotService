# 高价值问题解答附件与悬赏

用户可在高价值问题的解答编辑区上传图片、预览大图、删除图片，并随文字解答保存草稿或发布。仍需填写文字答案。

- 每条解答图片数量不限，单张不超过 10MB。
- 支持 PNG、JPG/JPEG、GIF、WEBP、BMP；复用已登录用户可用的 `/api/tasks/spec-doc/image` 上传接口，由服务端校验扩展名、文件魔数与大小。
- 图片文件保存至现有对象存储，数据库保存图片代理地址数组，不存图片二进制。
- 图片随私有草稿保存；未再次发布前不会替换公开解答的图片。首次发布后仅可再修改一次，图片变更也受该规则约束。
- 发布历史与到期评选快照包含对应图片地址。既有纯文字答案及旧快照仍可读取。
- 图片不做内容脱敏，上传前请确认不含客户隐私、内部信息、账号口令等敏感内容。

## 回答中的文档附件

- 解答编辑区另设“上传解答文档”入口，支持 Word（DOC/DOCX）、Markdown（MD/MARKDOWN）、Excel（XLS/XLSX）、PDF、PPT/PPTX、TXT、CSV、RTF、ODT/ODS/ODP。
- 文档数量不限，支持多选；单个文档不超过 20MB。图片仍走原入口，单张上限仍为 10MB。
- 文档保存至现有对象存储；数据库附件表保存原始文件名、大小、格式、上传人、本题 ID 和内部存储路径，答案只保存附件 ID 列表。存储路径不返回给客户端。
- 上传和下载均需要登录；上传受题目状态、截止时间及解答修改次数约束。只允许引用本人在本题上传的附件，不能借用其他用户或其他问题的附件 ID。
- 未发布文件仅上传者可下载，包括已发布答案的新编辑草稿。公开答案仅展示已提交附件，编辑草稿不会提前替换公开文件；提交删除后普通读者无法继续下载旧附件。
- 附件变更随草稿保存、发布、一次修改历史和截止快照保存。旧客户端省略附件字段时保留原文件，显式传空数组表示删除。
- 下载经过服务端权限检查，以附件形式返回，保留原始文件名，不直接内联执行或展示文档。已有截止快照的文件列表不受后续答案字段变化影响。
- 文档内容不做自动脱敏，上传前必须确认不含客户隐私、内部信息或口令等敏感内容；删除引用或回滚数据库迁移不会自动清理对象存储文件。

## 零元悬赏与发布者

- 悬赏支持 0 元和正数，仍最多两位小数；负数、非整数分和超出数据库整数范围的金额不接受。
- 零元问题仍正常征集、点赞、到期评选和生成最佳解答快照，但不创建 0 元奖励单或触发支付。
- 榜单摘要、首页预览和问题详情在奖金下方显示发布者的 `users.name` 名称，不使用登录账号或微信 ID；名称为空时不显示发布者。只有现有全局“管理员”“超级管理员”角色或管理员权限的账号可见；普通用户、仅项目级同名角色不会收到发布者字段。

## 回答中的资料链接

- 新发布或重新提交的回答保留公开 HTTP/HTTPS 资料链接，包括普通网址及 Markdown 链接；关联工单的问题与独立问题使用同一规则。
- 本地/内网地址、已识别的内部工单与后台地址、含账号密码或敏感凭据参数的链接仍会隐藏。链接中的已识别姓名、项目、电话、邮箱等敏感内容也不能借网址绕过脱敏。
- 内部业务地址按 `FRONTEND_BASE_URL`、`ZENTAO_BASE_URL` 和路径规则识别；不会访问外部链接或通过 DNS 判断其内容和访问权限，不能据此保证所有外部文档都适合公开。
- 页面将正常链接显示为可点击链接；不执行回答中的 HTML，不自动加载 Markdown 外部图片，图片上传入口与原有功能保持不变。
- 只调整高价值问题回答；问题正文与知识榜内容原有脱敏规则不变。已被替换的历史链接无法从已发布正文自动恢复，需要用户重新填写后提交；原有修改次数和截止时间限制不变。

## 数据库迁移

表 `knowledge_challenge_answers` 的可空 JSON 字段：

- `images`：已发布解答图片地址。
- `draft_images`：未发布的草稿图片地址；`NULL` 表示没有独立草稿，空数组表示已移除全部图片。
- `attachments`：已发布解答的文档附件 ID。
- `draft_attachments`：未发布草稿的文档附件 ID；`NULL` 与空数组含义同上。

新增表 `knowledge_challenge_attachments`，保存文档元数据及内部存储路径，不存文件二进制。

图片迁移为 `f2a5b8c1d437`，前置版本为 `e1f4a7b0c326`；本次文档迁移为 `a4c8e2f6b901`，前置版本为 `f2a5b8c1d437`。部署前备份数据库并核对目标环境配置，在 `backend` 目录使用项目虚拟环境执行：

```powershell
..\.venv\Scripts\python.exe -m alembic current
..\.venv\Scripts\python.exe -m alembic upgrade a4c8e2f6b901
```

仓库当前存在多个迁移分支，因此此处指定高价值问题分支的版本，不使用含糊的 `upgrade head`。本次迁移仅新增可空文档字段及附件表，历史记录无需回填；回滚会删除文档附件字段及附件表，不会删除原有图片字段或对象存储文件。

开发验证仅使用测试内存数据库，不会自动修改测试环境或生产环境数据库。上线需执行迁移并更新前后端部署；对象存储服务也需可用。
