# 权限管控改造总结

本次改造为「项目授权导出」和「资源管理」两个模块新增基于 RBAC 权限码的接口级与前端入口级管控，沿用既有 `backend:<resource>:<sub>:<action>` 命名约定。

---

## 一、新增权限码

### 项目授权导出模块

| 权限码 | 用途 |
|--------|------|
| `backend:project:license:export` | 导出 licence 授权（含完整授权中的 licence 部分） |
| `backend:project:user:export` | 导出人员授权（含完整授权中的 user 部分） |
| `backend:project:license:apply` | 申请项目 licence 授权 |

### 资源管理模块

| 权限码 | 用途 |
|--------|------|
| `backend:resource:base:read` | 查看/检索资源/文件夹/统计/点赞 |
| `backend:resource:base:download` | 下载/获取 **OSS 类型**资源（文件浏览页的构建产物；含分享链接/缩略图/预览 URL）。MINIO 普通资源（头像、项目文档等）仅需登录，不校验此权限 |
| `backend:resource:base:write` | 创建/更新资源/文件夹 |
| `backend:resource:base:delete` | 删除资源/文件夹 |
| `backend:resource:base:sync` | OSS ↔ DB 同步、构建部署同步 |

> `admin` 用户与持有 `*` 通配权限的用户直通所有检查。

## 二、后端改动

### 1. 项目授权导出

**文件**：`backend/app/modules/admin/api/export.py`

- **`export_project`**（导出项目数据）
  - 新增 `current_user: Dict[str, Any] = Depends(get_current_active_user_from_token)` 参数
  - 按 `type` 分别校验权限：
    - `license` → 校验 `backend:project:license:export`
    - `users` → 校验 `backend:project:user:export`
    - `all` → 两者皆需
  - 不满足抛 403 `权限不足: 缺少 {perm}`

- **`apply_project_license`**（申请项目授权）
  - 用 `current_user: Dict[str, Any] = require_permission(PERM_LICENSE_APPLY)` 替换原手写 `decode_token` 取用户身份的逻辑（与 `permissions.py#L96` 写法一致）
  - 保留 AUTH 服务拉取 `name` 的回退分支
  - 移除不再使用的 `from app.core.security import decode_token` 导入

### 2. 资源管理 - 资源接口

**文件**：`backend/app/modules/admin/resource_manager/api/resource.py`

- 21 个端点全部加 `require_permission(...)`，按 read/download/write/delete/sync 分类
- **下载类端点条件鉴权**：`download` / `download-url` / `thumbnail-url` / `preview-url` 4 个端点改为「登录认证 + 条件鉴权」——经新增的 `ensure_oss_download_permission(resource, current_user)` 判断，**仅当资源 `storage_type == OSS` 时才校验 `PERM_DOWNLOAD`**；头像（`category=用户头像`）、项目文档等 MINIO 普通资源任何登录用户均可获取（这些请求多来自 `<img>`/`window.open`，浏览器无法附加 Authorization 头，token 经 `?token=` 查询参数传递）
- **`get_resource_download_url`**：默认有效期 `5 → 3` 分钟
- 模块顶部新增权限码常量 `PERM_READ/PERM_DOWNLOAD/PERM_WRITE/PERM_DELETE/PERM_SYNC`
- 新增 `from app.modules.admin.api.auth import require_permission` 导入

### 3. 资源管理 - 文件夹接口

**文件**：`backend/app/modules/admin/resource_manager/api/resource_folder.py`

- 9 个文件夹端点加 read/write/delete 权限（与 resource.py 保持一致）
- 新增 `PERM_READ/PERM_WRITE/PERM_DELETE` 常量
- 修正 typing 导入为 `Dict` 以兼容 `current_user` 类型注解

### 4. 资源管理 - MinIO 预签名接口

**文件**：`backend/app/modules/admin/resource_manager/api/minio.py`

- `get_presigned_url` 加 `backend:resource:base:download` 权限（预签名 URL 等同于分享链接）

## 三、前端改动

### 1. 权限常量

**文件**：`frontend/src/stores/auth.ts`

在 `PERMISSION_VIEW_ALL` 后新增 5 个常量：

```ts
export const PERMISSION_LICENSE_EXPORT = 'backend:project:license:export';
export const PERMISSION_USER_EXPORT = 'backend:project:user:export';
export const PERMISSION_LICENSE_APPLY = 'backend:project:license:apply';
export const PERMISSION_RESOURCE_READ = 'backend:resource:base:read';
export const PERMISSION_RESOURCE_DOWNLOAD = 'backend:resource:base:download';
```

### 2. 项目管理页 - 导出按钮组

**文件**：`frontend/src/pages/admin/ProjectManage.tsx`

- 仿 `canViewAll` 模式新增 `canExportLicense` / `canExportUsers` / `canExportAll = canExportLicense && canExportUsers`
- 导出按钮组三个按钮分别用上述权限条件渲染
- 三项权限全无时整块隐藏（含 `borderTop` 分隔线）

### 3. 后台布局 - 菜单入口

**文件**：`frontend/src/shared/components/AdminLayout.tsx`

- `MenuItem` 接口新增可选 `permission?: string` 字段
- `resources` 与 `file-explorer` 两项标记 `permission: PERMISSION_RESOURCE_READ`

### 4. 仪表盘 - 数据资源弹层

**文件**：`frontend/src/pages/admin/Dashboard.tsx`

- 新增 `canReadResource = hasPermission(PERMISSION_RESOURCE_READ)`

### 5. 文件浏览器页 - 分享按钮

**文件**：`frontend/src/pages/admin/FileExplorer.tsx`

- 新增 `canDownload = useAuthStore((s) => s.hasPermission(PERMISSION_RESOURCE_DOWNLOAD))`
- 「分享」按钮用 `canDownload` 条件渲染（无 download 权限不显示）
- `share()` 调用 `expires_minutes=60 → 3`
- Toast 文案「60 分钟内有效」→「3 分钟内有效」

## 五、说明与遗留项

1. **`ProjectAuth.tsx` 的「申请授权码」按钮未加前端权限条件**：该按钮调用 `apply_project_license`，后端已强制 `backend:project:license:apply`。本次按用户明确范围只改 `ProjectManage.tsx` 的导出按钮，无权限用户点击该按钮时会收到后端 403 toast。如需同步隐藏该按钮，可再加一处 `hasPermission(PERMISSION_LICENSE_APPLY)` 条件渲染。

2. **FileExplorer 的「🔄 同步 OSS」按钮未加前端权限条件**：后端 `sync-oss` 已强制 `backend:resource:base:sync`，无权限会得到 403 toast。如需前端隐藏，告知后可补 `PERMISSION_RESOURCE_SYNC` 常量与条件渲染。

3. **`thumbnail-url` 与 `preview-url` 默认 5 分钟未改**：它们用于内联展示，未在「分享链接」范围内。如需同步缩减，告知即可。

4. **新权限码需在权限管理后台为相应角色分配后才会生效**；目前 `admin` 与 `*` 用户直通。建议为「实施工程师」「项目经理」等角色按需分配 `read`/`download`，为「调度研发」「系统管理员」分配 `write`/`delete`/`sync`。

5. **DEBUG_MODE 影响**：`utils_das/config.py` 中 `DEBUG_MODE = True` 仍会让 `Depends(security if not DEBUG_MODE else lambda: None)` 的接口跳过 HTTPBearer 认证，但本次新增的 `require_permission` 走的是独立的 `get_current_active_user_from_token` 链路，**不受 DEBUG_MODE 影响**，无 token 或权限不足仍会 401/403。这是相对原 `security` 依赖更严格的一道防线。
