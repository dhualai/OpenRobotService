## 填写说明

| 字段 | 说明 |
|------|------|
| 用例编号 | 模块前缀 + 序号，如 `API-TC-001`、`DB-TC-001` |
| 功能点编号/名称 | 对应需求文档中的功能点 ID 或名称 |
| 优先级 | P0=核心路径，P1=重要，P2=一般，P3=低频 |
| 前置条件 | 测试执行前必须满足的状态或数据 |
| 测试步骤 | 可执行的、有序的操作步骤，每步可跟预期结果 |
| 测试结果 | 执行后的实际结论 |

## 优先级定义

| 级别 | 含义 | 示例 |
|------|------|------|
| **P0** | 核心路径，不通过则阻塞发布 | 登录、创建工单、核心流程 |
| **P1** | 重要功能，需在迭代内修复 | 列表分页、搜索、通知 |
| **P2** | 一般功能，可后续迭代修复 | 标签管理、统计数据 |
| **P3** | 低频/边缘场景 | 边界值、异常数据、UI细节 |
