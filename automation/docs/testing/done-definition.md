# 功能完成标准

> 本文定义 OpenRobotService 项目中一个功能点从开发到验收的全流程完成标准（Definition of Done）。
> 参考 `docs/PRD.md` 第十一节"AI 自动化测试规则"和 `docs/PRD.md` 第六~八节的功能点规格模板。

---

## 一、完成标准总览

一个功能点标记为"完成"，必须满足以下全部条件：

```
[提测前]         [提测]           [验收]          [上线]
    │              │               │              │
    ▼              ▼               ▼              ▼
 自测通过  ──→  提交测试  ──→  测试验收  ──→  生产发布
    │              │               │              │
    ├ 代码完成      ├ 接口已登记    ├ 测试通过      ├ 监控就绪
    ├ 测试覆盖      ├ 联调通过      ├ 无 P0 bug    ├ 回滚方案
    ├ 文档同步      ├ 自测报告      └ 报告归档      └ 通知到位
    └ lint 通过     └ 异常覆盖
```

---

## 二、提测标准（各功能点 Owner 提测前自检）

### 2.1 功能完整性

- [ ] 功能点已按 PRD 模板补全"验收标准"
- [ ] 接口已在 PRD 第九节登记并联调通过
- [ ] 自测覆盖正常路径 + 至少一个异常路径（网络失败/权限不足/参数非法）
- [ ] 若功能点涉及 Agent 模型/Prompt/流程变更，对应版本迭代文档已更新

### 2.2 代码质量

- [ ] 后端：`ruff check app/` 通过
- [ ] 前端：`npm run lint` 退出码 0，`tsc -b` 通过
- [ ] 无调试代码残留（print/console.log/debugger）
- [ ] 异常处理覆盖完整

### 2.3 自动化测试

- [ ] 新增逻辑有对应自动化测试
- [ ] 后端测试通过：`cd backend && pytest --ignore=tests/tasks`
- [ ] 前端测试通过（如涉及前端改动）：`cd frontend && npm run test`
- [ ] 参数化测试覆盖边界值

### 2.4 文档同步

- [ ] OpenAPI 文档自动生成（FastAPI 自动处理）
- [ ] 业务规则变更 → 同步 `docs/business_rules.md`
- [ ] 测试策略变更 → 同步 `automation/docs/automation_strategy.md`
- [ ] 故障排查经验 → 同步 `docs/troubleshooting.md`

### 2.5 微信 H5 适配自检（强制）

> 本项目是微信服务号 H5 应用，任何前端组件/功能必须在「微信内置浏览器」与「手机微信端」实测通过方可提测。PC 浏览器模拟器验证不作为通过依据。

- [ ] **iOS 微信实测**：iPhone 微信内置浏览器走通核心交互路径（登录 → 主功能 → 提交/跳转），无白屏、无 JS 报错
- [ ] **Android 微信实测**：Android 微信内置浏览器同上
- [ ] **iOS 已知坑点已规避**：日期解析（`YYYY-MM-DD`）、`fixed` 输入框失焦归位、滚动惯性
- [ ] **部署前缀正确**：跳转/回调地址带 `/p/app/` 或 `/t/app/` 前缀，OAuth 回跳不 404
- [ ] **不使用 PC-only API**：无 `alert/confirm/prompt`，改用 TDesign 组件；无 hover-only 交互
- [ ] **触控与性能**：点击热区 ≥ 44px；SSE/长连接在微信切后台后能断线重连；首屏不白屏超 3s

> 自检细则见 `CONTRIBUTING.md`「微信 H5 适配要求」节；常见微信端问题排查见 `docs/troubleshooting.md` 第三章。

## 三、验收标准

### 3.1 测试验收

- [ ] 所有自动化测试通过
- [ ] P0 bug 已清零
- [ ] 功能与 PRD 规格一致
- [ ] 边界场景已验证（输入校验、权限、并发）

### 3.2 产品验收

- [ ] 产品经理确认功能符合预期
- [ ] UI/UX 满足移动端友好要求
- [ ] 微信服务号集成功能已实测

---

## 四、Bug 等级定义

| 等级 | 定义 | 处理时效 |
|------|------|----------|
| **P0** | 阻塞上线（如登录不可用、核心链路崩溃、数据丢失） | 当天必须修复 |
| **P1** | 功能性缺陷，不阻塞上线但影响体验 | 下周 Debug 期内修复 |
| **P2** | 架构性/技术债类问题 | 纳入后续迭代规划，不占当期资源 |

### 可 MVP 上线条件

- 无 P0 bug
- P1 bug 已记录且 Owner 确认不影响核心流程
- 回滚方案已就绪

## 五、功能点规格模板（新建功能点使用）

每个功能点需按以下模板补全，作为分派给 AI 生成代码时的直接依据：

```
### 功能点：<名称>
- 用户故事：作为 <角色>，我希望 <行为>，以便 <价值>
- 交互流程：<关键步骤，含异常分支>
- 输入字段：<字段名/类型/必填/校验规则>
- 输出字段：<字段名/类型/展示位置>
- 边界与异常：<网络失败/超时/知识库无命中/权限不足等场景的处理>
- 验收标准：<可勾选的具体断言，例如"输入XX后3秒内返回流式响应首字节">
```

---

## 六、回归触发条件

以下情况需要触发全量或部分回归测试：

- [ ] 任一功能点的接口契约变更
- [ ] 数据库模型变更（Alembic 迁移）
- [ ] 微信生产环境配置变更
- [ ] 基础框架/依赖版本升级（FastAPI/React/Vite）
- [ ] 核心状态机变更（`backend/app/modules/tasks/services/ticket_service.py` 的 `ALLOWED_TRANSITIONS`）

---

## 七、上线检查清单

- [ ] 所有 P0 bug 已修复并验证
- [ ] 自动化测试在 CI 中通过
- [ ] Allure 测试报告已生成并归档
- [ ] 生产环境变量已配置
- [ ] 数据库迁移已执行（`alembic upgrade head`）
- [ ] 回滚方案已确认
- [ ] 上线后监控已就绪
