# Test Gate 必跑套件验收判定

现有 Test Gate 为四个必跑套件生成 JUnit。汇总只统计 Allure 已收到的文件，单个套件全部跳过或缺少产物时，其他套件的结果仍可能使摘要显示没有失败。

框架与基础设施、Mock API、真实后端 Smoke 和 OpenAPI 契约属于必跑范围。每个套件的 JUnit 与 Allure 分别统计通过、失败或错误、跳过用例，任一类计数不一致即为未验收。JUnit 同一用例的测试失败和 teardown 错误合并为一次失败。DB 集成与工单场景沿用观察模式，继续进入诊断报告。

必跑 job 被取消或跳过、JUnit 无执行用例、产物缺失或损坏、判定步骤未生成有效结论时，门禁显示未验收。证据缺失和已确认的测试失败同时出现时，门禁摘要同时提示两者。报告整理、HTML 生成、上传与 Pages 发布状态独立显示。工作流最后按测试门禁判定退出。

如果 GitHub Actions 在整次运行被取消后没有调度汇总作业，运行页会保留 GitHub 自身的取消状态。

## 本地验证

产物联调使用 pytest 和 Allure 实际生成的文件，覆盖正常执行、部分跳过、全跳过、取消、文件缺失、部分丢失与损坏、fixture setup 和 teardown 错误。组合场景验证失败与未验收同时可见，并确认观察项进入业务 HTML。提审前在最终提交运行报告、客户端、断言、Mock 和业务 API 回归，验证工作流实际 Bash 中的退出码、未验收兜底与报告状态。最终提交和测试结果记录在 PR #493。
