## 可选项

- 在验收摘要中给每个失败或未验收套件附上作业入口和现有产物入口，方便从原因直接找到证据。可以随第 3 项一起做。
- 契约范围扩容、旧库升级验证、观察套件升级为阻塞，以及调整工作流触发条件，由后续里程碑单独确认。

## 集中验收方式

用同一份合成产物分别验证全通过、部分跳过、全跳过、空结果、测试失败与产物缺失。核对 GitHub Actions 摘要、业务 HTML 和用例清单 HTML 的统计与结论。用 pytest 实际产生的 JUnit 与 Allure 产物联调，再在最终提交运行回归并生成两种 HTML 和 Allure 报告。最终提交和结果记录在同一个 PR 的验证段。合入 `test` 后用完整 Test Gate 复查。
