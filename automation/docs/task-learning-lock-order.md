# 学习答题和后台题目操作的并发验证

普通学员提交答案时先锁文章再锁题目。后台保存或审核同一题时原先先锁题目再锁文章。这两条路径并发时可能形成 InnoDB 死锁。文章发布也先锁文章，因此后台保存和审核统一采用文章、题目的顺序。

后台先查询题目的文章 ID，取得两把锁后再核对归属。MySQL 的 `REPEATABLE READ` 可能在查询归属时建立快照，因此读取当前已发布版本时使用锁定读。这样即使管理员在等文章锁时有新版本发布，也会按获得锁后的版本验证题目。权限、题目审核状态和学员答题规则沿用原有约束。

## 验收

- MySQL 8.0.46（InnoDB、`REPEATABLE READ`）两条并发用例通过，覆盖学员答题与后台停用以及后台等锁期间发布新版本后保存题目。修复前的 `dee42441` 在同一测试中两条均失败，原因是后台首先锁了题目。
- 学员和知识沉淀相关回归 93 条通过，覆盖作答、进度、用户隔离与旧答卷唯一索引的兼容性。
- 后端回归按用例对比 `dee42441` 的 JUnit 结果，原有 123 个失败和 42 个错误完全相同。两条 MySQL 用例在未配置专用实例的全量运行中跳过，在上述独立实例中另外执行通过。

在专用 MySQL 测试实例的启动环境中配置 `LEARNING_MYSQL_TEST_URL`，然后从仓库根目录运行以下命令。账号需要创建和删除临时库的权限。每条用例使用独立的随机库名，运行后清理。

```powershell
python -m pytest backend/tests/test_learning_mysql.py -q
python -m pytest backend/tests/test_learning.py backend/tests/test_knowledge.py -q
```
