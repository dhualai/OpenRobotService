# Test Gate 业务场景与报告可读性待办

已确认范围，随当批报告改进集中提审。问题来自 [PR #497](https://github.com/dhualai/OpenRobotService/pull/497) 的报告联调样本。

## 第一版业务场景

业务 HTML 首页展示正式 Test Gate 结论和「业务场景一览」。每行给出业务模块、中文场景名、验证结果和测试来源。本批从 `test` 的 `2f2edd2c` 开始，复用已验证的报告统计、门禁结论和运行来源作为业务展示底座。

| 业务主线 | 首页场景 | 详情步骤与预期 | 候选证据 |
| --- | --- | --- | --- |
| 报障建单 | 现场报障后创建并确认工单 | 报障人提交故障问题、转工单并确认。验证按返回的会话和工单标识串联三个步骤。 | [提问、转工单与确认](../tests/call/test_call_code.py#L380) |
| 工单处理 | 处理工程师请求暂停，提单人确认 | 处理工程师接单后进入「处理中」，请求暂停后进入「待确认」，提单人确认后进入「已暂停」。 | [真实工单暂停场景](../tests/real/test_ticket_scenarios.py#L179) |
| 后台权限 | 普通工程师访问后台用户管理时被拒绝 | 已登录工程师请求查看用户列表，预期拒绝访问。明细显示实际授权结论与状态码，校验拒绝信息与用例断言对应。 | [后台非授权访问用例](../tests/admin/test_admin_code.py#L225) |

每个场景使用稳定标识关联已有用例和步骤。详情表展示「角色」「动作」「预期结果」「实际结果」，可展开技术证据查看接口路径、断言和脱敏附件。实际结果从本次产物提取，未执行或缺少证据时直接标明原因。模拟、真实和观察项的来源与结果一起展示。只有结果记录的用例显示已有结果，分步详情随有效证据提供。

## 分组与名称

- 普通用例保留业务功能标签。缺少功能标签时，使用已有的测试来源分组，例如「框架与基础设施」「模拟接口测试」「真实后端冒烟检查」。
- 将观察项的报告名称统一为易读的中文。建议用「知识库数据库检查（观察项）」和「真实工单流程（观察项）」。同一来源在业务 HTML 的模块表和用例明细，以及用例清单 HTML 的来源列使用相同名称。
- 对功能标签和测试来源都缺失的本地导入结果，显示「来源未标注」，便于识别预览数据缺少来源的情况。

## 验收

- 首页能找到报障建单、工单处理、后台权限三条主线，点击场景能展开角色、动作、预期与实际。用同一批产物核对首页结论、步骤明细和底层断言一致。
- 覆盖真实通过、模拟通过、业务结果不符、跳过或预期失败、产物缺失。业务差异先用中文说明，技术证据仍可展开。无证据时展示「未验证」或「未记录实际结果」，观察项保留观察属性。
- 用一个失败样本确认报告能指出具体步骤和状态差异，并确认公开 HTML 不出现原始凭据。
- 缺少功能标签但有来源的用例进入对应来源组。业务 HTML 的模块统计与分组后的用例数一致。
- 已有功能标签的用例仍在对应业务模块下。观察项显示中文名称，明细保留具体测试内容与结果。
- 覆盖功能标签完整、仅有来源、观察项以及来源缺失四种输入。用同一批产物核对两种 HTML 的分组、名称及计数。

## 联调样本

本地报告取报障建单和后台权限的实际 Mock 结果。未连接真实后端时，工单处理显示「未验证」，仍可展开查看角色、动作和预期。在另一个受控回归中，用合成响应验证暂停状态不符时，报告能指出「提单人确认暂停」这一步及实际状态。最终提交、回归结果和样本位置记录在草稿 PR。
