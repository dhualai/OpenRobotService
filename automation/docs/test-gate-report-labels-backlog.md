## 分组与名称

- 普通用例保留业务功能标签。缺少功能标签时，使用已有的测试来源分组，例如「框架与基础设施」「模拟接口测试」「真实后端冒烟检查」。
- 将观察项的报告名称统一为易读的中文。建议用「知识库数据库检查（观察项）」和「真实工单流程（观察项）」。同一来源在业务 HTML 的模块表和用例明细，以及用例清单 HTML 的来源列使用相同名称。
- 对功能标签和测试来源都缺失的本地导入结果，显示「来源未标注」，便于识别预览数据缺少来源的情况。

## 验收

- 首页能找到提单与接单、工单处理、后台权限三条主线，点击场景能展开角色、动作、预期与实际。用同一批产物核对首页结论、步骤明细和底层断言一致。
- 覆盖真实通过、模拟通过、业务结果不符、跳过或预期失败、产物缺失。业务差异先用中文说明，技术证据仍可展开。无证据时展示「未验证」或「未记录实际结果」，观察项保留观察属性。
- 用一个失败样本确认报告能指出具体步骤和状态差异，并确认公开 HTML 不出现原始凭据。
- 缺少功能标签但有来源的用例进入对应来源组。业务 HTML 的模块统计与分组后的用例数一致。
- 已有功能标签的用例仍在对应业务模块下。观察项显示中文名称，明细保留具体测试内容与结果。
- 覆盖功能标签完整、仅有来源、观察项以及来源缺失四种输入。用同一批产物核对两种 HTML 的分组、名称及计数。

## 联调样本

本地报告取提单与接单和后台权限的实际 Mock 结果。未连接真实后端时，工单处理显示「未验证」，仍可展开查看角色、动作和预期。在另一个受控回归中，用合成响应验证暂停状态不符时，报告能指出「提单人确认暂停」这一步及实际状态。最终提交、回归结果和样本位置记录在草稿 PR。

### 「高价值问题」验收样板

触发动作是有管理权限的管理员发布一条独立高价值问题。以同一问题贯穿用户解答、截止评选和奖励入审。

| 主流程 | 现有用例证据 | 本次提交的通过条件 | 还缺的证据 |
| --- | --- | --- | --- |
| 高价值问题 | 隔离后台规则验证普通用户发布受限，授权管理员能发布独立问题。页面组件覆盖发布入口及字段。 | 授权管理员发布并保存，同一问题在普通用户侧可见，标题、悬赏金额、截止时间一致。 | 当前版本管理员发布后，切换普通用户账号回查同一问题的页面证据。 |
| 用户解答 | 隔离后台规则提交两条答案并点赞。页面组件覆盖草稿私有、手动发布和已发布答案展示。 | 用户提交解答后，其他用户能看到该答案并点赞。重新打开后仍能看到同一条已发布答案及点赞结果。 | 当前版本两个普通用户在同一问题下提交、查看和点赞的实跑证据。 |
| 评选 | 隔离后台规则用可控时间触发截止结算，校验按答案点赞选中最佳答案，问题本身的点赞不计入。 | 目标环境中同一问题截止后完成结算，结果页展示获赞最多的有效答案。 | 当前版本真实结算入口或任务运行的记录，以及用户侧结果页回查证据。 |
| 奖励 | 隔离后台规则核对获奖人、来源问题、金额和待财务审核状态。重复结算只留一条奖励记录。 | 同一问题只为获奖者生成一条金额正确的待财务审核记录，重复结算后数量一致。 | 当前版本用测试悬赏核对财务待审记录及其与问题、获奖人的关联。验收终点是待财务审核，实际发放尚无实跑证据。 |

用例依据 [发布、评选和奖励入审规则](../tests/_service_account_backend_checks.py#L31) · [用户解答与发布组件](../../frontend/src/pages/admin/__tests__/KnowledgeChallenges.test.tsx#L490)。

三条样板均沿用「我要摇人」的证据关联口径。后台规则与页面组件标注实际验证范围，页面闭环结果按验收提交和目标测试环境关联到报告。关键步骤缺少当前证据时，首页列出具体缺口。
