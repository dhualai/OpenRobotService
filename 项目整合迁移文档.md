# 项目整合迁移文档

> v2.0 | 2026-07-09 | 目标：HelpDesk + BackgroundService → OpenRobotService

---

## 一、核心决策：React，不是 Vue 3

| 关键事实 | 影响 |
|----------|------|
| 主仓 `frontend/` 为空（仅 `.gitkeep`） | 选任何框架都零历史包袱 |
| 两个子项目都是 **React 19**，26 个页面已上线验证 | 用 Vue = 全部重写（10-15 天）；用 React = 结构调整+UI适配（**5-7 天**） |
| HD 的 API 层是成熟的企业级实现（token 刷新/缓存/重试/超时） | 可直接采纳为共享基础设施 |
| BS 已是 TypeScript + Vite 7 | 与目标架构天然吻合 |

**结论**：子项目代码是资产而非负债。用 React 保留 ~85% 代码，只换 UI 壳（Bootstrap/Antd/Docusaurus → TDesign Mobile），远比重写划算。

---

## 二、目标技术栈

```
React 19 + TypeScript + Vite 7
├── TDesign Mobile React    ← 腾讯官方移动 UI，微信生态最佳适配
├── React Router v7         ← BS 已在用
├── Zustand                 ← 极简状态管理（~1KB），优于 Context
├── HD createRequest 模式    ← API 层基座（token 刷新/缓存/重试/超时）
├── @tiptap/react           ← 富文本（HD 直接复用）
├── @xyflow/react           ← 状态流图（reactflow v11 → v12 升级）
├── echarts                 ← 图表（两个项目都在用）
├── dayjs                   ← 替代 moment（体积小 97%）
├── dompurify               ← XSS（HD 直接复用）
└── react-markdown          ← Markdown（HD 直接复用）
```

### 关键决策理由

| 决策 | 为什么 |
|------|--------|
| **TDesign Mobile** 而非 Vant | 腾讯官方设计系统，与微信生态天然匹配；React 版本维护活跃；组件丰富度足够 admin 复杂场景 |
| **Zustand** 而非 Context | Context 跨组件共享会导致不必要重渲染；Zustand 支持 selector 精准订阅 + 天然 TypeScript |
| **采纳 HD 的 API 层** | BS 的 API 调用散落在组件中（直接 fetch/axios）；HD 有 `createRequest` 工厂 + 发布-订阅 token 刷新 + 5min 缓存 + 2 次重试 + 30s 超时 |
| **@xyflow/react** | reactflow v11 的官方 v12，包名变了但 API 99% 兼容 |
| **dayjs** 替代 moment | 同样 API，体积小 97% |

## 三、迁移策略：三件事

```
1. 从 Docusaurus 剥离 React 业务代码（HD） 
2. 合并 3 个散落前端为 1 个清洁项目（BS）
3. 统一 UI 壳为 TDesign Mobile + 共享基础设施
```

**核心原则**：不改业务逻辑，只换 UI 壳。API 调用、数据流转、状态机、表单校验全部原封保留。

## 十一、风险与应对

| 风险 | 应对 |
|------|------|
| TDesign Mobile 组件覆盖不足 | 少数复杂组件可用自定义实现，不影响业务逻辑 |
| @xyflow/react v12 兼容性 | 官方迁移指南：API 99% 兼容，主要是包名变化 |
| Admin 复杂表格移动端可读性差 | 采用卡片布局降级 + 横向滚动；admin 推荐桌面端 |
| Docusaurus 剥离后布局失调 | HD 业务组件独立于 Docusaurus 布局壳，剥离 = 删外层壳 |
| 微信浏览器兼容 | TDesign Mobile 官方支持微信环境，上线前实测 |

**核心约束**：
- 业务逻辑零改动
- 知识库文档（Docusaurus）独立部署，主应用链接跳转
- HD 的 JSX → TSX 只加类型定义，不改逻辑
- API 统一使用主仓后端地址，vite proxy 转发

## 十二、方案对比总结

| 维度 | Vue 3 重写 | **React 统一（最优）** |
|------|-----------|----------------------|
| 代码复用率 | ~10%（仅逻辑思路） | **~85%**（组件+逻辑+类型） |
| 26 页改动量 | 全部重写 | **仅换 UI 壳** |
| 核心业务逻辑 | 翻译重写 | **零改动** |
| 工时 | 10-15 天 | **5-7 天** |
| 后期维护 | 单栈但翻译损耗 | **单栈 + 清洁分层** |
| 扩展开发 | 需熟悉 Vue 3 写法 | **直接写 React 组件** |
| 翻译错误风险 | 高（JSX→SFC，Context→Pinia） | **无** |
