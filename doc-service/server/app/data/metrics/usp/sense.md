# L5 · 感官看板 · 认可与反直觉

> 用户还会用眼睛判断：路径和派单像不像在瞎忙。  
> 一部分质疑合理（算法有空间）；一部分反直觉但整体更优。本页收场景、定指标，避免被「看着别扭」带偏优化方向。

---

## 1. 为什么单独说感官

效率看板回答客观结果；感官回答**信不信任调度表现**。

只追吞吐、不处理感官，常见两种后果：现场频繁改派把效率打回去；或为了讨好看强行「最近+最短」，吞吐与超时反而变差。

因此要：把别扭变成可统计信号；并把「真缺陷」与「反直觉但成立」分开——后者靠原因码和对照实验，而不是立刻迎合眼睛。

---

## 2. 两类感官结论

| 类型 | 含义 | 正确反应 |
|------|------|----------|
| **合理质疑** | 看起来别扭，对照之后也确实更差或说不清收益 | 当作缺陷：改算法、改地图规则，或补约束 |
| **反直觉但成立** | 看起来别扭，但换成「更直觉」的走法/派法后，吞吐、超时或综合收益变差 | 当作解释问题：保留策略，补原因展示与对照证据，培训现场预期 |

判断靠三步，尽量可自动化：打标（是否触发感官警报）→ 归因（有无站得住的原因码）→ 对照（仿真里强行直觉策略后，吞吐与超时变好还是变差）。

## 3. 比较经典的现场场景

下列场景在仓储/产线多车调度里常见。「常落在哪一类」是经验倾向，具体仍用上面三步核对。

### 3.1 路径相关

| 场景（人眼看到的） | 常常为什么会发生 | 更常落在 |
|--------------------|------------------|----------|
| 明明有更直的路，车却绕远 | 直路正在拥堵或被时空预约占住；绕行缩短的是**系统等待**，不是单车几何距离 | 反直觉居多；若走廊空着仍大绕，则合理质疑 |
| 车在半路停很久，像发呆 | 给对向或更高优先级让路，避免死锁或连环堵 | 有原因码时多为反直觉；无原因码的干等 → 合理质疑 |
| 先往目标反方向开一段 | 从窄道/对接点退出、给别人让通道、进入等待位 | 反直觉居多；反复拉锯无进展 → 合理质疑 |
| 小路里突然倒车、来回拧 | 可能是狭窄通道里的必要换向；也可能是规划抖动 | 偶发且有拓扑原因 → 可解释；高频抖动 → 合理质疑 |
| 两车互换车道或「交叉绕圈」 | 空间时间上的换位，局部看起来乱，全局更通 | 反直觉；若伴随死锁前兆 → 合理质疑 |
| 空车跑去很远的地方，附近明明有活 | 为下一波任务预定位，或避开即将锁死的区域 | 反直觉；若预定位从未被后续任务用上 → 合理质疑 |

### 3.2 分配相关

| 场景（人眼看到的） | 常常为什么会发生 | 更常落在 |
|--------------------|------------------|----------|
| 近处有空车，却派了远处的车 | 近车很快有更高优先级任务、电量/能力不符，或近车过去会堵死主通道 | 反直觉居多；近车长期空闲仍不派 → 合理质疑 |
| 一辆车忙到爆，另一辆长时间空闲 | 负载均衡、在休息点、在充电，或空闲车被预留 | 有休息/充电原因码时需解释；纯闲置无预留 → 合理质疑 |
| 任务干等，车却在充电 | 充电策略窗口；是否本可避开中途充 | 看 MidTaskChgRate；间隙充可解释，途中打断常合理质疑 |
| 任务干等，车停在休息点 | 无任务回休息点的规则行为 | 早期多为正常；长期有单不召回 → 合理质疑 |
| 任务干等，车却在跑别的、看起来不紧急的单 | 批次、优先级、截止时间 | 用优先级与超时解释；说不清 → 合理质疑 |

### 3.3 系统观感相关

| 场景 | 说明 | 更常落在 |
|------|------|----------|
| 路径刚出来又改、车头来回拧 | 重规划过频，观感极差，也常损害执行 | **合理质疑**为主（规划稳定性） |
| 某区域任务总被晾着 | 饥饿：局部长期得不到服务 | **合理质疑** |
| 频繁急停、贴脸让车 | 既可怕，也往往意味着冲突消解偏晚 | **合理质疑**（兼可靠与安全观感） |

## 4. 能抽象成什么指标

描述「有多不像直觉上的好方案」，以及「能不能解释、值不值得改」。不取代吞吐量。比率须绑定考察时间段。

### 4.1 路径绕行率

对一次已执行的取送路径，设实际行驶长度为 \(L_{\mathrm{act}}\)，同一地图上忽略动态车、只尊重静态通行规则的最短路长度为 \(L_{\mathrm{sp}}\)：

\[
\mathrm{Stretch}=\frac{L_{\mathrm{act}}}{L_{\mathrm{sp}}}
\quad (L_{\mathrm{sp}}>0)
\]

- 高绕行 + 当时走廊确实拥堵或原因码为避让/绕障 → 倾向反直觉；  
- 高绕行 + 走廊空闲 + 无原因码 → 倾向合理质疑。

聚合：时间段内 \(\mathrm{Stretch}\) 的均值、P95，以及「\(\mathrm{Stretch}>\theta_s\)」的行程占比（感官警报率的一部分）。

### 4.2 背离目标比例

执行过程中，定期看车辆到当前目标的剩余估计距离 \(d(t)\)。若 \(d(t)\) 上升，记为背离：

\[
\mathrm{AwayRatio}=\frac{\text{背离目标的时间（或里程）}}{\text{该段行程总时间（或里程）}}
\]

短暂背离常见于让路；长时间、反复背离且无原因码，观感差且常真有问题。

### 4.3 分配「舍近求远」差距

任务 \(\tau\) 派给车辆 \(V\)，空驶距离为 \(d(V,\tau)\)。  
在分配决策时刻，所有**当时可接单**的车里，到该任务最近的距离为 \(d_{\min}(\tau)\)：

\[
\mathrm{AssignGap}(\tau)=d(V,\tau)-d_{\min}(\tau)
\]

或相对形式 \(\mathrm{AssignGapRel}=d(V,\tau)/d_{\min}(\tau)\)（\(d_{\min}>0\)）。

- \(\mathrm{AssignGap}\) 大但近车随后接了更急的单、或近车过去会触发大拥堵 → 常需解释为反直觉；  
- 近车长期可接却一直空闲 → 合理质疑。

### 4.4 无解释等待占比

路径等待、分配等待应带原因码（见 [事实抽象](./09-fact.md)）。定义：

\[
\mathrm{UnexplainedWaitRatio}
=\frac{\text{原因码缺失或为 unknown 的等待时长}}{\text{总等待时长}}
\]

感官上的「干等」，很大一部分应落在这个指标里。目标是把它压低：不是消灭所有等待，而是**等待都说得清**。

### 4.5 可解释覆盖率

先用规则筛出「别扭」行程/分配，例如：

- \(\mathrm{Stretch}>\theta_s\)，或  
- \(\mathrm{AwayRatio}>\theta_a\)，或  
- \(\mathrm{AssignGapRel}>\theta_g\)

再看其中有多少条能落到合法原因集合（避让、绕开拥堵、单向/运动学、为后续任务预留、优先级等）：

\[
\mathrm{ExplainCover}
=\frac{\text{别扭样本中已归因的条数}}{\text{别扭样本总数}}
\]

交付对外解释时，优先提高覆盖率；算法侧则盯「别扭且未归因」和「别扭且对照实验证明更差」的集合。

### 4.6 重规划抖动

在短时间 \(\Delta t\) 内，同一车辆对同一任务的路径发生「实质性回摆」（例如走廊选择来回切、目标进度反复倒退），计一次抖动事件：

\[
N_{\mathrm{flicker}}=\#\{\text{抖动事件}\}
\quad\text{或}\quad
\mathrm{FlickerRate}=\frac{N_{\mathrm{flicker}}}{\text{规划次数}}
\]

这类问题几乎总是**合理质疑**（观感与执行都差），与「为了全局最优而绕一次远路」不是一类事。

### 4.7 现场否决与投诉率

若产品允许人工改派、锁车、或提交「路径不合理」类反馈，在考察时间段内：

\[
\mathrm{OverrideRate}=\frac{\text{人工否决或投诉次数}}{\text{完成任务数}}
\]

这是最接近「用户是否认可」的行为指标。它上升时，要回到 4.1–4.6 看是解释不够，还是策略真有坑。

### 4.8 直觉策略对照

这是把「反直觉」判真的关键实验，不是线上实时卡片：

1. 基线：当前分配 + 路径策略；  
2. 直觉变体：例如「总派当时几何最近的可接单车」+「尽量走静态最短路、少主动绕行」（具体规则项目内写死）；  
3. 在同一地图、同一任务到达过程、同一考察时间段下比较吞吐量、超时率、Makespan 等。

定义一种简单的对照结论即可，例如：

- 若基线吞吐量不低于直觉变体，且超时不更差 → 将基线上的高 Stretch / AssignGap 样本标为**反直觉但成立（有证据）**；  
- 若直觉变体全面更好 → 标为**合理质疑（算法有空间）**。

可选把「系统收益差」也写成数，例如吞吐差 \(\Delta\mathrm{Throughput}\)，供论文式消融使用；产品页不必直接甩公式。

## 5. 这些指标放在哪里、谁来看

| 指标 | 主要落点 | 建议优先级 | 谁最关心 |
|------|----------|------------|----------|
| Stretch、AwayRatio、AssignGap | 算法仿真器；交付排障下钻 | 第二批起 | 交付、算法 |
| UnexplainedWaitRatio、ExplainCover | 交付工具；可择要进统计页脚注 | 第二批 | 交付、甲方信任 |
| FlickerRate | 算法仿真器 / 可靠相关 | 第二批 | 算法、交付 |
| OverrideRate | 产品统计（若有人工入口） | 视现场能力 | 甲方、交付 |
| 直觉策略对照 | **仅算法仿真器** | 第三批也可，但很有价值 | 算法 |

与 A–D 的关系：不要把「绕行率最低」当主目标；吞吐为主、超时为底线；感官指标用于解释、分诊和约束抖动/无解释干等/饥饿等病态。见 [观测层](./07-bridge.md)。

---

## 6. 使用方式

1. 觉得开得不对 → 看 Stretch、Away、原因码。  
2. 有原因码 → 业务话解释；需要时调出直觉策略对照。  
3. 无原因码或抖动明显 → 合理质疑队列。  
4. 舍近求远 → 看 AssignGap，核对近车当时是否可接及随后去向。  
5. 周期性看 OverrideRate 与 ExplainCover。

---

## 7. 落地顺序

先做原因码与 Stretch / AssignGap / Flicker；再做回放上的别扭标记；后做直觉策略对照；可并行用 AI 做解释与排序（见下节）。不做「好看分」替代吞吐。

## 8. AI 做感官向分析：可行性

适合「人看故事、机器筛沙子」，不适合让模型单独裁定路径对错。

> 规则与指标检出；仿真对照判真；AI 负责叙述、排序和归类。

### 8.1 为何适合

现场表达是自然语言；争议多为个案长尾；判定带主观性；上下文要拼地图、拥堵、近车去向——检索增强比堆规则灵活。

### 8.2 任务可行性

| 任务 | 可行性 | 说明 |
|------|--------|------|
| 用原因码与结构化字段生成解释文案 | 高 | 禁止无依据编造原因 |
| 别扭警报的审核排序 | 高 | 省交付时间，不自动结案 |
| 相似案例检索 | 高 | 可用特征向量，不必上大模型 |
| 合理质疑 vs 反直觉初分类 | 中 | 需人标与对照标签 |
| 回放截图的多模态理解 | 中 | 辅助排障；对错仍以日志指标为准 |
| 模型断言「改最近车更好」当结论 | 低 | 收益差必须仿真 |
| 端到端替代 Stretch 等指标 | 低 | 难复现、难验收 |
| 实时改路径/改派单 | 低 | 本阶段不做 |

### 8.3 推荐管线

```
日志 → 规则检出候选 →（可选）检索上下文
    → AI：解释草稿 + 初分类 + 优先级
    → 人确认 →（抽样）直觉策略对照 → 标注沉淀
```

约束：输出须引用依据，无依据标「信息不足」；解释与判决分离；先离线再进工作台；敏感数据优先本地部署。

### 8.4 前提与边界

需要第 4 节特征、尽量全的原因码、持续人审标注；有条件再加对照实验标签。冷启动可用规则+模板，大模型只润色。

感官分只能用于解释、排障、发现病态模式，**不能**与吞吐量并列自动优化「好看」。

**结论：** 值得做；先解释、排序、检索；慎自动判案；不做替代仿真、不进控制环；地基仍是事实与指标。
