# L3 · 观测层

> 回答三件事：**观测什么、先做哪一批、结果呈现在哪里。**  
> 写法按「用户需求 → 架构」。名词定义见 [事实抽象](./09-fact.md)，公式见 [L-Joint](./08-l-joint.md) 与各看板，落地见 [观测编码规格](./17-obs-coding.md)。

---

## 1. 用户需求

### 1.1 不同角色想弄清什么

| 角色 | 想问的问题 | 怎样算满足 |
|------|------------|------------|
| 甲方 / 现场运营 | 这段时间运力效率怎么样？ | 选定班次或时间段后，能看到完成量和是否拖期，不必懂算法 |
| 甲方 / 现场运营 | 车为什么这么开、单为什么这么派？是算法差，还是其实更优？ | 别扭行程能标出、说得清原因；真问题进改进队列，反直觉但更优的有对照说明 |
| 交付 / 实施 | 达标了吗？不达标是偏慢，还是空跑、干等？ | 同一时间段下可下钻到时延、空驶和等待 |
| 算法研发 | 分配和路径哪一层在拖后腿？ | 仿真器里能做层消融，并看到诊断类细指标 |

### 1.2 产品必须具备

1. **先选考察时间段，再展示比率。** 未选时间段时不展示吞吐量等。时间段类型与默认见 [事实抽象](./09-fact.md)。  
2. **默认展示第一批指标：** 吞吐量、完成时延（均值 / P95）、完成率、人工介入次数；每项标明时间段与单位。有显式截止时间时再展超时率。  
3. **多看板、不打综合分。** 主目标是选定时间段内的吞吐量；完成时延高分位（如 P95）为通用时效底线；超时率仅作有截止时的附加底线。  
4. **算法诊断类指标默认不进甲方统计页**，放在算法仿真器报表。  
5. **感官问题要有出口，但不能替代效率主目标。** 详见 [感官看板](./18-sense.md)。

---

## 2. 总原则：先有时间段，再谈指标

持续在线调度没有「整局结束」的天然终点。吞吐量、超时率、使用率等，都必须先说明**考察时间段**，以及**数的是哪批任务**。

只写「吞吐量 = 120」、不写时间段和单位的数字，视为无效。细则见 [事实抽象](./09-fact.md)。

---

## 3. 架构

### 3.1 结果呈现在两处

```
事实与事件 ──► 按考察时间段汇总的指标
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
     产品统计页    算法仿真器    同时间段对比导出
```

| 落点 | 适合放什么 | 时间段通常怎么选 |
|------|------------|------------------|
| 产品统计页 | 产出、时效、运力发挥、可靠，以及感官摘要 | 墙上时钟，如班次或近一小时 |
| 算法仿真器 | 算法诊断、细指标、直觉策略对照 | 整次仿真运行的起止 |

**越细、越贴子模块，越不宜塞进甲方页，应主要在仿真器评估。**

### 3.2 指标分类

| 类别 | 名称 | 主要回答什么 | 主要呈现在 |
|------|------|--------------|------------|
| A | 产出 | 做了多少？ | 产品统计页 |
| B | 时效 | 够不够快？拖没拖太久？ | 产品统计页 |
| C | 运力发挥 | 已有运力用起来了吗？ | 产品统计页（可稍后于 A/B） |
| D | 可靠 | 稳不稳？要不要人盯？ | 产品统计页 |
| S | 感官 | 看起来是否合理？别扭是真问题还是反直觉？ | 交付工具为主；摘要可进产品页 |
| 算法诊断 | — | 问题更可能在分配还是路径？ | **算法仿真器** |

看板 A–D 对应产出到可靠；感官见 [感官看板](./18-sense.md)；端到端见 [L-Joint](./08-l-joint.md)。

### 3.3 优先级

| 优先级 | 含义 | 产品统计页 | 算法仿真器 |
|--------|------|------------|------------|
| 第一批 | 最重要、最好懂 | 必做 | 可同步计算 |
| 第二批 | 解释第一批；交付排障常用 | 第二期 | 可早于产品页 |
| 第三批 | 更细或更偏子模块 | 原则上先不做 | 主战场 |

开展顺序：事实可回放 → 第一批可算 → 统计页 → 第二批 → 第三批与感官对照实验。

### 3.4 指标清单

公式见各链接，此处只列名称。

| 优先级 | 类别 | 指标 | 详文 |
|--------|------|------|------|
| 第一批 | A | 吞吐量 | [看板 A](./10-board-a.md)、[L-Joint](./08-l-joint.md) |
| 第一批 | B | 完成时延均值 / P95 | [看板 B](./11-board-b.md) |
| 第一批 | B | 超时率（有截止时） | [看板 B](./11-board-b.md) |
| 第一批 | A / D | 完成率 | [看板 A](./10-board-a.md)、[看板 D](./13-board-d.md) |
| 第一批 | D | 人工介入次数 | [看板 D](./13-board-d.md) |
| 第二批 | B | 完成时延 P50 / P99（细读） | [看板 B](./11-board-b.md) |
| 第二批 | C | 运力使用率；**空驶率**；等待结构 | [看板 C](./12-board-c.md) |
| 第二批 | D | 故障、求助比率 | [看板 D](./13-board-d.md) |
| 第二批 | S | 绕行率、舍近求远差距、无解释等待、可解释覆盖、重规划抖动 | [感官看板](./18-sense.md) |
| 第三批 | S | 人工否决率；直觉策略对照 | [感官看板](./18-sense.md) |
| 第三批 | 算法诊断 | Makespan、路径层吞吐量；业务分配质量；休息回点；充电打断（MidTaskChgRate）等 | [L-Assign](./06-l-assign.md)、[L-MAPF](./05-l-mapf.md) |
| 第三批 | A / C | 拥堵热点、分区吞吐量 | 仿真器为主 |

本阶段不做：用综合分或「好看分」替代吞吐量。

### 3.5 和上下层

- **往上：** 看板只展示本层已定指标，时间段与任务圈定跟事实层一致。  
- **往下：** 层内诊断主要在仿真器；系统好坏以 L-Joint 为准。业务分配、休息、充电是任务子域下三个独立子问题；路径层只负责开往各自目标点。
