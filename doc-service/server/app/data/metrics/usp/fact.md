## 1. 为什么单独做这一层

没有统一约定时，常见问题是：

- 算法说「路径等待降了」，交付看板对不上；  
- 同一句「利用率」，有人含充电、有人含交管等待。

本层只做三件事：**有哪些对象、发生过什么、怎么计量**。

## 2.1 考察时间段

在持续在线调度里，任务不断到达，通常没有整局终点。谈吞吐量、完成时延、超时率之前，必须先声明考察时间段 \([t_0,t_1]\)，且落在某次运行范围内。

**缺少考察时间段的比率数字无效。**

### 时间段可以怎么选定

| 名称 | 编码时可用的标识 | 如何确定起止 | 什么时候用 |
|------|------------------|--------------|------------|
| 按墙上时钟 | `W_CLOCK` | 由用户或配置指定，例如某班次 08:00–16:00，或「最近一小时」 | 产品统计页的默认方式 |
| 按一次运行 | `W_RUN` | 取该次运行的开始与结束 | 算法仿真里一次完整试跑 |
| 按一批任务推导 | `W_COHORT` | 先圈定一批任务，再由这批任务的发布时间、完成时间推导，或使用事先定好的时长 | 批任务实验、对比实验 |

### 统计哪一批任务

时间段是尺子；分子分母还要声明任务范围：

| 名称 | 编码时可用的标识 | 含义 | 常见用途 |
|------|------------------|------|----------|
| 在时间段内完成的任务 | `C_DONE_IN_W` | 完成时刻落在 \(t_0\) 到 \(t_1\) 之间 | **计算吞吐量时默认用这个** |
| 在时间段内发布的任务 | `C_REL_IN_W` | 发布时刻落在 \(t_0\) 到 \(t_1\) 之间 | 计算超时率、完成率时常用作分母 |
| 在时间段内仍活跃的任务 | `C_ACTIVE_IN_W` | 与这段时间有交集，且不是在时间段开始前就已经结束 | 看积压时常用 |

**产品第一批默认：** 吞吐量用墙上时钟 + 时间段内完成；超时/完成率用时间段内发布，并在 \(t_1\) 结算。

### 时间段结束时，未完成任务怎么算

对「时间段内发布」的那批任务，在结束时刻 \(t_1\)：

**完成率**（不依赖截止）：已完成计入分子；仍未完成且业务上仍应完成的，进分母；「进行中且尚未到约定观察终点」的默认处理见项目约定（班次未结束时常不进分母，以免偏低）。

**超时率**（**仅当**任务定义了截止 \(s(\tau)\)）：

| 当时状态 | 是否算作完成 | 是否算作超时 |
|----------|--------------|--------------|
| 已经完成，且没有超过截止时间 | 是，且为准时 | 否 |
| 已经完成，但超过了截止时间 | 是，但是超时完成 | 是 |
| 仍未完成，且截止时间已经过了 | 否 | 是 |
| 仍未完成，但截止时间还没到 | 记为「进行中」；默认不进完成率分母 | 暂时不判超时 |

无截止字段时：不上报 LateRate；时效只看完成时延分布（[看板 B](./11-board-b.md)）。若考察整次仿真运行，结束时通常强制结算。公式见 [L-Joint](./08-l-joint.md)。

### 3.2 等待原因码

| 原因码 | 通常计入哪一类等待 | 谁最常看 |
|--------|--------------------|----------|
| `assign_queue` | 等业务分配 | 业务分配指标、看板 C |
| `traffic` / `yield` | 路径上的交管 / 避让等待 | 路径规划指标、看板 C、感官解释 |
| `congestion_avoid` | 为绕开拥堵而主动等待或绕行相关的停顿 | 感官看板 |
| `resource_lock` | 资源占用等待 | 看板 C |
| `charge` / `charge_queue` | 充电中 / 等充电位 | 充电策略、看板 C |
| `rest` | 在预配置休息点待命 | 休息策略、看板 C |
| `future_task` / `reposition` | 为后续任务预定位 | 感官看板、休息中后期选点 |
| `manual` | 人工介入导致的停顿 | 看板 D |

同一段墙上时间只归一个主原因。原因码越全，[感官看板](./18-sense.md) 的可解释覆盖率越高。

## 4. 指标定义模板

为每个指标固定记下这些信息，避免口头约定漂移：

- 名称与单位  
- 考察时间段怎么取  
- 统计的是哪一批任务  
- 若是单任务时延：起点时刻、终点时刻分别是什么  
- 包含哪些等待、排除哪些等待  

示例——吞吐量：

- 单位：任务数 / 小时  
- 时间段：按墙上时钟，或按一次运行  
- 任务范围：在该时间段内完成的任务  
- 分子：完成任务个数（或按载荷加权）；分母：时间段长度  

示例——任务从发到完成的总时延：

- 单位：秒  
- 任务范围：在该时间段内完成的任务  
- 起点：任务发布时间；终点：完成时间  
- 包含：分配等待与路径等待（端到端）  

示例——仅分配等待：

- 起点：发布时间；终点：分配成功时刻  
- 只计入原因码为「等分配」的等待  

## 5. 本阶段先不做

筛选 UI、自定义公式引擎、即席查询产品化——优先级放低。本层成功标准是约定够清楚，看板能从同一套事实上长出来。
