# 讨论区消息转发到微信方案

> 状态：**Phase 1 已落地（单条文本/链接转发到自己或他人微信）**。
> 适用范围：工单/任务详情页讨论区（`DiscussionPanel`，两端共用）。
> 通道：**微信公众号客服消息**（`/cgi-bin/message/custom/send`）。

---

## 1. 背景与目标

讨论区消息目前只能在系统内查看。用户希望把讨论消息**转发到微信**（仿微信转发体验），便于跨端留档、通知同事。

微信侧能力边界：
- 本项目接入的是**微信公众号（服务号）客服消息**，按 `open_id` 单发，**无法直接发到微信群**（群发接口面向全部粉丝，非指定群）。
- 客服消息有 **48 小时互动窗口**（`errcode 45015`）：接收人 48h 内与公众号有过交互才能送达。
- 开放 API **不支持**"合并转发聊天记录卡片"原生类型，需模拟。

### 分阶段范围

| 阶段 | 范围 | 状态 |
|------|------|------|
| Phase 1 | 单条文本/链接转发到自己或他人微信（接收人需绑定 open_id） | ✅ 已落地 |
| Phase 2 | 单条带图片/文件（补微信临时素材上传 `media/upload` + `image`/`file` 消息） | 待开发 |
| Phase 3 | 合并转发：前端 `html2canvas` 渲染聊天记录长图 → `image` 消息 | 待开发 |
| 后续 | 企业微信（应用消息/群机器人，无 48h 限制，支持微信群） | 待开发 |

## 2. 数据模型

### 2.1 `users` 表新增字段

业务账号需绑定微信 `open_id` 后才能作为转发接收人。微信登录用户（`username` 形如 `wechat_xxx`）的 `users.id` 即原始 `open_id`，无需绑定。

```python
# backend/app/models/identity.py · UserDB
wechat_openid = Column(String(128), nullable=True, index=True,
                       comment="绑定的微信open_id（讨论区消息转发到微信用）")
```

### 2.2 幂等迁移脚本

`backend/apply_user_wechat_openid_migration.py`（规避 alembic 多 head 问题，直接原生连接幂等加列）：

```powershell
cd backend
python apply_user_wechat_openid_migration.py
```

- 列已存在则跳过；不存在则 `ALTER TABLE ADD COLUMN` + 建索引。可重复执行。

### 2.3 open_id 解析逻辑

`backend/app/modules/tasks/api/task.py · _resolve_wechat_openid(user_record)`：

1. 优先取绑定的 `wechat_openid`（业务账号绑定后填入）；
2. 否则若 `username` 以 `wechat_` 开头（微信登录用户），取 `users.id`（即 open_id）；
3. 两者皆无返回 `None`（该用户不可作为转发接收人）。

## 3. 后端接口

### 3.1 微信 open_id 绑定（`backend/app/core/auth_routes.py`，前缀 `/api/auth`）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/me/wechat-openid` | 查询当前账号绑定状态，返回 `{bound, open_id_masked}` |
| `POST` | `/me/wechat-openid` | 绑定，body `{open_id}` |
| `DELETE` | `/me/wechat-openid` | 解绑 |

### 3.2 转发接收人列表（`backend/app/modules/tasks/api/task.py`，前缀 `/api/tasks`）

```
GET /api/tasks/{task_id}/comments/forward-targets
```

返回自己 + 全部同事，标注是否已绑定微信（`wechat_bound`），自己置顶：

```json
[{"id":"user_xxx","username":"zhangsan","name":"张三","is_self":true,"wechat_bound":true}, ...]
```
]

> 与 `/api/tasks/assignable-users` 解耦：后者字段最小化（id/username/name/status），本接口专为转发增加 `is_self` / `wechat_bound` 标记。

### 3.3 转发单条评论

```
POST /api/tasks/{task_id}/comments/forward-to-wechat
body: { comment_id, target_usernames: [...], as_link: bool }
```

- 取评论 → 去 HTML 标签得纯文本（截断 600 字防超微信文本上限）；
- 带附件消息附加 `[图片: xxx]`/`[文件: xxx]` 占位（Phase 1 仅转发文字 + 附件名，图片/文件本体待 Phase 2）；
- 按 `target_usernames` 查 `users`，解析每个接收人 `open_id`；
- `as_link=false`：发**文本消息**（`send_message_to_user`），含转发者、原作者、内容、工单链接；
- `as_link=true`：发**链接卡片**（`send_link_message_to_user`），标题=原作者讨论消息，点开跳工单详情页；
- 并发发送（`asyncio.gather` + `asyncio.to_thread`）：微信发送是同步 `requests` 调用，**必须丢到线程池**，否则会阻塞 FastAPI 事件循环导致整个后端卡死；
- 带附件的消息：content 可能为空（纯图片），附加附件名占位 `[图片: xxx]` / `[文件: xxx]`，避免发空消息；图片/文件本体待 Phase 2；
- 逐个发送，返回每人送达结果（`delivered` / `failed` / `skipped` 未绑定）。

详情页链接用 `settings.FRONTEND_BASE_URL` + `/app/tasks/{task_id}` 拼接，跟随环境配置。

## 5. 限制与风险

| 项 | 说明 | 处理 |
|----|------|------|
| 48h 互动窗口 | 接收人超 48h 未与公众号互动收不到（`errcode 45015`） | 转发结果返回失败原因；后续走企业微信 |
| 微信群 | 公众号无"发群"接口 | 留企业微信阶段（群机器人/群消息） |
| 合并转发 | 微信无原生聊天记录卡片 | Phase 3 用长图模拟 |
| open_id 绑定 | 业务账号需手动绑定 | 弹窗内提供输入入口，后续接 OAuth |
| 评论含 HTML | 微信文本消息不支持 HTML | 后端 `_strip_html_for_wechat` 去标签 |
| 附件消息 | 当前未支持图片/文件素材，转发时附附件名占位 `[图片: xxx]`/`[文件: xxx]` | Phase 2 补 `media/upload` |
| 同步阻塞 | 微信 `requests` 调用若直接在 async 接口执行会卡死事件循环 | 已用 `asyncio.to_thread` 丢线程池 + `gather` 并发 |

## 6. 测试要点

- 绑定：`POST /api/auth/me/wechat-openid` 绑定后 `GET` 返回 `bound:true`；转发接收人列表里自己 `wechat_bound:true`。
- 单条文本转发：选自己 + 一位同事，文本形式 → 双方微信收到含原文 + 工单链接的文本。
- 链接卡片转发：同上，`as_link=true` → 收到可点击跳工单详情的卡片。
- 未绑定接收人：选中未绑定同事 → 该项 `skipped`，其余正常送达。
- 48h 超时：模拟超时 → 返回 `failed` + `45015` 释义。
- 长按菜单：讨论区任意消息长按 → 菜单出现"转发到微信"项 → 打开弹窗。
- 带附件消息：转发含图片/文件的评论 → 微信收到文字 + `[图片: xxx]`/`[文件: xxx]` 占位，不卡死。
