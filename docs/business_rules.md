# 业务规则

> 本文记录 OpenRobotService 项目的核心业务规则、约束和决策，供测试开发和代码编写时参考。
> 与代码相关的业务逻辑见 `docs/CODEBASE_OVERVIEW.md`，产品需求见 `docs/PRD.md`。

---

## 一、角色与权限

### 1.1 角色定义

| 角色 | 标识 | 说明 |
|------|------|------|
| 客户 | `customer` | 现场人员，可提交工单、咨询、查看自己提交的工单 |
| 工程师 | `engineer` | 实施工程师，可接单处理、转派、讨论、上报 |
| 项目经理 | `manager` | 可派单、处理、讨论、查看本项目工单 |
| 上级领导 | `leader` | 可接收上报、决策、查看全局工单 |
| 系统管理员 | `admin` | 全部权限、用户与项目管理 |

### 1.2 权限规则

- 提交工单、参与讨论是所有角色的通用能力
- 权限码格式：`backend:{resource}:{scope}:{action}`
- `require_permission(perm, project_id)` 支持 admin 直通、`resource:*` 通配
- 开发环境可用 `/api/auth/dev-login` 跳过微信 OAuth 获取 JWT
- `frontend/.env.local` 的 `VITE_DISABLE_AUTH_GUARD=true` 可跳过前端守卫

## 二、任务状态机

### 2.1 状态流转

```
待派单(pending_assignment) → 已派单(assigned) → 处理中(in_progress)
                                                        │
              ┌───────────────────┬──────────────────────┼──────────────────────┐
              ▼                   ▼                      ▼                      ▼
         待讨论(discussing)   已上报(escalated)      已解决(resolved)       已关闭(closed)
                                                                              │
                                                                              ▼
                                                                        处理中(in_progress) ← 重开
```

### 2.2 状态合并规则（外部任务源同步）

当禅道等外部源同步任务时，状态取较后：

| 本平台状态 | 序号 | 外部来源 |
|------------|------|----------|
| `new` | 0 | `wait` |
| `in_progress` | 1 | `doing` |
| `pending` | 1（同级） | `pause` |
| `resolved` | 2 | `done` |
| `closed` | 3 | `cancel` / `closed` |

合并规则定义在 `app/integrations/engine.py` 的 `merge_status()`：
- incoming 序号 ≤ local 序号 → 不动（返回 None）
- incoming 序号 > local 序号 → 推进（返回 incoming）

### 2.3 工单任务类型映射（禅道 → 核心）

| 禅道 type | 核心 TaskType |
|-----------|---------------|
| `devel` | `feature` |
| `test` | `support` |
| `design` / `research` / `misc` | `other` |
| 空 / `None` | `other` |

### 2.4 任务优先级映射

| 禅道 pri | 核心 Priority |
|----------|---------------|
| 1 | `urgent` |
| 2 | `high` |
| 3 | `medium` |
| 4 | `low` |
| 空 / 非数字 | `medium` |

## 三、外部任务源集成

### 3.1 插件化设计

- 每个任务源是一个独立包，位于 `app/integrations/sources/` 下
- 通过 `TASK_SOURCES_ENABLED` 配置启用（如 `["zentao"]`）
- 插件实现 `TaskSourceAdapter` 接口，仅负责"拉取 + 翻译成 ExternalTask"
- 状态合并、账号映射、入库由 `SyncEngine` 统一处理
- 移除一个源：删除对应目录 + 从配置中去掉 → 核心零改动

### 3.2 同步规则

- 方向：单向只读（外部 → 本平台），不回写
- 触发：Airflow DAG 定时触发 `POST /api/tasks/sources/{name}/sync`
- 鉴权：独立 API Key（`X-API-Key`），与用户 JWT 分离
- 幂等：按 `(source, external_id)` upsert，可安全重跑
- 容错：单条失败不中断整批

## 四、测试隔离规则

### 4.1 数据库隔离

- **单元测试**：conftest.py 使用占位模块阻止真实 DB 连接，不需要 MySQL
- **集成测试**（`test_standard_task_creation_db.py`）：通过 `TEST_DATABASE_URL` 环境变量连接独立 MySQL，无此变量时自动 skip
- 生产 DB 连接串由 `settings.DB_CONFIG` 注入，测试环境不读取

### 4.2 外部服务隔离

- 微信功能测试：可用 `/api/auth/dev-login` 降级模式，无需真实微信环境
- MinIO 测试：不依赖真实对象存储
- AI 模块测试：需要真实 LLM API key 和网络连接（`ai/tests/test_llm_api.py`）

### 4.3 外部接口契约

- 后端 API 路由以 `/api/` 为前缀
- AI 服务路由以 `/api/ai/` 为前缀
- 微信回调路由以 `/api/wechat/` 为前缀
- 前端 `/api/*` 经 vite 代理或 nginx 分发：`/api/ai/*` → AI 服务，其余 → 业务后端

## 五、配置规则

### 5.1 环境变量

| 变量 | 用途 | 测试影响 |
|------|------|----------|
| `DATABASE_URL` | MySQL 连接串 | 不设置时单元测试也可运行 |
| `TEST_DATABASE_URL` | 测试用 MySQL 连接串 | 设置后集成测试才会执行 |
| `TASK_SOURCES_ENABLED` | 启用的任务源 | 影响集成注册行为 |
| `WECHAT_*` | 微信配置 | 缺失时功能降级为日志 |
| `MEILI_ENABLED` | Meilisearch 全文检索开关 | 可降级为 ilike |

### 5.2 前端构建配置

| 构建命令 | base | API 前缀 | 用途 |
|----------|------|----------|------|
| `npm run build` | `/` | `/api` | 默认 |
| `npm run build:test` | `/t/app/` | `/t/api` | 测试环境 |
| `npm run build:prod` | `/p/app/` | `/p/api` | 生产环境 |

## 六、项目管理规则

### 6.1 项目唯一键约束

- **项目编号**（`project_code` / `project.code`）与 **项目名称**（`name`）均为项目的唯一 key。
- 后台「项目管理 → 项目导入 → USP 项目」新建项目时，以下字段为必填：**项目名称、项目编号、项目状态**。
- 创建（`POST /api/admin/projects/`）与更新（`PUT /api/admin/projects/{id}`）时，后端会先与库中已有项目比对：
  - 项目编号或项目名称已存在 → 返回 `409 Conflict`，提示「项目编号/项目名称『xxx』已存在，请重新输入」。
  - 更新时排除当前项目自身（`exclude_id`），避免自比较误判。
- 并发提交兜底：即使绕过前端校验，数据库 `project.code` 唯一索引冲突也会被转换为 `409` 提示，而非 500。
- 前端新建页对三个必填字段做提交前校验，并把后端的 409 提示原样展示给客户（Toast 警告）。

## 七、知识贡献榜与匿名归档审核（2026-10-15）

- 一期时间：北京时间2026-11-01 00:00至2027-01-01 00:00，不含结束时刻。创建和首次有效归档都须在活动期间；历史工单不补计，归档须报告审核通过。
- 以首次有效归档的自然月归属贡献；重开、重提或更换报告不增加次数、不更换首次计分用户或跨月重计。
- 提单与接单按用户归并为唯一综合月榜；有效贡献数降序，相同再按相关当月工单收到的有效点赞数降序。前三各100元、第4—10名各50元，不分角色另发一份。
- 同用户同工单双角色暂计一次并标记待确认；完全同分若跨第3/4或第10/11奖励边界，最终核验暂不通过，不能自行扩大奖励名额。
- 全部登录用户可查公开榜单及通过报告，提单/接单身份可公开，审核人身份始终不公开。未通过正文不进入公开问题榜。
- 后台首页“知识贡献榜”整块卡片（标题、“查看榜单”入口、前三名和提示文案）由独立权限 `frontend:admin:knowledge:show` 控制。权限管理显示“显示知识贡献榜”启停开关，角色管理可对任意系统/项目角色勾选或取消；用户任一实际角色获得该权限且权限已启用即可显示，不再按角色名称写死。未勾选默认隐藏，用户名admin、`isAdmin`、通配权限及原角色名称不替代明确授权；全局开关关闭后所有角色均隐藏。初始化仅补充权限定义，不自动给任何角色授权，不重置已有的启停或角色配置。
- 用户详情继续下发 `can_view_knowledge_contribution`，前端默认隐藏，角色加载失败、退出或切换账号时不沿用旧标记，隐藏时不请求卡片榜单数据。配置后刷新用户详情生效；角色权限授予/撤销及权限更新/删除清除当前进程缓存，多进程其余实例最多沿用现有60秒缓存。本次仅控制首页卡片可见性，不改变公开知识接口、独立榜单页面或匿名审核的原有访问规则，不新增数据库表或字段。
- 完整人员榜展示同一综合月榜前十名，头像每行三人；点击可按月份查看该用户提单/接单的已公开归档工单，不因此开放未归档或原始私有工单。角色筛选使用首次发布的贡献归属，不按后来改派的人重新计分。
- 已公开知识详情提供独立讨论区，登录用户可发布1—2000字纯文本并分页查看；不公开原工单内部评论，讨论不改变工单状态、不计贡献或奖金。审核人参与讨论时作者匿名，正文继续隐藏审核人身份及敏感信息；问题撤回或失去有效公开资格后讨论不可读写。
- 平台名单派审且必须回避提单人、当前接单人及报告作者；匿名报告仅分配审核人可处理，审核动作须revision匹配。审核人不能用原任务详情、文档、关联列表或WS绕过匿名页面。
- 榜单总览为平台指定名单、已有分配/意见记录的人员及管理员展示评审工作台入口；名单人员无需先收到任务。入口可见不代表获得其他人的报告权限，管理员也不能代看/代审未分配给自己的报告。待审数量及列表不受活动月份限制，审核身份统一匹配用户ID/账号/OpenID。
- 通过、驳回均须意见；通过另须价值点。驳回意见只供当事人及该意见作者，历史按报告提交版本保存，重提不覆盖。
- 活动报告须包含问题概述、问题场景、复现条件、原因分析、解决方案、验证结果、适用范围、遗留问题八个Markdown章节，各节正文不能为空。AI初稿不能覆盖已有或已经提交的内容。
- 点赞按用户/工单去重，可取消；本人提单/解答及当前审核的问题不能自行点赞计奖，风险无效或待核验点赞不计有效获赞。月榜用事件还原月末点赞状态。
- 每个用户按北京时间自然日最多成功点赞5个不同问题，每日00:00重置；仅计当日成功点赞事件，历史仍有效的点赞不占当天名额。同日同题重复请求或取消后重赞不重复占额，取消及后续判无效不返还当天名额；失败请求不占额，取消操作不受限额拦截。达到上限后对新问题点赞返回429及中文说明，列表、人员工单与详情使用同一后端校验。首页知识贡献榜卡片及榜单页顶部展示此规则，不增加奖金激励提示。
- 2026-10-16起知识榜单移除异常观察与月度结算入口及操作界面，管理员也不显示；月度排名和预计奖金展示不变，不因移除界面自动发奖或删除历史奖励记录。
- 奖金激励方式由专门入口提醒，知识首页及榜单各页不再分散展示奖励金额规则、叠加规则、核验/发放或结算说明；后端内部提示不直接透出。原已确认的头像旁奖金数额仍保留，排名、计奖和奖励数据不变；本轮不新增该提醒入口。
- 保留的后台兼容接口仍要求admin或 `backend:knowledge_incentive:manage`；异常核验不作为第二轮内容审核，未完成既有核验不得入账月榜奖金，前端不再提供这些操作。
- 后台兼容服务仍保留月末冻结、风险修订、重新核验及发放幂等保护；发放中禁止并发更改计奖点赞。月榜奖励通过 `knowledge_monthly` 来源幂等入账，可与单题、优质奖励叠加。
- 入账不等于微信转账成功；提现继续使用现有奖励/转账链路。本次未新增单题6元自动入账，优质奖金规则待定不能按0元完成结算；挂赏追加与活动宣传轮播仍在后续范围。
