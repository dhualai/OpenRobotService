## 0. 背景与现状

### 0.1 需求回顾

工单逾期/催办提醒当前在非工作时间（含凌晨）推送。期望改为：

- 触发时间落在非工作时间 → **不即时推送**，改到就近工作时间节点
- 截止时间在非工作时间内 → 在**截止前最后一个工作时段末尾**发「即将逾期」
  - 例：周五 23:00 的提醒 → 改到周五 17:00 发
- 期间未处理 → 在**截止后第一个工作时段开始**发「已逾期」
  - 例：周一 09:00 发
- 判断基准：**接收人所在时区**，而非服务器时间
- 需**排除法定节假日**，节假日期间命中的提醒顺延到节后首个工作日

### 0.2 现状调研结论（代码事实）

| 结论 | 证据 |
|---|---|
| 自动逾期/临期提醒**只有一处**入口：Airflow DAG | `dags/notification_dag.py` |
| DAG 判断依据是 `deadline_at`，**不检查 `updated_at`** | `dags/notification_dag.py:201-244` |
| "工单长时间未更新"只是模板写死文案，**不是真实扫描条件** | `backend/app/utils/notification_utils.py:736` `reason = "工单长时间未更新"` |
| DAG 为**无状态 + 精确整点窗口命中即发**，`catchup=False` | `dags/notification_dag.py:243` `if notify_hour != now_hour_floor: continue` |
| 通知为**同步直发**，走本地线程池，**进程重启即丢** | `backend/app/utils/notification_utils.py:762` `run_in_executor` |
| 用户/公司/部门**均无时区字段** | `backend/app/models/identity.py`、`backend/app/models/organization.py` |
| **无任何工作时间/节假日/免打扰配置** | 全库检索无相关实现 |
| **无用户级通知偏好**，前端也无设置页 | `frontend/src/pages` 下无通知设置页 |
| 普通用户**无自助更新资料接口**，仅管理员可改 | `backend/app/modules/admin/api/users.py:772`（`require_permission`） |
| 服务号**无法获取用户时区**（微信已下线地区字段） | `backend/app/wechat/api/wechat.py:432` 注释：「nickname/sex/city 等字段微信已不再提供」 |
| 活跃/未完结状态口径**存在 4 套不一致**定义 | DAG 用 `new,in_progress`；统计用 `new,pending,in_progress`；仪表盘用 `in_progress,pending_requested,pending` |

> ⚠️ **关键结论**：当前 DAG 是「窗口命中即发」。若仅在发送前判断"非工作时间则跳过"，通知会**永久丢失**。必须引入「按接收人排程 + 持久化 Outbox」。

### 0.3 方案 2 的两个硬缺口

**缺口 1 — 覆盖率盲区**
浏览器上报只能覆盖「登录过 Web 端」的用户。系统存在 `wechat_xxx` 形式的微信登录用户，一线被催办人可能长期只在微信收消息、从不打开后台——这部分人**永远拿不到时区**。必须有兜底默认值。

**缺口 2 — 时区解决不了节假日**
时区只回答"几点算上班"，回答不了"国庆放几天"。"哪天是法定假日"仍需靠**组织归属**决定。因此节假日日历 + 三级绑定**不能省**。

## 4. 建议落地组合

考虑到方案 2 的覆盖率缺口（P0-1），建议实际采用 **「方案 2 + 组织级默认值兜底」**：

```
用户有效时区 = 浏览器上报值（若已上报且未锁定）
             ↓ 未上报
             = 部门配置
             ↓ 未配置
             = 公司配置
             ↓ 未配置
             = 系统默认 Asia/Shanghai
```

这样即使一线运维从未登录 Web，也能靠公司配置拿到正确时区和节假日，避免「通知永远发不出去」或「永远凌晨发」的极端情况。

### 最小可用闭环（MVP）

```
A1 组织/用户时区字段
B2 节假日模型 + B3 三级绑定 + B4 工作时间计算服务
C1 Outbox 表 + C2 排程 Worker + C3 通知意图入队
D1 DAG 改为事件识别 + D3 逾期顺延到下一工作时段开始
```

即可先解决「凌晨推送」问题；D2（临期前置）、C5（积压合并）、E 系列（配置界面/监控）迭代补齐。
