# AI 检视使用说明（ORS-1149）

## 贡献约定

**协作者统一使用主仓分支提 PR（不经过 fork）**。fork PR 的深度检视事件
GitHub 不派发（无 secrets 必失败，实测 4 次全零），快筛虽能跑但无评论能力。

## 触发方式

| 场景 | 操作 | 执行者 |
|---|---|---|
| 规则快筛 | PR 打开/更新**自动**（秒级，无高危完全静默） | 无需操作 |
| 深度检视 | PR 页面右侧 Labels 勾选 `ai-review` | 任意有写权限成员 |
| 带标签 PR 的迭代重检 | 无需操作——每次 push 自动升级深度检视（标签=开关） | — |
| 移除深度检视 | PR 页面摘掉 `ai-review` 标签 | 任意有写权限成员 |

深度检视触发后：PR 评论区出现 ⏳ 进度评论（分阶段打勾 + 已进行秒数），
约 1~2 分钟自动替换为检视报告，标签自动摘掉（下次再打即再次触发）。

## 报告解读

- 🔴 **必须采纳**：合入前应处理的问题（高危/涉库/密钥/部署链路）；
- 💡 建议折叠在每条下方，含影响、改法与收益；
- 报告**不阻塞合并**，是否采纳由人工判断；
- `🔄 较上次检视：新增 X 条，已消除 Y 条` 为与上次报告的增量对比；
- 尾部 `⏱ 总耗时` 为本次检视的分项耗时。

## 已知限制

- 部署机/服务器上的深度检视增强（如 PR 评论命令 `/ai-review`）为二期候选，
  未实现；
- AI 检视意见由 LLM 生成，存在误报可能——观察期误报记录见
  [evaluation.md](evaluation.md)。
