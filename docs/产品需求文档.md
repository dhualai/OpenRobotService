## 一、产品定位与愿景

### 1.1 一句话

> 面向工业移动机器人（AGV/AMR）行业的微信服务号平台——**高效"摇人"解决问题、加速项目交付**，AI 沿"需求/供给/管理"三种视角全流程深度参与。

### 1.2 四项根本决策

| 维度 | 决策 |
|---|---|
| 产品路线 | 开箱即用的成品平台，非抽象框架 |
| 领域绑定 | 专门面向工业移动机器人（AGV/AMR） |
| 目标用户 | 现场工程师 / 客户 / 管理人员——全部移动端办公 |
| 开源关系 | 开源版是主线，官方「摇人吧」是推广门面 |

### 1.3 品牌

- **品牌名**：摇人吧 | **英文代号**：OpenRobotService
- **Slogan**：机器人有问题，还得摇人吧！
- **入口**：微信服务号扫码关注，底部三菜单直达

### 1.4 愿景阶段

1. **短期（0-6月）**：底座稳固 + 三业务模块上线 + AI Agent 初步可用
2. **中期（6-18月）**：知识库 RAG 成熟，"工单关闭→AI总结→审核入库"闭环跑通
3. **长期（18月+）**：建成行业第一个开源知识协作平台，AI 从辅助走向自治

## 二、核心设计理念：三视角架构

现实中人往往身兼数职，系统按**行为视角**而非角色切分：

| 视角 | 行为 | 菜单 | AI Agent |
|---|---|---|---|
| 🆘 需求 | 主动求助 | 我要摇人 | 提单 Agent（诊断引导） |
| 📥 供给 | 被动承接 | 系统任务 | 任务 Agent（辅助处理） |
| 📊 管理 | 监控全局 | 后台管理 | 管理 Agent（风险分析） |

三个菜单对所有人统一开放，内容按身份**动态渲染**。人人都有三种视角的需求。

### 角色对应视图

| 角色 | 我要摇人 | 系统任务 | 后台管理 |
|---|---|---|---|
| 客户 | 报障、咨询、看自己工单 | 相关回访/确认任务 | 自己项目概况 |
| 工程师 | +提需求/bug | 派给我的工单/bug | 负责项目的工单/风险 |
| 经理 | 同上 | +待审批上报/待派单 | 跨项目看板/风险概览/决策 |
| admin | 全部 | 全部 | +用户权限管理 |

> Wave 1（ORM 收敛、Alembic 工具链、shim 层兼容）已于 2026-07-10 完成。

### 4.2 外部任务源集成（禅道）

四阶段插件化设计方案（`INTEGRATION_DESIGN.md`）：

- **Phase 1**：ExternalTask 契约 + SyncEngine + 数据模型变更
- **Phase 2**：禅道 client/mapper/adapter 实现
- **Phase 3**：通用路由 + API Key 鉴权 + 账号映射 CRUD
- **Phase 4**：Airflow DAG 定时触发 + 文档

关键设计原则：移除禅道时核心代码零改动。

### 4.3 USP 平台接缝

机器人故障与任务统计数据入站接口（`POST /api/integration/usp/*`），独立 API Key 鉴权，落库供后台管理看板展示。

2026-07-16 刚完成 `/app` 工作台收口（三 Tab MainLayout），workbench store 跨视图联动。AI 模块（诊断 SSE/LLM 对话/会话记忆）落地。

| AI 依赖知识库 | Agent 效果取决于 RAG 质量 | 先建库后调 Agent |

## 七、产品设计原则

1. **三菜单 = 三视角 = 三 AI Agent**，一一对应，AI 沿全流程渗透
2. **统一显示、内容动态**，贴合"一人多角色"真实工作流
3. **纯移动端**，无 PC 后台
4. **知识库是护城河**，AI 质量取决于知识库专业度
5. **效果优先于部署轻量**，服务效果是生命线
6. **功能垂直切分**，每人对口一个模块全栈（100% AI 生成代码协作）
7. **插件化外部集成**，禅道等外部源接入/移除对核心零侵入
