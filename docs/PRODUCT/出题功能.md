# 后台管理：AI知识点文章与关联题目生成设计

> **文档用途：** 明确后台管理的产品方案和实现边界；2026-11-20已增加首版后台页面与配套接口，实际交付、部署条件及未覆盖项见第16节，不代表目标环境已部署。  
> **本期范围：** 多来源选材 → 全量脱敏 → AI提炼知识点文章 → 人工确认 → AI生成关联题目 → 人工审核 → 后台管理与开卷预览。  
> **学习模式：** 用户先阅读知识点文章，再直接回答相关问题；答题时可以继续查阅文章，属于开卷学习，不是闭卷考试。  
> **明确暂缓：** 不设计系统任务中的呈现、创建、分发、通知、接收人、完成状态、作答记录或统计，也不实施用户端学习页面。

---

## 1. 设计结论与范围

### 1.1 本轮确认的产品方向

1. 先把后台管理的AI生成文章、生成题目和内容管理设计完整，系统任务如何承载这些内容留到下一阶段。
2. 工单来源包括已关闭及关闭后的节点，当前项目具体为 `closed`、`archiving`、`archived`，不只允许 `closed`。
3. 知识点文章与现有知识沉淀文章是不同内容：前者是短小、精炼、可复用的知识，后者通常记录某个项目实际问题的处理经过。
4. 一篇知识点文章可以来自多个相似工单，也可以来自技术资料等非工单材料，不强制关联唯一来源工单。
5. 工单和其他材料必须先脱敏再生成；普通学习内容只包含知识点和相关题目，不展示原始工单、来源身份或内部记录。
6. 题目用于帮助用户理解刚读过的知识点。答案依据应在文章内，不能以隐藏文章、禁止查阅或记忆项目细节作为考查方式。

**术语约定：** 本文统一使用「知识点文章」指新生成的精炼学习内容，使用「沉淀文章/归档报告」指现有案例内容。「更短小、来源不限于工单」针对知识点文章，不要求改写现有沉淀文章的定位。

### 1.2 本期设计与交付边界

| 设计范围 | 本期要求 |
|---|---|
| 后台知识点生成 | 选择一个或多个来源、脱敏预处理、AI生成文章、人工修改与确认 |
| 后台知识点管理 | 草稿恢复、搜索筛选、版本查看、修改、启用与停用 |
| 后台关联题目生成 | 基于已确认文章生成单选、多选、判断题，并支持人工编辑 |
| 后台题库管理 | 提交审核、通过/驳回、启用/停用、查看关联文章和内部依据 |
| 后台开卷预览 | 验证「先读文章、再答相关问题、答题时可查阅」的内容体验 |
| 内容与安全底座 | 多来源追溯、不可变文章版本、脱敏、后端权限、操作留痕、生成失败恢复 |

本期不做系统任务接入、正式用户答题服务、学习记录、任务进度、通知、分发、考试排名、积分奖励、自动组卷或复杂学习统计。后台预览不生成真实用户作答记录，不将预览次数当成学习数据。

### 1.3 与现有项目的关系

- 复用后台布局、菜单和角色权限、工单查询、AI客户端、Markdown展示、迁移和审计能力。
- 现有 `KnowledgePublication` 是以工单为主键的归档知识发布实体，不直接当作本功能的文章主表。
- 新功能不修改工单状态、不覆盖归档报告、不自动公开沉淀内容，也不改变知识贡献计分、财务审核或奖励规则。
- 允许读取已有沉淀材料作为来源，但「读取来源」与「发布一篇新知识点文章」是两个独立动作。
- 现在只定义独立的内容资产和后台管理流程，不提前确定系统任务的表结构、生命周期或页面形式。

## 2. 知识点文章的定位

### 2.1 与沉淀文章的区别

| 对比项 | 沉淀文章/归档报告 | 本功能知识点文章 |
|---|---|---|
| 主要目的 | 留存某次实际问题和处理经验 | 提炼可重复学习、可直接应用的知识点 |
| 组织方式 | 项目背景、现象、处理经过、结果 | 知识结论、适用条件、关键方法、注意事项 |
| 内容长度 | 可以较长，保留案例过程 | 短小精炼，一篇聚焦一个主题 |
| 来源关系 | 通常围绕具体工单或案例 | 可以综合多个相似工单及其他材料 |
| 用户阅读重点 | 了解这次问题如何解决 | 理解这个知识点是什么、何时适用、如何判断 |
| 对具体身份的依赖 | 内部材料可能包含项目与人员信息 | 学习内容不得依赖来源身份或私有上下文 |

**知识点文章不是把一篇归档报告缩短，也不是把几个工单全文拼在一起。** AI应抽取共同知识、保留必要技术边界，去掉案例身份、重复过程和无助于学习的细节。

### 2.2 篇幅和结构

- 默认一次生成一篇文章，一篇只讲一个可独立理解的知识主题。
- 正文建议约300～800字，可更短，不以凑够字数作为质量要求；过长时提示拆分主题。
- 核心知识通常整理为1～5条，优先讲清楚结论和适用条件，不强制套用完整故障报告模板。
- 有必要时补充一个短小、匿名化的说明示例，但示例不得伪装成来源中真实发生过的事实。
- 涉及不同产品或版本的差异时分开说明；不能把只在某一版本成立的结论抽象成通用规则。
- 信息不足以形成可靠知识结论时保留草稿并提示补充，不生成看似完整的正式文章。

推荐正文结构：

1. **知识结论：** 要掌握的核心概念或判断方法。
2. **适用条件：** 适用场景、前置条件和不适用情况。
3. **关键方法：** 必要的判断依据、步骤或处理原则。
4. **注意事项：** 容易误解之处、例外条件和安全边界。

不是每篇文章都需要四个独立小标题；可以使用简短段落和要点，但必须让读者准确理解结论及适用范围。

### 2.3 示例：从案例提炼知识

- 来源材料：若干工单分别描述车辆定位异常时的排查过程，以及一段经确认的相关技术说明。
- 不合适的文章：「某客户某项目某天发生定位问题，某工程师修改参数后解决」。
- 合适的知识主题：「定位异常排查时如何区分环境因素与配置因素」。
- 应保留：材料确实支持的判断依据、前置条件、适用范围和安全限制。
- 应移除：客户、项目、人员、设备标识、具体地址、内部链接及能够反推出来源的独特细节。
- 若不同案例的条件不一致，应说明差异或拆开生成，不能仅因为现象相近就合并处理结论。

该示例只说明抽象方式，不预设任何具体设备诊断结论。

## 3. 后台入口与完整流程

### 3.1 已确认菜单与维护入口

```text
后台管理
└── 其他
    └── 运营与数据
        └── 题目生成
            ├── 知识点管理（新建、生成、编辑、确认、版本和启停）
            └── 题库维护（生成、编辑、审核、启停和开卷预览）
```

页面路由为 `/admin/question-generation`，返回入口为 `/admin/entries/operations`。生成和日常维护共用这个页面，不另设「知识学习」一级菜单。「知识点管理」用于找回文章草稿、修改文章和查看版本，不能只提供一次性的生成向导。

### 3.2 主流程

```text
知识点生成
    ↓
选择一个或多个工单 / 添加其他技术材料，填写知识主题
    ↓
后端校验来源权限与工单状态，构建脱敏材料和内部依据标记
    ↓
AI提炼一篇短小的知识点文章草稿
    ↓
管理员编辑，检查适用边界、事实依据与脱敏结果
    ↓
确认文章，形成不可变的已确认版本
    ↓
基于该版本生成相关题目
    ↓
编辑题目 → 提交审核 → 审核通过
    ↓
形成可用的「知识点文章版本 + 关联题目」内容资产
    ↓
后台开卷预览：先读知识点，再回答问题，可随时查阅文章
```

本流程终点是后台内容资产和预览，不继续设计任务发布和用户任务执行。

### 3.3 保存和恢复

- 文章草稿、来源选择和已成功生成的题目保存在后端，不依赖浏览器内存维持整个流程。
- 保存文章草稿后，可从知识点管理列表点击「继续编辑」或「继续出题」。
- 保存题目草稿后，可从题库管理列表继续编辑和提交审核。
- 已确认文章可稍后再出题；文章确认和题目生成不是必须一次完成的事务。
- 页面离开前有未保存修改时提示；生成失败、切换步骤或刷新后不清空已保存数据。

## 4. 来源材料选择

### 4.1 来源类型

| 来源类型 | 本期支持方式 | 约束 |
|---|---|---|
| 工单 | 从现有工单列表中选择一张或多张 | 仅允许已关闭及关闭后节点，且当前操作人有权读取 |
| 沉淀文章/归档报告 | 从已选工单中读取有权访问的内容；已有独立选择能力时可复用 | 不因具备生成功能权限而绕过归档审核或匿名访问限制 |
| 其他技术材料 | 后台人工录入或粘贴技术说明、产品资料片段、操作规范等 | 填写材料名称和出处说明，确认有权使用且版本明确 |
| 已有附件解析文字 | 复用项目已经支持的附件文字提取结果 | 无法解析时明确提示未纳入，不新建OCR、爬虫或复杂文档解析平台 |

一篇文章至少需要一份有效材料，但可以没有工单。非工单来源本期先通过人工录入/粘贴覆盖，不把新建资料库、自动抓取外链或上传解析能力作为前置条件。

### 4.2 工单范围

- 当前允许状态明确为 `closed`（已关闭）、`archiving`（归档中）、`archived`（已归档）。
- 不把 `resolved`（已解决但尚未关闭）或其他未关闭状态自动纳入。
- 默认查询上述全部状态，可按状态、编号/标题、类型、项目、产品和时间继续筛选，支持跨页多选和去重。
- 生成前由后端再次校验实际状态与读取权限，不能只在前端限制选择。
- 处于 `archiving` 的工单也可使用，但不能将尚未审核的归档结论视为已确认事实；不允许越权读取匿名审核内容。
- 确认文章前再次核对来源资格；工单重开或权限失效时暂停确认，提示移除、替换来源或重新核验。

### 4.3 选材交互与读取优先级

- 工单列表展示编号、标题、状态、类型、时间和是否已有知识点文章，仅向有对应来源权限的管理人员展示。
- 已选材料面板展示材料名称、类型、脱敏摘要和内部标记 `S1`、`S2` 等，允许移除、补充及标记重点。
- 知识主题可由管理员填写；未填写时由AI提出建议，管理员需要确认本次只聚焦一个主题。
- 优先使用有权读取且已经确认的处理结论、审核通过的归档内容和版本明确的技术材料。
- 沟通记录中的猜测、AI诊断草稿、未审核报告只能作为待核验线索，不能直接提升为知识结论。
- 多个来源存在矛盾、版本差异或主题不一致时给出提示，要求管理员区分条件、移除材料或拆分主题。
- 不强制保留一个「主要来源工单」；文章与来源是多对多关系，同一工单也可用于不同知识主题。

## 5. 全量脱敏与内部追溯

### 5.1 脱敏流程

```text
有权限的后端读取原始材料
    ↓
确定性脱敏：身份、项目、设备标识、联系方式、地址、链接、密钥等
    ↓
仅将脱敏后的材料及 S1 / S2 等标记发送给AI
    ↓
对AI输出再次检查敏感信息和可反推来源的细节
    ↓
管理员核对知识正确性、匿名化程度与适用边界
    ↓
确认后形成不包含原始来源身份的知识点文章
```

- 不把完整原始工单直接交给模型，再只靠提示词要求模型脱敏；脱敏必须包含后端预处理和输出复查。
- 人名、账号、微信标识、电话、邮箱、客户名、项目名、实际地址、设备序列号、内部IP/域名、工单编号、附件地址和凭据等不得进入学习内容。
- 对独特时间、现场位置、设备组合等可能反推来源的描述做泛化或删除，不能只替换姓名。
- 为理解知识必须保留的通用技术概念、单位、非敏感产品类型和版本适用范围可以保留；私有配置值及能定位现场的内容应移除或抽象。
- 不能因为脱敏而删除影响结论成立的条件。无法同时保证匿名性和技术准确性时，不确认该知识点，要求重新选材或人工重写。
- 管理员后续手工修改文章、题干、选项、解析和示例后，也要重新执行脱敏检查，防止人工重新带入敏感内容。
- 本期知识正文以文字为主，不自动嵌入原始工单图片、附件或私有链接；已有图片不能因为文字脱敏就被视为安全材料。
- 模型返回内容、错误提示、生成日志和审计日志不得包含密钥、原始敏感材料或完整请求体。

### 5.2 内部追溯与学习内容分离

| 内容 | 后台内部用途 | 学习内容中是否出现 |
|---|---|---|
| 来源类型、内部标记、脱敏依据摘录 | 核验知识来自何处 | 不出现 |
| 原始工单ID、材料定位信息、来源版本 | 有权限人员追溯 | 不出现 |
| 客户、项目、人员、设备身份、原始链接 | 仅保留在既有受控来源中，不复制到文章正文 | 不出现 |
| 精炼知识正文、适用范围、注意事项 | 编辑、确认和阅读 | 出现 |
| 关联题干和选项 | 编辑、审核和答题 | 出现 |
| 正确答案和解析 | 后台编辑审核；预览提交后反馈 | 不在答题前作为答案字段展示 |

- 后台来源面板默认展示脱敏摘要；查看原始工单仍需满足该工单原有权限，不能仅凭内容管理权限放行。
- 内部追溯信息使用独立实体和独立响应字段，不先返回给学习内容前端再通过隐藏组件处理。
- 学习内容采用白名单字段投影，不带原工单入口、来源标记、内部审核意见、生成提示词或敏感映射表。
- 全脱敏不等于取消追溯：管理端可以查证来源，学习内容不承担展示原始材料的职责。

## 6. AI生成、编辑与确认知识点文章

### 6.1 生成配置与结果

- 输入：有效来源集合、知识主题或主题建议请求、目标读者和可选的考查重点。
- 一次生成一篇文章；若材料包含多个独立主题，返回拆分建议，不强行拼成一篇。
- 后端配置单次来源数量、单份文字及总上下文上限；超限时明确提示精简或分批，不静默截断关键条件。
- 生成结果包括文章草稿、内部依据映射、待核验事项和不能采纳的材料说明。
- 文章正文中的技术结论必须能追溯到材料，通用表达可以归纳，但不能引入材料外的新参数、结论或操作建议。
- 多案例共同结论必须有足够依据；只在一个案例中出现的情况不能未经说明就推广为普遍规律。

### 6.2 文章字段

| 字段 | 要求 | 说明 |
|---|---|---|
| 文章编号 | 系统生成 | 与工单编号独立，不暴露原始工单身份 |
| 标题 | 必填 | 简短说明知识主题，不使用带客户、项目身份的工单标题 |
| 分类 | 必填 | 复用合适的现有分类能力；不存在时提供可维护分类 |
| 标签 | 可选 | 用于搜索、筛选和复用 |
| 知识结论 | 必填 | 一段简洁、事实可靠的核心概括 |
| 适用条件 | 必填 | 说明场景、前提、版本或限制，不能写无依据的「所有情况适用」 |
| 核心知识点 | 必填 | 1～5条，每条有稳定的内部标识，如 `KP1`，便于题目定位依据 |
| 关键方法 | 按需 | 有明确方法或判断过程时填写，不强制编造处理步骤 |
| 注意事项/安全边界 | 按需 | 存在例外、误区或安全风险时必须说明 |
| 简短示例 | 可选 | 匿名且不引入新事实，可明确标注为说明性示例 |
| 内部依据 | 确认前必填 | 核心知识点与来源标记、脱敏摘录的对应关系，不进入阅读正文 |
| 待核验事项 | 内部字段 | 缺失信息、冲突结论、未证实假设；未解决的关键事项阻止确认 |
| 版本及状态 | 系统维护 | 区分可编辑草稿和不可变的已确认版本 |

文章正文由上述内容字段统一渲染，管理端编辑和阅读预览使用同一份内容数据，不维护两份可独立修改的正文。`KP1` 等内部标识和依据映射不需要显示给学习者。

### 6.3 页面与操作

文章编辑页分为「脱敏材料摘要」「知识点文章编辑」「内部依据/待核验事项」三个区域，支持查看生成警告和实际纳入的材料。

| 操作 | 规则 |
|---|---|
| 生成文章 | 后端校验来源，脱敏后调用AI，结果只进入草稿 |
| 保存草稿 | 保存文章、来源快照和待核验事项，不自动确认 |
| 重新生成 | 只处理当前草稿；提示已有人工修改，生成候选结果，确认替换后才覆盖草稿 |
| 确认文章 | 校验事实依据、必填项、适用边界及脱敏结果，形成不可变版本 |
| 生成题目 | 仅针对当前启用文章的有效已确认版本 |
| 修改已确认文章 | 创建新版本草稿，不原地修改已确认正文 |

确认不要求补齐与知识主题无关的「原因分析、故障现象、完整解决经过」，避免继续沿用案例报告模板。但核心知识没有依据、适用范围无法确定或安全结论待核验时，不能以「待补充」占位通过确认。

涉及人员安全、急停、维修、带电操作等知识，必须由具备相应专业能力的人员核对安全边界；无法核验时不得确认或用于出题。

### 6.4 版本与可用性

- 文章有独立主记录，版本内容单独保存。已确认版本包含实际正文、核心知识点及当时的脱敏依据快照，不能只存 `updated_at`。
- 同一文章本期只保留一个待编辑草稿；已确认版本保留为不可变历史记录。
- 首次确认文章后成为当前已确认版本，默认启用；确认操作中明确提示该结果，但不代表发布到任何用户或系统任务。
- 修改时从当前版本创建新草稿。新草稿尚未确认期间，原已确认版本仍为当前版本，可正常使用；如原内容有错误，管理员应主动停用文章。
- 新版本确认后，事务内切换当前版本，并将关联旧版本的题目退回草稿、停用，记录「文章版本更新，待重新核验」；历史审核记录不删除。
- 旧题不能自动绑定新版本或自动继承审核结果。管理员需重新生成，或核对后明确更新文章版本、知识点及依据，再提交审核。
- 文章停用后不允许新出题，也不提供可用的关联题目集合；历史版本、题目及审核记录保留。
- 重新启用文章不自动恢复被驳回、退回草稿或人工停用的题目；可用性仍需逐项满足题目规则。
- 已确认后来源的状态或正文变化不静默改写文章；发现事实失效、材料撤回或隐私风险时提示复核，必要时停用文章及其可用内容。

- 筛选条件：关键词、分类/标签、草稿/已有确认版本、启用状态、是否已有题目、创建人和时间。

- 允许停用和重新启用；已确认或已关联题目的文章不提供物理删除操作，避免丢失依据。

- 本期不提供脱离来源的自由AI写作入口；人工补充新的技术结论时，应同时增加有效材料并重新确认。

## 8. 基于知识点文章生成题目

### 8.1 前置条件与配置

只有文章已启用、存在当前已确认版本时，才允许生成题目。题目只基于选定文章版本，不让AI重新读取原始工单补充隐藏知识。

| 配置 | 默认值/规则 |
|---|---|
| 生成数量 | 默认3道，允许1～10道；依据不足时可少于请求数量 |
| 题型 | 单选、多选、判断，默认由AI按文章内容选择合适组合，也可指定 |
| 难度 | 默认中等，可选简单/中等/困难；困难不代表依赖文章外知识 |
| 考查重点 | 从文章知识点中选择，可多选；默认覆盖主要知识点 |
| 出题依据 | 后端绑定当前已确认文章版本，不允许客户端任意指定未确认内容 |

### 8.2 开卷出题原则

1. 读完当前文章应当有足够依据回答问题，答题时重新查阅文章是正常行为。
2. 优先考查结论理解、适用条件、场景判断、方法选择和注意事项，不考客户名、项目名、工单编号或现场记忆。
3. 可以有帮助用户快速掌握结论的直接理解题，不为增加难度刻意使用绕口表述或陷阱。
4. 场景题需要的条件必须在题干中给足，判断依据必须在文章中；不得隐含产品参数或未提供的经验规则。
5. 单选只有一个明确正确答案；多选明确所有正确项；判断题命题不能含糊或混用多个不一致条件。
6. 错误选项必须能依据文章辨别为错误，不能仅因文章没提到就认定它错误，也不能引入可能成立但无法判断的选项。
7. 不把文章中的「可能」「通常」「满足某条件时」改成「必然」「所有情况」。
8. 同批题目避免重复考同一句话；每题关联具体知识点，解析说明为什么正确，必要时说明典型错误原因。
9. 涉及安全的题目必须保留安全前提，不能把危险操作当作可尝试的备选建议。
10. 支撑不了请求数量时少生成并说明原因；一题也无法可靠生成时提示依据不足，保留文章，不生成空题或编造题目。

### 8.3 题目字段与统一格式

| 字段 | 要求 |
|---|---|
| 题目编号 | 系统生成，与工单编号无关 |
| 关联文章及版本 | 必填，后端绑定，不能仅关联可变文章主记录 |
| 关联知识点 | 必填，引用该文章版本中的一个或多个稳定知识点标识 |
| 题型 | `single_choice`、`multiple_choice`、`true_false` |
| 题干 | 必填，完整、脱敏且条件明确 |
| 选项 | 必填，稳定key、文本和排序；判断题使用固定选项 |
| 正确答案 | 必填，统一存为选项key数组 |
| 解析 | 必填，解释文章中的判断依据，不只重复答案 |
| 文章依据摘录 | 必填，摘自所绑定的已确认文章版本，不是原始工单摘录 |
| 难度/标签 | 难度必填，标签可选 |
| 审核状态 | 草稿、待审核、已审核、已驳回 |
| 使用状态 | 启用/停用，与审核状态分开 |

选项示例：`[{"key":"A","text":"选项内容","sort":1},{"key":"B","text":"选项内容","sort":2}]`。单选答案如 `["A"]`，多选如 `["A","C"]`；判断题固定使用 `T`/`F` 对应正确/错误，答案仍为数组。

### 8.4 后端校验与编辑

- 单选和多选均为2～6个选项；选项key与规范化文本不得重复，文本不能为空，答案key必须存在。
- 单选只能有一个正确key；多选至少两个正确key，只有一个正确答案时应改为单选；判断题固定两个选项且只有一个正确key。
- 知识点必须属于绑定的文章版本，依据摘录必须能在该版本正文中找到；校验失败不能提交审核。
- AI结果逐题校验，合法题目保存为草稿；不合法题目不写入题库，返回具体原因和成功数量，不能把部分失败伪装成全部成功。
- 所有生成题目默认草稿且停用；AI生成或保存操作都不会自动审核通过。
- 支持逐题编辑、删除未审核草稿、单题重新生成、批量保存和批量提交审核；重新生成先产生候选结果，替换前提示人工修改。
- 整批重新生成不覆盖已保存或已审核题目，新增草稿并提示可能重复；不做复杂全库语义去重。
- 人工编辑与AI生成使用相同的结构、依据和脱敏校验，不能以人工录入为由绕过质量要求。
- 本期不增加独立的人工新建题目入口；管理人员可以充分编辑AI生成题目，但不能脱离文章自由出题。

生成开始时固定文章版本；结果返回时若当前版本已切换或文章已停用，保留成功结果为不可用草稿并提示重新核验，不能自动绑定到新版本。

## 9. 题库管理与人工审核

### 9.1 列表和详情

- 列表展示编号、题干摘要、题型、文章标题/版本、关联知识点、难度、审核状态、启用状态、创建人和更新时间。
- 支持按关键词、文章、分类/标签、题型、难度、审核状态、启用状态、是否需要版本复核和时间筛选。
- 详情展示文章及题目、选项、答案、解析、文章依据、生成批次、审核记录和修改记录。
- 原始材料不默认出现在题目详情；确需追溯时通过独立权限读取内部来源信息。

### 9.2 审核流程

```text
草稿 → 提交审核 → 待审核 → 已审核
                         ↓
                       已驳回 → 修改 → 草稿 → 重新提交审核
```

- 提交审核时执行完整后端校验，校验文章仍启用且题目绑定当前已确认版本。
- 仅有审核权限的人员可以通过或驳回；驳回必须填写原因，通过必须确认答案、依据、开卷可答性和脱敏结果。
- 不额外引入强制双人审批；同一管理人员具有相应权限时可完成生成、文章确认和题目审核，操作均留痕。
- 审核通过与启用分开：通过后可由具备启停权限的人员启用；可提供显式的「通过并启用」操作，但须同时校验两项权限。
- 审核动作携带记录修订号，后台校验其仍是待审核的同一内容，防止审核通过已经被他人改过的题目。
- 审核记录保存当时的题目内容、文章版本、依据、审核人、结果、原因和时间，不以当前可变内容代替历史记录。

### 9.3 修改、启停与可用性

- 已审核题目修改题干、题型、选项、答案、解析、文章版本、关联知识点或依据时，保存后立即回到草稿并停用，必须重新审核。
- 仅修改不影响事实和题意的分类标签或难度时可不强制重审，但必须留痕；修改的实际字段由后端判断。
- 已驳回题目修改后回到草稿，不自动重新进入待审核，需显式提交。
- 待审核题目修改关键内容时撤回到草稿，再提交；不能让审核人审核旧内容而保存新内容。
- 人工停用题目不删除审核历史。重新启用前仍需校验文章状态、当前版本、题目审核状态和内容完整性。
- 可用题目必须同时满足：文章启用、文章版本为当前已确认版本、题目已审核、题目启用。
- 已审核过的题目不允许物理删除，只能停用；未审核且无审核历史的废弃草稿可以删除并留痕。
- 同一知识点可有多道题，同一文章可分批补充题目；本期不设计这些题目在系统任务中的选择和组合规则。

## 10. 后台开卷预览

### 10.1 预览目标与边界

预览用于管理员验证文章是否短小易懂、题目是否能依据文章作答，以及脱敏后的内容是否仍然准确。不设计系统任务入口、任务卡片、接收人、完成状态或正式用户端页面。

预览内容顺序固定为：

1. 展示知识点文章全文，包括结论、适用条件和必要注意事项。
2. 阅读区之后直接展示该文章关联的问题，不把文章放到作答后的解析页才首次展示。
3. 答题时文章仍可查阅，不通过阅读计时、滚动到底或隐藏文章强制制造闭卷条件。
4. 模拟提交后展示对错、正确答案、解析及文章中的对应依据。

### 10.2 预览规则

- 内容审核预览允许管理员选择草稿题或已审核题，并显著标记「后台预览/未审核」等状态；不代表内容已可用。
- 可用内容预览仅使用当前启用文章版本及其已审核、启用的题目；无可用题目时提示继续出题或审核，不假造题目。
- 两种预览都使用不含原工单、材料身份或内部审核字段的阅读投影，内部审核面板另行展示。
- 不在模拟提交前展示独立答案字段或解析；管理员在专门的编辑/审核界面查看答案不受此预览规则限制。
- 模拟判题只记对错、不设置分值：多选答案集合完全一致才正确，漏选、错选均错误；空答案或非法key直接提示输入无效。
- 预览提交可复用后端判题逻辑，但不落真实用户作答表，不计算学习人数、完成率或积分。
- 答错不阻止继续查阅和尝试；本期不通过预览确定未来正式作答次数和任务完成规则。

## 11. 数据模型与关联建议

以下为职责建议，实际表名和字段遵循现有项目规范。使用独立学习内容命名空间，避免与现有归档知识、公开问题榜和高价值问题实体混淆。

| 实体 | 主要字段/职责 |
|---|---|
| 知识点文章 `LearningArticle` | `id`、独立编号、分类/标签、`active_version_id`、`enabled`、创建/修改人及时间 |
| 文章版本 `LearningArticleVersion` | `id`、`article_id`、版本号、草稿/已确认状态、标题、结构化正文及知识点标识、内部依据映射、待核验事项、`revision`、确认人/时间 |
| 版本来源 `LearningArticleSource` | `id`、`article_version_id`、来源类型、可空的原始来源ID、内部材料标记、来源版本/读取时间、实际使用的脱敏材料快照、受限定位信息 |
| 题目 `LearningQuestion` | `id`、编号、`article_id`、`article_version_id`、知识点标识、题干/题型/选项/答案/解析/文章摘录、难度/标签、审核状态、启用状态、`revision`、生成请求标识及创建/修改信息 |
| 题目审核记录 `LearningQuestionReview` | 题目ID、被审核修订号、当时内容快照、文章版本、审核结果、原因、审核人和时间；历史记录不可覆盖 |
| 生成请求/操作记录 | 优先复用现有能力；不能满足时增加轻量记录，包含请求ID、操作人、操作类型、目标草稿/文章版本、输入修订号、状态、脱敏错误摘要和生成结果定位 |

### 11.1 关联与约束

```text
知识点文章 1 ── N 文章版本
文章版本   1 ── N 版本来源（同一原始来源可被不同文章版本引用）
文章版本   1 ── N 关联题目
关联题目   1 ── N 题目审核记录
```

- 对文章ID与版本号建立唯一约束；事务或等效约束保证同一文章至多一个可编辑草稿。
- 已确认版本及其来源快照不可变，实际正文必须可还原，不能仅保存原文章指针或更新时间。
- `active_version_id` 必须属于该文章；题目中的文章ID和版本ID必须一致，知识点标识必须属于该版本。
- 其他技术材料没有原始工单ID时允许为空，以来源类型、材料说明和脱敏快照追溯，不伪造工单关联。
- 确认新版本、切换当前版本、退回旧题和记录审计在同一事务内完成。
- 草稿保存、文章确认和题目审核使用修订号/乐观锁；过期请求返回冲突，不覆盖他人修改。
- 生成请求ID建立幂等约束；同一成功批次的题目结果项有稳定标识，重试不能重复插入已保存题目。
- 内部来源、审核人和模型运行信息由后端按权限读取；不能将所有实体直接序列化成阅读内容。

本期不新增系统任务关联表、任务题目快照表、用户作答表或任务状态字段。文章版本的不可变设计是内容管理所需，不代表提前确定任务接入方案。

## 12. 后端服务与AI接入

### 12.1 后端能力边界

| 能力 | 后端职责 |
|---|---|
| 查询来源与准备材料 | 校验原有来源权限、工单状态、材料数量/长度，脱敏并生成内部标记 |
| 生成文章 | 使用脱敏材料调用AI，校验结构、依据和风险，保存草稿或待替换候选 |
| 保存/确认文章 | 执行并发、来源资格、事实依据、脱敏及版本校验，维护不可变版本 |
| 生成题目 | 固定文章版本，校验模型结果，按合法项保存草稿并反馈部分失败 |
| 编辑/审核/启停题目 | 校验内容、依据、权限与修订号，维护审核和使用状态 |
| 管理列表与历史 | 查询文章、版本、题目、审核和操作记录，按权限隔离来源数据 |
| 开卷预览 | 组装阅读内容白名单投影，提供无真实学习记录的模拟判题 |

接口放在独立的后台学习内容命名空间，具体路由沿用项目API规范；不复用公开知识榜接口发布学习文章，也不增加正式用户提交答案或系统任务接口。

### 12.2 AI调用与提示约束

- 检查并优先复用现有AI封装、模型配置和超时重试能力；前端不能直接调用模型，密钥和系统提示词不进入前端。
- 文章生成角色为「可复用知识点提炼助手」：只整理已提供的脱敏材料，抽取共同知识，说明条件差异，不自由诊断现场问题。
- 工单、技术资料、人工粘贴内容中的指令都作为材料文本处理，不允许覆盖系统规则或诱导输出原始身份。
- 文章生成的结构化结果区分正文内容、知识点依据和内部待核验事项；后端逐项校验，不只判断JSON是否可解析。
- 题目生成角色为「开卷理解题出题助手」：只接收文章已确认版本及其知识点，不接收原始来源或未确认的新草稿。
- 题目结构化结果包含题型、题干、选项、答案数组、解析、知识点标识、文章摘录、难度和标签；少生成时附原因。
- 结构合法不代表知识正确，文章确认和题目审核都必须由人工完成；AI不得自动将内容置为确认或已审核。

### 12.3 运行状态与失败恢复

- 前端展示生成中状态；后端用请求ID防止重复调用和重复落库，不能只依靠禁用按钮。
- 生成请求有可查询的运行结果，刷新页面后可恢复查看；优先复用已有作业机制，不要求额外建设大型队列平台。
- 调用模型前准备并保存必要的脱敏输入快照，不在长数据库事务中等待模型返回。
- 模型返回后再次核对草稿修订号或文章版本；编辑已变化时保存候选并提示冲突，不自动覆盖人工修改。
- 失败保留已有来源、草稿和已成功保存的题目，提供重试入口；错误中不展示原始材料或服务凭据。
- 模型结果不足、部分题目不合法、来源冲突、附件未解析、脱敏存疑等均明确展示，不静默忽略。

## 13. 权限与操作留痕

| 权限 | 允许的操作 |
|---|---|
| 查看知识点/题库 | 查看相应管理列表和已授权的内容详情 |
| 选择与追溯来源 | 在原有来源权限范围内读取材料摘要和定位原始材料，不自动获得全部工单权限 |
| 生成/编辑文章 | 准备材料、生成、保存和编辑文章草稿 |
| 确认文章 | 核验知识与脱敏结果，确认新版本 |
| 管理文章启停 | 停用或重新启用文章 |
| 生成/编辑题目 | 基于已确认文章出题，修改题干、选项、答案和解析 |
| 审核题目 | 通过或驳回当前待审核修订 |
| 管理题目启停 | 在满足可用条件时启用题目或主动停用 |
| 后台开卷预览 | 预览被授权的文章和题目，不因此获得原始来源或审核答案管理权限 |

权限接入现有角色、菜单和后端校验体系，不新建一套账号体系。编辑、审核接口可按权限返回答案；仅预览权限通过阅读投影和模拟反馈获取内容，不能直接访问答案管理接口。

操作留痕至少覆盖：准备/替换来源、生成与重新生成、保存草稿、文章确认与版本切换、题目编辑与提交审核、审核通过/驳回、启用/停用和删除废弃草稿。复用已有操作日志，保留操作人和目标修订，但不把原始敏感材料写进日志。

## 14. 异常与边界处理

| 场景 | 处理规则 |
|---|---|
| 选择未关闭工单 | 后端拒绝纳入，明确允许的三个状态 |
| 归档中但没有已审核报告 | 可以使用其他有依据且有权读取的材料，不将待审报告视为可靠结论 |
| 没有工单、只有有效技术材料 | 允许生成，不要求虚构工单ID |
| 多工单描述相似但结论冲突 | 提示条件差异或要求拆分，不擅自选一个作为通用答案 |
| 材料不足或仅有猜测 | 允许保存草稿；无可靠知识依据时阻止确认和出题 |
| 脱敏会丢失必要技术条件 | 要求重写或更换材料，不能输出错误的泛化结论 |
| 人工修改重新带入身份或私有链接 | 再次脱敏检查，未解决前阻止确认/审核 |
| 来源重开、权限失效或材料变化 | 确认前重新校验；已确认内容保留原快照并提示复核，不自动改写 |
| AI失败、无效结构或部分题目失败 | 保留已成功内容，反馈明细，重试不重复写入 |
| 生成返回时草稿已被修改 | 保存候选，提示修订冲突，不覆盖人工修改 |
| 文章确认新版本 | 旧版题目退回草稿并停用，需重新关联依据和审核 |
| 文章/题目停用 | 不提供可用内容；历史版本和审核记录保留 |
| 越权读取原工单或内部追溯 | 后端拒绝，不通过预览接口或页面隐藏绕过 |

## 15. 验收标准

### 15.1 来源、文章与安全

- [ ] `closed`、`archiving`、`archived` 工单均可选择，未关闭工单不能绕过后端校验。
- [ ] 可选择多个相似工单共同生成一篇知识点文章，也可仅使用有效的非工单材料。
- [ ] 不把匿名审核限制或未确认猜测绕过为可公开知识。
- [ ] 材料发送给模型前已脱敏，文章、题干、选项、解析及预览均无来源身份和私有链接。
- [ ] 知识点短小、聚焦主题、可复用，包含必要条件，不强制生成完整案例报告。
- [ ] 每个核心知识点有内部依据，关键待核验事项未解决时不能确认。
- [ ] 草稿可保存、退出、恢复；重新生成不会无提示覆盖人工修改。
- [ ] 已确认版本不可变，新版本确认及旧题退回在同一事务内完成，历史正文可还原。
- [ ] 不修改原工单、沉淀文章、贡献计分、财务审核或奖励数据。

### 15.2 题目、审核与开卷预览

- [ ] 只能基于当前启用文章的已确认版本出题，不能把未确认草稿或原始工单作为隐藏依据。
- [ ] 支持单选、多选、判断，题目答案、知识点和文章摘录均可校验。
- [ ] 数量不足时明确说明，不为满足数量编造事实或重复问题。
- [ ] 生成和人工编辑都执行结构、脱敏及依据校验，保存不会自动审核通过。
- [ ] 关键编辑后题目回到草稿并停用；审核需校验状态、权限及修订号，驳回必须有原因。
- [ ] 文章停用、版本更新、题目待审或停用时不能被视为可用内容。
- [ ] 预览先展示知识点文章，再展示问题，答题时可继续查阅文章，模拟提交后再展示答案解析。
- [ ] 多选按答案集合完全一致判对；非法答案被拒绝，模拟作答不写入真实学习数据。
- [ ] 预览和内部管理字段分离，非来源授权人员不能访问原始工单或材料。
- [ ] AI失败、重复请求、并发修改、生成期间版本切换均有明确处理，已保存内容不丢失。
- [ ] 本期未夹带系统任务改造、正式用户端页面、任务分发或作答记录开发。
