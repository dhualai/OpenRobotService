# 兜底双工单方案（项目不在项目集时）

> 2026-08-03 · 状态：已评审通过，实现中
> 需求来源：2026-08-02 会议纪要
> 涉及：前端 ChatPanel 确认页 + ProjectSelect + UserSelect + AI 侧 confirm_submit + 后端 create_ticket/assign（张文星改）

## 一、背景

用户提单时，AI 可能匹配不到项目（项目不在系统项目集），或用户不在该项目中。现有兜底是把工单派到"摇人吧服务号提单"项目，但后续用户无法绑定正确项目，且缺乏统一处理机制。

## 二、方案：双工单

用户在确认页勾选 checkbox「我的项目不在所属项目集中，向项目负责人发送申请工单」→ 触发双工单：

| | 工单1（正常工单） | 工单2（申请单） |
|---|---|---|
| 创建路径 | `confirm_submit`（AI 侧现有） | `POST /api/tasks/`（系统任务创建） |
| project | 摇人吧服务号提单 | 摇人吧服务号提单 |
| project_id | 空（兜底项目无 id） | 空 |
| assigned_to | 空（AI 派单 Worker 自动派） | **项目负责人**（前端传 assigned_to） |
| 派单方式 | AI 派单 Worker | 不派单（创建即指派） |
| 内容 | AI 草稿（用户编辑确认） | 固定模板 |
| 概览气泡 | ✅ 插入对话区（派单中→轮询） | ✅ 插入对话区（派单中→轮询） |
| 写入表 | tasks | tasks（同表，历史工单可查） |

工单2 固定模板：
- 标题：`【项目申请】请求新建项目/添加用户`
- 描述：`用户「{提单人}」提单时项目「{期望项目名}」不在系统项目集中，请处理：1）新建项目；2）将用户加入对应项目。`
- type=`support`、priority=`中`

## 三、触发逻辑

- checkbox **默认不勾**（正常流程：项目在项目集，单工单）
- 用户主动勾选 → 显示提示 + 项目负责人下拉（UserSelect，全量用户）→ 提交时生成双工单
- 提示文字：勾选后展示「项目不在项目集中，将默认提单至摇人吧服务号提单项目，同时向项目负责人发送申请工单」

## 四、前端改动（张俊磊侧）

1. **ProjectSelect 数据源改全量**：`getMyProjects` → `getProjects`（`GET /api/admin/projects/`）
2. **UserSelect 通用化**：去 console.log、placeholder/title 可配（已是 props）、加 nameHint 回显（value 是 user.id，联系人场景存 username/name 时按 nameHint 匹配预选）
3. **新增 `createTicket` 封装**（`api/ticket.ts`）：`POST /api/tasks/`，入参按 TicketCreate schema
4. **确认页加 checkbox + 提示 + 项目负责人下拉**
5. **`handleConfirmTicket` 双工单分支**：
   - 工单1：`confirm_submit`，overrides 强制 `project="摇人吧服务号提单"`、`project_id=""`
   - 工单2：`createTicket`（POST /api/tasks/），`assigned_to=项目负责人username`、`project_name="摇人吧服务号提单"`、固定模板内容
6. **两个工单都插概览气泡 + 轮询**：工单1 用 confirm_submit 返回的 db_id，工单2 用 createTicket 返回的 id

## 五、后端改动（张文星侧）

1. **`create_ticket`（`ticket_service.py:80`）**：`assigned_to=created_by` → `assigned_to=ticket_data.assigned_to or created_by`（尊重前端传入的处理人）
2. **`PATCH /{task_id}/assign`（`task.py:622`）**：去掉 `if not is_admin: raise 403` 限制（处理人不应写死 admin 权限）
3. **（建议）`create_ticket` 传了 `assigned_to` 时 `status=IN_PROGRESS`**（已派单），否则保持 NEW

## 六、字段/接口对齐

- 项目负责人下拉数据源：`GET /api/tasks/assignable-users`（仅需登录，字段最小化 id/username/name/status）
- 项目下拉数据源：`GET /api/admin/projects/`（全量）
- 工单2 创建：`POST /api/tasks/`（TicketCreate schema）
- 文案统一：`摇人吧服务号提单`（与 pipeline `pipeline.py:1237/1271/1272` 兜底一致）

## 七、已确认的关键点

1. ✅ `Ticket = Task`（`modules/tasks/models/ticket.py:20`），AI 转单与系统任务创建写同一张 tasks 表，历史工单可查
2. ✅ `_check_required_fields`（`pipeline.py:150`）：project_id 和 project 二者有一个非空即可，兜底"摇人吧服务号提单"（project_id 空）能通过校验
3. ✅ 派单 Worker `_assign_one` 不读 contact，改 contact/项目负责人不影响派单
4. ✅ 系统任务创建用 `customer` 字段，AI 转单用 `metadata_info.contact`，两字段独立

## 八、验证步骤

1. 项目在项目集（正常）：不勾 checkbox → 单工单（confirm_submit）→ 一个概览气泡
2. 项目不在项目集：勾 checkbox + 选项目负责人 → 双工单 → 两个概览气泡
3. 历史工单列表：双工单场景能看到两条工单
4. 工单2 接单人 = 项目负责人（后端改后验证）
5. 两个气泡轮询：派单完成后都更新为"已派单 · 处理人"
