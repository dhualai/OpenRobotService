- `handleConfirmTicket`（ChatPanel.tsx:1170）成功后：关弹窗 + `refreshTasks()` + Toast「工单已生成」。对话区**无任何工单反馈**——用户看不到刚提的工单长什么样、派单进度如何。

- 派单中动效 `.dispatch-pulse` + `.task-card2__person-name--dispatching` 已存在于 global.css（HistoryTickets/TicketDetailPage 复用）。
- 派单状态查询：`GET /api/tasks/{db_id}` 返回 `assigned_to` + `assigned_to_name`（TicketDetailPage 已用）。

## 二、设计

### 2.1 触发时机
`handleConfirmTicket` 成功（`res.code === 0`）后：
1. 关闭弹窗（现有）
2. **构造工单概览气泡** → `setMessages` 插入对话流末尾（assistant 角色）
3. `appendMessage` 持久化（`messageType='ticket_overview'`，content 存工单 JSON）
4. `refreshTasks()`（现有）
5. Toast 保留（简短成功提示，气泡为主反馈）
6. **启动派单轮询**

### 2.2 气泡数据结构

`Message` 接口新增：
```ts
subtype?: 'solution_draft' | 'ticket_overview';
ticket_overview?: {
  db_id: number;        // tasks.id，轮询查派单状态用
  ticket_id: string;    // AI-ticket-id 展示
  title: string;
  type?: string;        // problem|bug|...
  priority?: string;    // 紧急|高|中|低
  project?: string;     // 项目名称
  contact?: string;
  description?: string; // 摘要展示（截断）
  created_at?: string;
}
```

### 2.3 气泡 UI（结构化工单卡片）

```
┌─────────────────────────────────┐
│ 🎫 工单 #42    [报障] [高]      │  ← 头部：图标+单号+类型/优先级 Tag
│ XSC151 无法启动                  │  ← 标题（加粗）
│ 📁 南京本川项目                  │  ← 所属项目
│ XSC151 上电后无反应，已排查…     │  ← 描述摘要（2 行截断）
│ ─────────────────────────────   │
│ 🔵 派单中…        10:32         │  ← 状态行：派单中动效 / 已派单
└─────────────────────────────────┘
```

- **派单中**：`.dispatch-pulse` 呼吸点 + 「派单中…」蓝字（复用现有动效）
- **已派单**：`已派单 · 张三`（绿色或对勾图标）
- **点击整卡**：跳转 `/app/call/ticket/{session_id}` 工单详情页

### 2.4 派单状态轮询

- 插入气泡后启动 `setInterval` 每 **5s** 查 `GET /api/tasks/{db_id}`（`createRequest(TASKS.BASE_URL)`）
- 查到 `assigned_to` 非空 → 更新气泡状态为「已派单 · {assigned_to_name}」，**停止轮询**
- **超时 3 分钟**未派单 → 停止轮询（保持「派单中…」静态显示，不再请求）
- **切会话 / 组件卸载** → 清理 interval（防泄漏）
- 同一会话多次确认（多个工单气泡）→ 各自独立轮询

实现方式：`useEffect` 监听 `messages` 中 `subtype==='ticket_overview'` 且未派单的气泡，集中管理轮询（一个 interval 轮询所有派单中气泡，比每个气泡一个 interval 更省）。

### 2.5 持久化与恢复

**持久化**：
- `appendMessage(convId, 'assistant', JSON.stringify(ticketOverview), { messageType: 'ticket_overview' })`
- content 存工单 JSON 字符串，messageType 标记类型

**恢复**（`mapDbMessages` 扩展）：
- `message_type === 'ticket_overview'` → 解析 content JSON → 重建 `subtype: 'ticket_overview'` + `ticket_overview` 结构的气泡
- 恢复后的气泡如果是「派单中」状态（无法从 DB 消息判断，需查一次 `GET /api/tasks/{db_id}`），**恢复时查询一次**：
  - 已派单 → 直接显示「已派单 · 处理人」（静态，不轮询）
  - 未派单 → 显示「派单中…」+ 启动轮询

### 2.6 交互流

```
用户点「确认提交」
  → handleConfirmTicket → qaConfirmTicket → res.code === 0
  → 关弹窗
  → 插入工单概览气泡（派单中…）
  → appendMessage 持久化
  → refreshTasks + Toast
  → 启动轮询（5s）
      ├─ 查到 assigned_to → 气泡更新「已派单 · 张三」→ 停止
      ├─ 3min 超时 → 停止（保持派单中）
      └─ 切会话 → 停止
```

## 三、风险与对策

| 风险 | 对策 |
|---|---|
| **轮询泄漏**（切会话/卸载后 interval 还在跑） | `useEffect` cleanup `clearInterval`；interval 统一由组件级 ref 管理，切会话时清 |
| **持久化后恢复不出气泡** | `mapDbMessages` 加 `message_type==='ticket_overview'` 解析分支，JSON.parse 失败则降级为普通文本气泡 |
| **恢复后状态过期**（恢复时工单已派单） | 恢复时对每个 ticket_overview 气泡**查一次** `GET /api/tasks/{db_id}`，直接显示最新状态（已派单则不轮询） |
| **多工单轮询并发** | 组件级一个 interval 轮询所有派单中气泡，避免 N 个 interval |
| **气泡内容过长** | 描述摘要 CSS 2 行截断（`-webkit-line-clamp: 2`），详情点气泡跳转 |
| **旧会话无 ticket_overview 消息** | 向前兼容：mapDbMessages 只解析 `message_type==='ticket_overview'`，旧消息不受影响 |

## 五、评审点（已评审，结论见第八节）

## 八、评审结论（2026-08-02 定稿）

1. **气泡 UI 布局**：✅ 认可，字段加多更详实（见下）
2. **轮询超时**：60s（5s × 12 次），非 3min
3. **持久化**：✅ 存 DB（刷新/切会话后气泡还在）
4. **点击跳转**：✅ 认可（点气泡 → 工单详情页）
5. **Toast**：保留但缩短文案（气泡插入有延迟，Toast 提供即时反馈，两者互补）
6. **恢复后轮询**：查一次 + 继续轮询；**轮询用 setTimeout 递归**（非 setInterval），防泄漏——每次查完再 setTimeout 下一次，查到/超时就停，组件级 ref 存 timeout id，cleanup 时 clearTimeout

**气泡字段（详实版）**：
- 头部：🎫 工单号(db_id) + 类型 Tag + 优先级 Tag
- 标题（加粗）
- 所属项目、联系人（有则显示）
- 描述摘要（3 行截断）
- 创建时间
- 状态行：派单中（dispatch-pulse 动效）→ 已派单 · 处理人

**轮询实现（setTimeout 递归）**：
```ts
// 组件级 ref 存所有派单中气泡的 timeout id
const pollTimeoutsRef = useRef<Record<string, ReturnType<typeof setTimeout>>>({});

const pollDispatch = useCallback(async (msgId: string, dbId: number, attempt = 0) => {
  if (attempt >= 12) { delete pollTimeoutsRef.current[msgId]; return; } // 60s 超时
  try {
    const task = await tasksRequest(`/${dbId}`);
    if (task.assigned_to) {
      setMessages(prev => prev.map(m => m.id === msgId && m.ticket_overview
        ? { ...m, ticket_overview: { ...m.ticket_overview!, assigned_to_name: task.assigned_to_name || task.assigned_to } }
        : m));
      delete pollTimeoutsRef.current[msgId];
      return;
    }
  } catch { /* 单次失败继续 */ }
  pollTimeoutsRef.current[msgId] = setTimeout(() => pollDispatch(msgId, dbId, attempt + 1), 5000);
}, []);

// 卸载/切会话清理
useEffect(() => () => { Object.values(pollTimeoutsRef.current).forEach(clearTimeout); }, []);
```
