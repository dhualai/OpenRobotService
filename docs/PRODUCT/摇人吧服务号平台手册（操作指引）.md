# 摇人吧服务号平台手册 · 操作指引

> 本手册回答「摇人吧」服务号平台自身的操作问题：项目授权、角色与权限、人员账号、工单流转、菜单入口等。
> 注意区分：本手册讲的是**服务号平台**；「USP 调度系统」的配置问题请参考 USP 操作手册，两者不是同一个产品。

---

## 操作前提

「项目授权」「角色分配」「用户管理」等操作入口都在 **后台管理 → 项目管理**（PC 浏览器访问），执行这些操作需要有管理员或项目负责人权限。普通员工、甲方客户在界面上看不到这些入口，无法操作。

进入路径：微信服务号「摇人吧」底部菜单 → 📊 后台管理 → 仪表盘下方「更多功能」→ 项目管理。

---

## 对项目授权（人员授权）

「项目人员授权」决定**普通用户能在系统里看到哪些项目的数据**：没有全局查看权限的用户，只能看到自己被授权关联的项目。

操作步骤：

1. 进入 后台管理 → 项目管理 → 项目授权。
2. 先在最上方的项目选择框里搜索并选中要授权的项目。
3. 展开「项目人员授权」区域，在成员树里点「添加人员」。
4. 依次选择：要授权的人员 → 给该人员在这个项目里的角色 → 该人员的汇报上级。
5. 确认后保存。被授权的人刷新页面后，就能在工单、看板、数据列表里看到这个项目。

补充说明：

- 一次添加一个人。要给多个人授权，就重复上述步骤；也可以在 后台管理 → 更多功能 → 分配角色 里按「项目优先」模式批量授权。
- 长按成员树里的某个成员可以移除该人员在本项目的授权。
- 授权后对方看不到项目，通常是：没选对人、没保存成功、或者对方还没有登录过系统；重新登录后再检查。
- 汇报上级仅用于组织架构展示，不影响权限本身。

### 项目 licence 授权码

「项目授权」区域里还有一个「项目 licences 授权」子面板，它和人员授权是两回事：它是给 **USP 调度系统**申请软件授权码（licence）的，凭机器码申请，带有效期和最大车数限制。

操作步骤：

1. 在「项目授权」区域先选中项目。
2. 展开「项目 licences 授权」子面板，查看该项目已有的授权记录（授权码、机器码、有效期、申请人、允许最大车数）。
3. 在「申请授权码」表单里填写：机器码、开始日期、结束日期、允许最大车数。
4. 点「申请授权码」，系统自动审批后生成授权码，列表里出现新记录，可复制授权码或机器码。
5. 点某条授权记录上的「撤销」可以撤销该授权。

## 让领导/管理员看到全部项目

普通用户默认只能看到自己关联的项目。如果某个账号需要跨项目查看全部数据（比如领导），不需要逐个关联项目，直接给该账号加一条权限即可：

1. 进入 后台管理 → 更多功能 → 角色管理，找到该用户拥有的角色。
2. 给角色勾选「查看全部项目数据」这条权限并保存。角色管理里权限按**名称**显示（名称是建权限项时自定义的，各环境可能不同）；如果列表里找不到，去 后台管理 → 更多功能 → 权限管理 按编码搜一下，还没有就新建一条：编码必须一字不差填 `backend:project:all`，名称随意（如「查看全部项目数据」），建完回角色管理就能勾了。
3. 该用户重新登录后，后台管理各页面（仪表盘、项目管理、数据导入、项目进度等）就会请求全部项目数据。

注意：`backend:project:all` 是数据范围开关，不是页面开关。它不会凭空多出菜单入口——用户需要先有后台管理入口权限（编码 `frontend:admin:other:show`，同样以权限管理里实际存在的为准），否则连后台管理都进不去。持有 `admin` 直通权限的账号（开发者/超级管理员）默认放行所有权限，无需单独配置。

## 给人员分配角色

系统角色分为两类：

- **系统角色**：开发者、超级管理员、用户（决定全局能力）。
- **项目角色**：按项目维度的人员身份（如项目对接人、调度研发等），挂在「用户 + 项目」绑定上。

给人员在项目里分配角色有两种入口，效果一样：

**方式一（项目优先）**：后台管理 → 更多功能 → 分配角色 → 选「按项目授权」→ 先选一个项目 → 多选用户 → 批量授权/移除角色。

**方式二（用户优先）**：分配角色 → 选「按用户授权」→ 多选用户和多选角色 → 再选多个项目 → 一次性把「用户×角色」批量授权到所有勾选的项目。

**方式三（在项目管理里逐个加）**：后台管理 → 项目管理 → 项目授权 → 项目人员授权 → 添加人员（适合单个项目内维护人员树和汇报关系）。

注意：分配角色页面里只会列出**项目角色**，系统角色要在 角色管理/用户管理 里配置。

## 新建用户账号

后台管理 → 更多功能 → 用户管理：

1. 点「新建用户」，填写用户名、密码、姓名、部门、职级、状态。
2. 职级分三档：一线、管理/审核、仅兜底。
3. 「责任模块」卡片用于智能派单匹配（模块名 + 职责关键字，如「调度USP」+「调度算法」）；「职责画像」是自由文本补充，也参与 AI 派单匹配。
4. 保存后，新用户可用账号密码登录；也可以在微信服务号里输入姓名完成注册。

## 工单流转与状态

工单有 6 种状态：**新建 → 处理中 → 已解决 → 已关闭**，旁支为**已挂起**（暂停/退回）和**已取消**（撤回）。

- 新建：等待派单；提单人可催办、撤回。
- 处理中：处理人可暂停、处理完成；提单人可上报、撤回（派错单时撤回）。
- 已挂起：处理人可继续处理（可换人）；提单人可催办、撤回（派错单时撤回）。
- 已解决：由提单人确认关闭或退回（退回会重新打开）。
- 已取消：提单人可重新打开。
- 已关闭：终态，普通用户不能再编辑，只有管理员可改。

关键规则：

- **只有提单人能把「已解决」确认为「已关闭」**，处理人不能替提单人关单。
- **撤回工单是提单人和管理员的特权**，处理人不可撤回（防止处理人替提单人撤回导致提单人看不到工单）。撤回适用于新建/已挂起/处理中三个状态——派错单或误提单时，提单人可及时撤回避免错误流转。
- 任意已登录用户都可以重新指派（换处理人），不限定管理员。
- 非管理员点「删除」其实是软删除（状态改为已关闭）；只有管理员删除才真正移除数据。
- 系统底层不强制状态按顺序流转，有权限的人可以直接改状态，这属于系统允许的行为。

## 工单可见范围

- 普通用户只能看到：自己创建的工单、指派给自己的工单、自己关联项目下的工单。
- 要看到系统里全部工单，需要 `frontend:task:all` 权限（系统任务列表里才会出现「全部」筛选）。
- 用户反馈「看不到别人的工单」，最常见的原因是：没有该项目关联，或没有 `frontend:task:all` / `backend:project:all` 权限。对应的解决方法是项目人员授权或加权限。

## 权限速查

权限项（编码+名称）存放在系统的权限管理里，**系统不会预置这些权限**——角色管理里能不能勾到，取决于权限管理里是否已建过对应编码的权限项，没有就先去 后台管理 → 更多功能 → 权限管理 新建（编码必须一字不差）。角色管理里权限按名称显示，核对或新建以编码为准。持有 `admin` 直通权限的账号默认放行所有权限。

| 编码 | 作用 |
|------|------|
| `frontend:admin:other:show` | 显示「后台管理」入口 |
| `frontend:develop` | 系统任务里显示「同步外部任务」按钮和「新建工单」按钮 |
| `frontend:task:all` | 系统任务里显示「全部」筛选（可见系统全部工单） |
| `backend:project:all` | 数据范围开关：后台各列表页请求全部项目；不持有则只看自己关联项目 |
| `backend:user:role_project:write` | 允许给用户在项目里分配/移除角色 |
| `backend:role:system` | 允许编辑其他用户的系统级角色（高危操作） |

## 常见问题

**Q：怎么给某个工程师开某个项目的权限？**
后台管理 → 项目管理 → 项目授权 → 选中项目 → 项目人员授权 → 添加人员 → 选人、选角色、保存。

**Q：怎么给领导开全部项目的查看权限？**
在角色管理里给领导的角色勾选编码为 `backend:project:all` 的权限（界面上按名称显示，找不到就先去权限管理按编码新建，见上方「权限速查」的说明），并确认其账号有后台管理入口权限。

**Q：授权做了但对方还是看不到项目？**
检查：是否选对了项目和人员；是否保存成功；对方是否重新登录。仍未解决可提单报障。

**Q：项目授权码（licence）在哪里申请？**
后台管理 → 项目管理 → 项目授权 → 项目 licences 授权，填机器码、起止日期、最大车数后申请。

**Q：为什么看不到别人的工单？**
默认只能看到自己的工单和关联项目下的工单。需要 `frontend:task:all` 权限（看全部工单）或该项目的人员关联。

**Q：工单怎么关闭？**
处理人标记「已解决」后，由提单人在工单里确认关闭；处理人不能替提单人关单。

**Q：想换人处理工单怎么办？**
工单详情里点「重新指派」，选人和填原因，任何已登录用户都可以操作。
