# 发布说明（Release Notes）

> **用途**：生产环境部署成功后，企微通知卡片「更新日志」区的内容来源
> （见 `deploy/notify.py` 的 `RELEASE_NOTES_FILE`）。
>
> **内容来源（三级，优先级从高到低）**：
> 1. **自动生成**：部署流水线在构建阶段用 `deploy/gen_release_notes.py` 截取
>    「上次成功生产发布 → 本次部署分支最后一次提交」之间已合并的 PR，经 LLM
>    合并去重、归纳成三组，成功即覆盖本文件；
> 2. **上次成功的发行说明**：自动生成成功、且本次部署成功的每次发布，都会把结果
>    滚存到 GitHub Release（tag `prod-release-notes`）。本次没生成时优先读它，
>    所以「人工版」的实际内容 = 上一次真上过线的发行说明，而不是陈年手写清单；
> 3. **下方手写条目**：只有首次发布（还没有那份 Release）或读取失败时才轮到。
>
> **维护方式**：下方「## 未发布」区只是冷启动兜底，平时不必维护——合入功能后写不写
> 都不影响通知内容。真需要手写时，在对应分组追加一条 `- 描述`。
> 注意：`dev` / `test` 都有保护规则（必须经 1 人 approve 的 PR），CI 无法回写本文件，
> 滚存一律走 Release；两者内容不一致时以 Release 为准。
>
> **写法要求**：一条一行，言简意赅（建议 ≤ 30 字），写用户可感知的变化，
> 不写内部重构细节；新功能/影响面大的写「新增功能」，交互细节打磨写「体验优化」，
> 缺陷修复写「BUG 修复」。分组名固定为这三个，顺序即展示顺序。
