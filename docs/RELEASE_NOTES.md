# 发布说明（Release Notes）

> **用途**：生产环境部署成功后，企微通知卡片「更新日志」区的内容来源
> （见 `deploy/notify.py` 的 `RELEASE_NOTES_FILE`）。
>
> **内容来源（三级，优先级从高到低）**：
> 1. **自动生成**：部署流水线在构建阶段用 `deploy/gen_release_notes.py` 截取
>    「上次成功生产发布 → 本次部署分支最后一次提交」之间已合并的 PR，补充 PR 正文与
>    改动文件后经 LLM 合并去重，按菜单模块归纳并生成逐项验证入口；
> 2. **上次成功的发行说明**：自动生成成功、且本次部署成功的每次发布，都会把结果
>    滚存到 GitHub Release（tag `prod-release-notes`）。本次没生成时优先读它，
>    所以「人工版」的实际内容 = 上一次真上过线的发行说明，而不是陈年手写清单；
> 3. **下方手写条目**：只有首次发布（还没有那份 Release）或读取失败时才轮到。
>
> **维护方式**：下方「## 未发布」区只是冷启动兜底，平时不必维护。真需要手写时，
> 在对应菜单模块追加一条 `- 【类型】描述｜验证：入口`。注意：`dev` / `test` 都有保护规则，
> CI 无法回写本文件，滚存一律走 Release；两者内容不一致时以 Release 为准。
>
> **写法要求**：一级分组使用「我要摇人 / 系统任务 / 后台管理 / 其他」；类型使用
> 【功能】/【优化】/【修复】。描述写用户可感知变化，验证写到具体菜单、页面和操作；
> 无菜单入口时写真实 API 或项目端验证方式，不得虚构菜单。历史三分类文件仍可兼容解析。
