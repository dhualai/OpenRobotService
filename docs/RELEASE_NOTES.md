# 发布说明（Release Notes）

> **用途**：生产环境部署成功后，企微通知卡片「更新日志」区的内容来源
> （见 `deploy/notify.py` 的 `RELEASE_NOTES_FILE`）。
>
> **内容来源（两条路，自动优先）**：
> 1. **自动生成**：部署流水线在构建阶段用 `deploy/gen_release_notes.py` 截取
>    **最近 7 天**已合并 PR（`mergedAt` 落在 `now-7d` 内），经 LLM 合并去重、
>    归纳成三组，成功即覆盖本文件；
> 2. **人工兜底**：未配置 `RELEASE_LLM_API_KEY` / 窗口内无 PR / LLM 调用失败 /
>    产出为空时，沿用下方「## 未发布」区的手写条目。
>
> **维护方式**：功能/修复合入后，在下方「## 未发布」区的对应分组里追加一条 `- 描述`，
> 每人只追加自己负责的条目；生产发布时 CI 读取「未发布」区渲染进通知。
> 条目累计到下次生产发布即视为已随版本发出。
> 注意：自动生成成功时会整体覆盖本文件的「## 未发布」区，手工条目不会与自动结果混排。
>
> **写法要求**：一条一行，言简意赅（建议 ≤ 30 字），写用户可感知的变化，
> 不写内部重构细节；新功能/影响面大的写「新增功能」，交互细节打磨写「体验优化」，
> 缺陷修复写「BUG 修复」。分组名固定为这三个，顺序即展示顺序。
