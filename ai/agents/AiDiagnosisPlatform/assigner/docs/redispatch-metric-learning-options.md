# 重新派单进指标 / 学习：两种方案说明

状态：已拍板采用 **方案 A**（2026-09-28）  
范围：开发者模式漏斗指标 + 派单学习；不改建簇、不改转弹窗三种类型。  
关联前提（已共识）：

- 处理人转派必选「派错了 / 阶段转派 / 其它」→ 用户已打标，「派错了」进错派分子。
- 重新派单默认可视为对当前派单不满意，不必每条都靠开发者点「算不准确」。
- **倾向人×2**（连续两次同一倾向人直派）是「确认就派这个人」，**不算剔除分母，也不应算作「AI 又错了」**。
- 必须保留 **「测试不算」** 标签，用于压测 / 演示 / 误点，从指标与学习中剔除。

---

## 背景：现在三条通道

| 通道 | 现状 | 问题 |
|------|------|------|
| 转派弹窗 kind | 强制选类型；`misassign` 进指标+学习 | 已较干净 |
| 重新派单 redispatch | 默认 pending，开发者模式审「算不准确 / 测试不算」后才进率与学习 | 生产依赖人工审核，积压则率偏低 |
| 倾向人×2 | 落库像直派（`matched_pref` + `_step0_winner_profile`），漏斗「仅曝光」 | 若「重派一律不准确」，会和「仅曝光」打架 |

漏斗侧已定：从未 AI → Step0 扣除；倾向人×2 **仅曝光、不扣分母**。  
下文两种方案回答的是：**重派如何进「不准确」分子，以及如何进学习**。

---

## 方案 A：首次（或非连续同倾向）重派算不准确

### 核心规则

对一张单上的重新派单序列：

1. **算不准确（进指标 + 默认可学习）**  
   - 该单上的**第一次**重新派单；或  
   - 本次倾向人 ≠ 上一轮派单/上一轮重派倾向人（非「连续同倾向」）。

2. **不算不准确（不进不准确分子，不学习）**  
   - 判定为 **倾向人×2** 的那一轮（连续两次同一 `preferred_id` 并走直派）；  
   - 或显式标了 **测试不算**。

3. **倾向人×2 在漏斗**  
   - 继续仅曝光张数/次数；不扣 AI 池分母；不进重派不准确分子。

### 指标怎么算

| 分子 | 口径 |
|------|------|
| 弹窗派错了 | 不变（kind=misassign） |
| 重派不准确 | 满足规则 1 且非测试不算、非倾向人×2 的重派 |
| 并集 | 上两者按单去重 / 按次可加 |

首派错派率（若后续做）：只看首派之后是否出现「派错了」或「方案 A 下的重派不准确」。

### 学习怎么算

- 仅对「算不准确」的重派抽纠错对：压**上一任 AI 派人**（×0.7），倾向人作 to（可空）。  
- 倾向人×2、测试不算：不写学习样本。

### 优点

- 语义干净：「第一次不满意」才算错；第二次同人确认不算错。  
- 与漏斗「倾向人×2 仅曝光」一致，不会出现「曝光又不算错、却进了不准确率」。  
- 实现上可落在「重派序号 + preferred 是否与上轮相同 + 本轮是否 preferred_twice 直派」。

### 缺点 / 风险

- 「第一次重派」若其实是换人排查、不是嫌 AI，仍会算不准确（可用测试不算兜）。  
- 非连续同倾向的第二次重派（先派甲、再改乙）仍算不准确——一般合理，但要在文案里写清。  
- 需要稳定识别「第几次重派」和「是否连续同倾向」（依赖 `task_dispatch_log` / 操作日志顺序）。

### 适用

希望 **指标分子尽量等于「真对算法不满」**，接受实现上多一层「第几次 / 是否同倾向」判断。

---

## 方案 B：重派都进「重派率」，学习与错派分子拆开；倾向人×2 单独标

### 核心规则

拆成**两层计数**，不要用一个「不准确」包打天下：

1. **重派率（行为率，宽）**  
   - 凡重新派单且非「测试不算」都计入（**含倾向人×2**）。  
   - 回答：「有多少单/次发生了重派」。  
   - **不直接等于错派率**。

2. **重派不准确 / 错派并集（质量率，窄）**  
   - 默认：非测试不算的重派进不准确；  
   - **倾向人×2 单独标签**：计入「倾向人×2 重派」曝光，**不计入**不准确分子，也**不扣** AI 池。  
   - 与弹窗「派错了」组成并集错派。

3. **学习**  
   - 只对「进不准确分子」的重派（及弹窗派错了）学习，压上一任 AI 派人。  
   - 倾向人×2、测试不算：不学。  
   - （可选增强）学习样本带 `source=redispatch|misassign|preferred_twice_excluded`，便于观测闭环。

### 指标怎么算

| 名称 | 分母 | 分子 | 用途 |
|------|------|------|------|
| 重派率 | AI 池张数或 AI 次 | 有重派的单 / 重派次数（含×2，剔测试） | 体验/不满强度 |
| 重派不准确率 | 同上 | 重派且非×2、非测试 | 质量 |
| 倾向人×2 占比 | AI 池或重派次数 | ×2 张/次 | 确认直派有多少 |
| 并集错派率 | AI 池 | 派错了 ∪ 重派不准确（不含×2） | 主质量指标 |

### 优点

- 「重派」和「算法错」分开说话，汇报时不易把确认直派说成错派。  
- 学习边界清晰：只学质量负反馈，不学确认行为。  
- 漏斗上可以同时挂：重派率（宽）+ 不准确率（窄）+ ×2 曝光。

### 缺点 / 风险

- 多一个「重派率」指标，页面与对外口径要解释「重派率 ≠ 错派率」。  
- 若产品口头仍说「重派就不准确」，会和方案 B 的宽口径混淆——必须以文档/UI 文案区分。  
- 实现上多一套聚合字段，但识别 ×2 / 测试不算与方案 A 相同。

### 适用

希望 **行为量（重派有多频）和质量（算不算错）都能看**，并明确学习只跟质量走。

## 对照表

| 维度 | 方案 A | 方案 B |
|------|--------|--------|
| 普通首次重派 | 进不准确 + 可学习 | 进重派率 + 进不准确 + 可学习 |
| 倾向人×2 | 不进不准确、不学习；漏斗仅曝光 | 进「重派率」、**不进**不准确；漏斗仅曝光；不学习 |
| 测试不算 | 指标剔除、不学习 | 同左 |
| 是否多一个「重派率」 | 可不单列（不准确≈过滤后的重派） | **建议单列**宽口径重派率 |
| 与「仅曝光」一致性 | 高 | 高（不准确层一致；宽重派率含×2） |
| 实现复杂度 | 中（次序 + 同倾向） | 中低（×2 标记 + 双计数） |
| 对外一句话 | 「过滤确认直派后的重派不满率」 | 「重派有多频」+「其中算算法错的有多少」 |

共同点（两种都要做）：

- 转派「派错了」口径不变。  
- 倾向人×2 **不从 AI 池扣除**，**不进不准确分子**，**不进学习**。  
- **测试不算** 永久保留为剔除口（指标 + 学习）。  
- 开发者模式审核区可转为：默认自动进不准确（按所选方案），人工主责打「测试不算」/抽检。

---

## 和后续指标的衔接（两种方案都兼容）

1. **首派错派率**：首派后是否出现「派错了」或「方案下的重派不准确」（不含×2、不含测试不算）。  
2. **覆盖**：新建 / AI 覆盖 / 智能派单覆盖 / 静默正确——与重派方案正交。  
3. **学习闭环观测**：只统计「可学习样本」周增量；评价「学过后同类单是否少再派到被压的人」时，样本定义与上表「可学习」一致。

---

## 建议怎么选

- 若开发者模式以 **一个错派并集率** 为主、页面要简单 → 偏 **方案 A**。  
- 若同时要回答「现场重派多不多」和「算法错不多」→ 偏 **方案 B**（多一行重派率，成本小、语义更全）。

折中（若以后要合成一版落地）：

- 指标展示用 **方案 B 的两行**（重派率 + 重派不准确率）；  
- 「不准确」的判定规则用 **方案 A**（首次或非连续同倾向才算不准确；×2 永不算不准确）；  
- 学习只跟「不准确」；测试不算双剔。

---

## 落地时涉及面（选定后）

1. 写入：重派日志带齐 `channel=redispatch`；测试不算写 `redispatch_verdict=skipped`（或等价）；倾向人×2 轮次与 dispatch 日志可关联。  
2. 统计：`reassign_stats` / 漏斗分子按选定方案过滤。  
3. 学习：`correction_pair` 与 worker 纠错索引与「不准确」对齐，排除 ×2 与测试不算。  
4. 前端：漏斗文案 + 审核区改为「测试剔除为主」；若选 B，增加「重派率」一行。  
5. 不改：建簇、转派三种类型弹窗、正式对话 VLM。
