# 派单模块「产品→界面→功能」三层责任树 — 设计方案

> 目标：让**工程师画像**能准确和**用户看到的界面/功能**连接起来。
> 以「产品→界面→功能」三层树为**唯一主数据**，`module_classify` / `module_keywords` / `module_anchor_texts` 自动从树生成，不再手工维护。

---

## 一、为什么用「产品→界面→功能」

- **用户视角**：用户在系统里**某界面下用某功能**时出问题 → 报障说"任务管理里下发任务失败"。
- **工程师视角**：工程师负责**某个界面/功能**的研发，他维护时直接选"我负责哪个界面下的哪个功能"。
- 之前用「前端/后端/算法」这种**技术层**切法，工程师和用户对不上，导致误归因（如"任务模拟器"被归到"项目管理"）。

---

## 二、数据模型（单棵树，自描述）

```yaml
module_tree:
  # ===== 产品：调度USP =====
  usp调度:
    name: 调度USP
    interfaces:
      # ---- 界面：任务管理 ----
      - key: task
        name: 任务管理
        description: 任务创建、下发、模板、执行监控等
        default_engineer: <default_engineer_id?>   # 可选：该界面默认负责人
        functions:
          - key: task_dispatch
            name: 任务下发
            keywords: [任务下发, 任务分配, 任务执行, 派工]
            anchor: 任务下发与分配、任务执行、派工、任务连续下发
            engineers: [ <engineer_id_A>, <engineer_id_B> ]
          - key: task_template
            name: 任务模板
            keywords: [任务模版, 任务模板, 模板创建]
            anchor: 任务模板创建与复用、任务模板异常
            engineers: [ <engineer_id_C> ]
          - key: task_simulator
            name: 任务模拟器/仿真
            keywords: [模拟器, 仿真, 任务模拟器]
            anchor: 任务模拟器下发、仿真模拟、机器人适配
            engineers: [ <engineer_id_D> ]
      # ---- 界面：地图 ----
      - key: map
        name: 地图管理
        functions:
          - ...
```

### 每个「功能」叶子节点字段

| 字段 | 说明 | 用途 |
|------|------|------|
| `key` | 功能唯一标识 | 程序内部引用 |
| `name` | 功能名（用户可读） | 前端展示 |
| `keywords` | 关键词列表 | 生成 `module_keywords`（L3 子串） |
| `anchor` | 语义锚文本 | 生成 `module_anchor_texts`（L2 Embedding） |
| `engineers` | 负责工程师 id 列表 | 生成 EngineerProfile 的责任模块 |

### 自动生成映射（已落地，2026-08-20）

- `module_classify[产品][功能name] = 功能name`
- `module_keywords[产品-功能name] = [该功能 keywords]`
- `module_anchor_texts[产品-功能name] = 该功能 anchor`（每功能一条）

> 语义演进：历史版本 `module_classify` 是「细分模块→类别」（技术层：前端/后端/算法），
> 现已改为「产品→界面→功能」三层树驱动。工程师画像 `users.responsibility_modules`
> 同步升级为**三层结构** `{产品: {界面name: [功能name]}}`，由
> `sync_to_user_profiles` 从树的功能节点 `engineers` 字段聚合生成。
> 派单端以**功能 name** 为召回/收紧粒度。

## 三、USP 界面层草案（待你确认/补充）

基于本地 USP 架构文档 + 用户界面视角，初步梳理：

| 界面 | 该界面下的功能（示例） |
|------|------------------------|
| **首页/概览** | 平台状态、数据概览 |
| **任务管理** | 任务下发、任务模板、任务模拟器/仿真、任务逻辑、任务回调/执行 |
| **地图管理** | 地图编辑、地图导入导出、地图拓扑/连通性、AI地图 |
| **库位管理** | 库位管理、库区管理、载具类型管理 |
| **设备/外设管理** | 门、电梯、输送线、交通灯、呼叫器 |
| **机器人监控/管理** | 机器人状态监控、车端对接、厂商协议适配 |
| **路径规划/调度** | 路径规划、避让、锁区、交通管制、充电休息、跨楼层 |
| **数据/报表** | 数据统计、报表、经营指标 |
| **系统设置/运维** | 系统配置、许可证、部署、升级 |
| **权限/审计** | 用户/角色、操作日志、鉴权 |
