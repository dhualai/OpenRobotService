# 回归信号：改动之后，「有没有变坏」

## 为什么有它

这一轮（[issues.md](../issues.md) #22）删掉了自评和旧 `eval/` —— 那一把尺子量不出东西
（手写陷阱用例换配置照样全过），删得对。但删完之后**一个度量都没有了**：改完只能说
「逻辑对」（单测），说不了「没把别的地方弄坏」。

这个目录补的就是这一层。**它不判「答得对不对」**（那需要标准答案，而讨论问答的标准
取决于用户问了什么 —— 同一个结论在 #22 里已经论证过），只判**「有没有踩这几类明显的错」**。

## 四个信号（全部确定性、可复现、**不调 LLM**）

| 信号 | 判什么 | 数据从哪来 |
|---|---|---|
| **S1 人名幻觉** | 回答里提到的**人名**，在「工单描述 + 提问前的讨论史」里出现过吗 | `users` 表的人名集合，拿去和材料对（不是 NER，无模型） |
| **S2 引用真实性** | 回答里 `#N` 引用的工单，库里真的存在吗 | 全部工单 id |
| **S3 放弃式收尾** | 「无法确认/信息不足」这类话术的占比 | 回答正文的模式匹配 |
| **S4 覆盖率** | 每条用例**能不能算**（材料为空就无从核对，单独标出、不进比率） | 用例自带 |

S1 是这里最值钱的一个 —— 它就是 #4 那个 bug 的形状（回答里冒出材料里没有的人）。

## 怎么跑

```bash
# 1. 抽真实用例（要连生产库）—— 生成物含真实人名与工单正文，不入库（.gitignore 已挡）
python -m ai.agents.AiTaskPlatform.regression.build_cases --limit 20

# 2. 存一份基线（当前状态作为「没坏」的参照）
python -m ai.agents.AiTaskPlatform.regression.run --save-baseline

# 3. 以后每次改动后跑一遍：退化就非零退出，可当 CI 卡口
python -m ai.agents.AiTaskPlatform.regression.run
```

退出码：`0` 没退化 / `1` 有退化 / `2` 用法或数据问题。加 `--json out.json` 落逐条明细。

**跑检查不需要数据库**：人名表与工单号表在**抽取时**就烤进了数据集，所以 `run` 是纯离线的。
（也顺带保证基线可比 —— 人名表变过，同一份回答的 S1 结果会漂。）

## 抽取纪律（改 `build_cases.py` 前先读）

- **材料必须早于提问** —— 提问之后的评论绝不进材料，否则 AI 自己的回答混进证据，
  核对就变成抄答案。这是唯一不可让步的一条，`test_build_cases.py` 里锁着。
- **同一张工单默认只取 1 条** —— 否则 20 条可能其实只有 1 个观测（一张话痨工单占满样本）。
- **滤掉系统通知** —— 归档/派审/指派这类后端自动消息不是讨论。
- **真人发言 < 2 条的工单跳过** —— 没有讨论就无从核对人名。
- **作者名走生产同一套还原**（`author_display_name`，含未实名代称）——
  材料必须与模型当时看到的长得一样，否则量的是另一个东西。

## 边界（别把它当质量分读）

- **它不量「答得对不对」**。指标降下去 ≠ 答得更好，只说明**没踩这几个坑**。
- **S1 只查人名，不查错误码/数字**：错误码的合法来源（日志分析、知识库）**不在**我们
  重建的材料里，拿它当幻觉会大面积误报。
- **材料不含**当年的附件分析 / 检索结果 / 记忆 —— 所以 S1 抓的是「凭空冒出来的人」
  这类硬错，不是全部幻觉。
- **分母都写清楚**：没提到人名的用例不进 S1 分母，否则「没提」会被算成「提得对」。

## 还缺的那一半

**没有人工锚点，就只能证明「没退化」，证明不了「变好了」。**

要回答后者，得固定一小批用例人工打分（每批抽 5 条即可），把它和这四个信号放一起看。
在那之前，这份报告的意义是：**改动不会悄悄把已经踩过的坑重新踩一遍**。
