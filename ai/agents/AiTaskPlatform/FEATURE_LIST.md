## 一、架构边界说明

任务 Agent 是整个「系统任务」模块的 AI 组件，覆盖以下位置：

```
系统任务页面
├── ChatPanel（顶部 AI 助手）
│    └── 自由问答：能感知用户所有工单+诊断信息，自然语言问答
│
├── 工单卡片列表（全部/待处理/已完成）
│    └── 数据源：GET /api/tasks/（后端从 tasks 表查，非本模块职责）
│
└── 工单详情 Popup
     └── AI 深度诊断信息（静态展示，非多轮对话窗口）
          └── 新派单自动触发诊断生成
```

**本模块不涉及**：后台管理、工单卡片列表 CRUD、微信服务号。

另外，**智能派单（Assigner）** 是提单 Agent（AiDiagnosisPlatform）的子功能，归属「我要摇人」模块，由本工程师交付，不在本表内（已由提单 Agent 负责人上报）。

## 二、已完成功能（✅）

### 2.1 自由技术问答

| 项目 | 说明 |
|------|------|
| 能力 | 工程师在系统任务页面 ChatPanel 自由提问 AGV/AMR 技术问题（错误码、配置、故障排查等） |
| API | `POST /api/ai/task/chat/stream`（SSE 流式） |
| 对话记忆 | 同一 session_id 跨 chat/analyze 上下文连续，Redis memory 共享 |
| 状态 | ✅ **已完成** |

### 2.2 工单深度分析诊断

| 项目 | 说明 |
|------|------|
| 能力 | 基于提单 Agent 输出的 diagnosis JSON，三路并行分析 → 生成结构化方案草稿 |
| 三路 | ① 排查树结论检索（Qdrant troubleshooting collection）② 历史工单方案检索（task_resolutions collection）③ 附件解析 |
| 输出 | `SolutionDraft`：根因分析 + 建议步骤（可执行）+ 参考来源 + 置信度 |
| 铁律 | Prompt 硬编码四条铁律：不复诊 hypotheses、不排查 ruled_out、不追问已收集信息、不编造 |
| API | `POST /api/ai/task/analyze/stream`（SSE） + `/api/ai/task/analyze` + `/api/ai/task/submit` |
| 状态 | ✅ **AI 核心已完成**，前端接入待架构调整（见三） |

### 2.3 附件解析

工程师上传的附件类型：**图片** / **ZIP 压缩包** / **解压后的文件夹** / **日志文件**。

| 附件类型 | 当前能力 | 状态 |
|------|------|:---:|
| 日志文件（.txt / .log） | ✅ ERROR/WARN/FATAL/EXCEPTION 行提取 + 首尾时间范围 + 截断保护（文本 ≤100KB，摘要 ≤2000 字） | **已完成** |
| CSV 文件 | ✅ 当纯文本读取，与 .log 一致的处理逻辑 | **已完成** |
| ZIP 压缩包 | ❌ 未处理。需要解压 → 遍历内部目录 → 对日志型文件做提取 | 未完成 |
| 图片（png/jpg/...） | ❌ 未处理。需 OCR 文字识别提取错误码/界面文字，或至少提取文件名/EXIF 作为上下文 | 未完成 |
| 解压后的文件夹 | ❌ 未处理。需遍历目录树 → 识别文件类型 → 分别处理 | 未完成 |
| 回放文件 | ❌ 预留了解析入口（`has_replay` 标记位 + 骨架代码），解析逻辑未实现 | 未完成 |

**已实现的容错能力**：附件不存在/不可读时静默跳过，不阻塞主流程；大文件自动截断，不撑爆 LLM context。

### 3.1 自由聊天与诊断分离（P0，架构重构）

| 现状 | 目标 |
|------|------|
| 点击工单 → ChatPanel 内流式分析 → SolutionCard（聊天内渲染） | **Chat 独立**：自由问答不依赖选中工单，但能感知用户所有工单；**Diagnosis 独立**：新派单自动触发，工单详情页静态展示 |

**需要做**：

- [ ] Chat API 改造：能访问当前用户**所有**工单的诊断信息，回答"我现在有什么急单""哪个工单最优先处理""这个错误码我的另一个工单是不是也有"
- [ ] Diagnosis 剥离成独立服务：检测新派单 → 自动生成 → 写入 tasks.diagnosis
- [ ] 工单详情页面：直接渲染诊断结果（非聊天窗口），移除多轮对话
- [ ] SolutionCard 改造成静态展示 + 提交（去掉聊天气泡外壳）

### 3.2 附件解析升级（P1）

工程师上传的实际类型：图片 / ZIP / 解压文件夹 / 日志文件。

| 类型 | 要做的事 | 优先级 |
|------|------|:---:|
| ZIP 压缩包 | 解压 → 遍历内部目录树 → 对识别出的日志/文本文件做提取 | P0 |
| 解压后的文件夹 | 同 ZIP 逻辑，少了"解压"步骤 | P0 |
| 图片 | 有 OCR 能力时的路径：提取文字 → 错误码/界面信息作为诊断上下文。无 OCR 时：提取文件名和 EXIF 作为弱上下文 | P2 |
| 回放文件 | 需要回放格式说明 → 解析路径起点/终点/状态变化节点 | P2 |
