# 智能派单系统说明

> 位置：`ai/agents/AiDiagnosisPlatform/assigner/`
> 核心流程：`pipeline/dispatch_flow.py::DispatchFlow.aassign`
> 触发方式：Redis Pub/Sub 事件驱动 + 定时扫描兜底（`pipeline/worker.py`）
> 对照设计：`v1.0.2智能派单改动设计.md`（现行口径以本文 + 该设计为准）
>
> **准入门槛**：Step1–6 的候选人必须画像完整（部门、职级、责任模块都有）。缺任一项进不了召回/精排/仲裁。Step0 指定人和 Step7 兜底人不受此限：指定人在职就派；对接人/项目经理是配置的兜底人，画像不全也派。

---

## 一、整体流程（8 步）

```
TicketContext（工单）+ EngineerProfile（候选项:工程师画像）
    │
    ▼
【Step 0 提单人指定】结构化/弱信号识别指定接单人；命中即返回
    │ (未指定 / 指定人找不到)
    ▼
【Step 1 候选收紧】部门 → 产品（模块层不收紧）
    │
    ▼
【Step 2 打标】提单人 / 对接人 / 倾向接单人 / 原不满意接单人
    │ 描述含 [问题描述不完整] → 跳过 Step3–6
    ▼
【Step 3 三路召回】并行 L1 LLM / L2 语义 / L3 历史
    │
    ▼
【Step 4 精排 + 职级轻折扣】倾向人保底 0.9；对接人只打标
    │
    ▼
【Step 5 负载均衡】代码保留，enabled=false，主流程不调用
    │
    ▼
【Step 6 LLM 仲裁】铁律 + 产品附录；失败 / 名单外 → None
    │ (交不出人)
    ▼
【Step 7 兜底】对接人 → 本单项目经理 → 配置项目经理
    │ (三者都空)
    ▼
未指派 + 写 dispatch_log（unassignable）；提单人看到失败 tip；工单保持未指派；下一轮再试
```

---

## 二、各步骤详解

### Step 0 提单人指定
两级策略，**命中即直接返回，不走后续流程**：
1. **强信号**：结构化格式 `[指定处理人：XXX]`（提单 Agent 标准输出），正则直接提取人名匹配，**不调 LLM**，置信度 **0.95**。
2. **弱信号兜底**：自由文本（"这个给张三看一下""转给李四"等）先做轻量预判，疑似有指定意图才调 LLM 识别，避免每单白跑一次 LLM。

指定人找不到 → 记下 `profile.specified_name`，继续智能派单（候选池有门槛，只会派画像完整的人）；tip 与重派同一出口 `build_redispatch_tip`。重派未派到倾向人时该出口出详情模板（谁没派上、改派给谁、原因、下一步），不用「暂未采纳」短句。

未指定 → 继续走正常流程。

**本版口径：一张单只派一个指定人。** 提单 Agent 写成 `[指定处理人：张三、李四]` 时，按顺序找得到的人派上，tip「工单暂时只允许分配一个处理人」；画像不完整再叠「接单人画像不完整。」；同名再叠同名句。第一人找不到则试后面的人。两条独立强信号仍只取第一次、不打多人标记。弱信号「张三和李四」仍只抽一个名。详见 `v1.0.2智能派单改动设计.md` §3.1 / §9.2。

### Step 1 候选收紧（`filtering/candidate_tightener.py`）
把工单归到部门，再收到产品；模块层本版不收紧：
- 部门：R2 LLM 为主判、R3 历史为佐证；够确信才 hard_filter
- 产品：项目标记 > 部门映射 > 默认产品
- 收紧后无候选人 → 回退全量

### Step 2 打标（不踢自提人）
四标签进精排快照，一路传到 Step6：
- 提单人
- 项目对接人
- 倾向接单人（重派表单）
- 原用户不满意的接单人（上一轮 assigned）

模糊强信号：配置 `vague_strong_signals.keywords`。本版先认问题描述/标题里的 **`[问题描述不完整]`**。命中则跳过 Step3–6，进 Step7，理由「描述含模糊强信号，无法可靠召回」。

### Step 3 三路召回（并行执行）
| 路 | 权重 | 机制 |
|----|------|------|
| **L1 纯 LLM 召回** | 0.70 | LLM 看画像打分并给一句话原因。人少单轮 Top5；人多分批每批 Top3，并集全部进 Step4，不再决选 |
| **L2 语义召回** | 0.15 | Embedding 工单 → 模块锚文本 → 反查工程师 |
| **L3 历史召回** | 0.15 | A路:相似工单聚人（Qdrant）+ B路:问题域聚人。转派旁路本版恒空 |

任一路异常仅跳过该路，不阻断整个派单。给大模型看的人一律 `姓名:张三 ID:u-zhang`。

### Step 4 精排 + 职级折扣（`ranking/ranker.py`）
`raw_total = Σ(各路分数×权重)`，再乘职级轻折扣（管理级约 0.90）。  
对接人 / 提单人 / 原不满意只打标不加分。倾向接单人 `total = max(分, 0.9)`。不对仲裁再砍 TopK。

### Step 5 负载均衡
代码在 `dispatch_flow._apply_load_balance`，配置 `load_balance.enabled=false`，**主流程不调用**。

### Step 6 LLM 综合决策（`ranking/llm_decision.py`）
LLM 看工单 + 召回原因 + 精排全量窗口 + 标签，给出最终人选。  
失败 / `can_decide=false` / 名单外 id / 姓名当 id → 返回 `None`，**禁止**回精排 #1。

### Step 7 规则兜底（`ranking/fallback_decision.py`）
不再按分数阈值选人。顺序：

1. 本单项目对接人
2. 本单 `project.project_manager_id`
3. 配置 `project_manager_id`

有人 → `decision_type=fallback`，理由按来源（模糊截断 / Step6 交不出人）。这三人都是配置的兜底人，**不看** Step1–6 的画像完整门槛。

**三者都空怎么返回：**

| 层 | 行为 |
|----|------|
| `DispatchFlow.aassign` | 返回 `AssignmentResult`：`engineer_id=""`，`profile.unassignable=true`，不编精排 #1 |
| Worker | 写 `task_dispatch_log`（空 assigned_id）；不写 `assigned_to`；不发已派单通知。同一失败不重复刷轮次 |
| 工单 | 保持新建 + 未指派；下一轮扫描再试 |
| 提单人 | 列表/详情 tip：「暂时无法派单：项目未配置对接人和项目经理，工单还没有接单人。配置后系统会继续尝试。」 |

## 三、数据模型（`schemas.py`）

| 模型 | 数据来源 | 说明 |
|------|---------|------|
| `TicketContext` | 后端 `tasks` 表 | 工单上下文（含故障码、车型、Project、Agent 诊断信息） |
| `EngineerProfile` | 后端 `users` 表 | 工程师画像（部门、职级、责任模块、职责） |
| `AssignmentResult` | — | 派单结果：`engineer_id/name` + `confidence_score` + `decision_type`(auto/recommend/fallback) + `reasoning` |

派单结果写回 `tasks.assigned_to` + `task_dispatch_log`（置信度/理由/决策类型/画像快照）。  
Step7 都空时不写 `assigned_to`，但写一条 `unassignable` 日志，供提单人 tip。

## 四、日志格式

所有派单日志**工单编号置前**，便于按单串联整条链路：

```
[派单:{id}] 开始派单 | 工单=... | 描述=... | 故障码=... 车型=... | 候选=N人
[派单:{id}] Step0 提单人指定 → 张三(...) 置信=0.95
[派单:{id}] Step0 指定人未命中，记下 specified_name=... 进入后续
[派单:{id}] Step1 候选收紧 N→M人 | 部门=... | 产品=...
[派单:{id}] Step2 提单人=... 保留在候选
[派单:{id}] Step2 模糊强信号命中 → 跳过 Step3–6，进 Step7
[派单:{id}] Step3 L1召回 | 命中=... | 姓名:张三 ID:u-zhang=0.95
[派单:{id}] Step3 转派旁路 transfer_signals=empty
[派单:{id}] Step3 L2召回 | ...
[派单:{id}] Step3 L3召回 | ...
[派单:{id}] Step4 精排Top | #1 ... 总=... LLM=... 语义=... 历史=... [标签]
[派单:{id}] Step6 LLM决策 → ... 或 Step6 交不出人 → 交 Step7
[派单:{id}] Step7 → 对接人/项目经理 理由=...
[派单:{id}] Step7 对接人与项目经理都空，派单失败（不拔精排#1，写 tip 不派人）
[派单:{id}] 派单结果[Step7兜底] | 未指派 unassignable | 理由=...
[派单:{id}] 派单结果[...] | 指派=... | 置信度=... 决策=...
```

环境里核对某单：在 `ai/logs/assigner/assigner.log` 搜 `[派单:{id}]`。

### 编号统一说明
- **主流程**：连续 `Step0`~`Step7`
- **子模块内部**：标注父步骤层级
  - 部门过滤 → `Step1-部门匹配` / `Step1-部门过滤`
  - L1 召回 → `Step3-L1` · L2 → `Step3-L2` · L3-A → `Step3-L3-A` · L3-B → `Step3-L3-B`
- 工单编号一律 `[派单:{id}]` 开头

## 五、关键配置（`assigner/settings.py` ← config.yaml）
- 三路召回权重：L1=0.70 / L2=0.15 / L3=0.15
- L3 内部 A/B 路权重：默认各 0.5
- 部门融合门槛：见 `department_routing.thresholds`
- 负载均衡：`enabled=false`，主流程不调用
- 模糊强信号：`vague_strong_signals.keywords` 含 `[问题描述不完整]`
- L1 人数：单轮 Top5；分批每批 Top3 全进精排
- 倾向人保底：`preferred_floor=0.9`
- 仲裁窗口：`llm_decision_topk=0`（不截）
- Step7 配置项目经理：`project_manager_id`（默认为空）
- `decision_thresholds` 为遗留键，Step7 不再按分数选人
