# 智能派单系统说明

> 位置：`ai/agents/AiDiagnosisPlatform/assigner/`
> 核心流程：`pipeline/dispatch_flow.py::DispatchFlow.aassign`
> 触发方式：Redis Pub/Sub 事件驱动 + 定时扫描兜底（`pipeline/worker.py`）

---

## 一、整体流程（8 步）

```
TicketContext（工单）+ EngineerProfile（候选项:工程师画像）
    │
    ▼
【Step 0 提单人指定】先看提单人有没有明确指定接单人
    │ (未指定)
    ▼
【Step 1 部门过滤】把工单归到部门，只在部门候选人里挑
    │
    ▼
【Step 2 排除提单人】常规派单不派给自己
    │
    ▼
【Step 3 三路召回】并行召回候选工程师（L1/L2/L3）
    │
    ▼
【Step 4 精排 + 职级折扣】
    │
    ▼
【Step 5 负载均衡】按在途工单数打折，避免单子扎堆
    │
    ▼
【Step 6 LLM 综合决策】LLM 看全量信息定最终人选
    │ (LLM 失败/为空)
    ▼
【Step 7 规则兜底】按分数阈值 auto/recommend/fallback
```

---

## 二、各步骤详解

### Step 0 提单人指定
两级策略，**命中即直接返回，不走后续流程**：
1. **强信号**：结构化格式 `[指定处理人：XXX]`（提单 Agent 标准输出），正则直接提取人名匹配，**不调 LLM**，置信度 **0.95**。
2. **弱信号兜底**：自由文本（"这个给张三看一下""转给李四"等）先做轻量预判，疑似有指定意图才调 LLM 识别，避免每单白跑一次 LLM。

未指定 / 未匹配 → 继续走正常流程。

### Step 1 部门过滤（`filtering/department_filter.py`）
把工单归到部门，只用该部门候选人：
- **strong 关键词** 命中 → 直接判定部门
- **medium + weak 组合** 命中 → 判定部门
- 均未命中 → **embedding 语义匹配** 部门故障场景（阈值默认 0.65）
- 跨部门歧义 → 不过滤（让多部门一起参与召回 + LLM 决定）
- 过滤后无候选人 → 回退全量

### Step 2 排除提单人
把提单人本人从候选人移除（常规不派给自己）。移除后为空则回退全量。

### Step 3 三路召回（并行执行）
| 路 | 权重 | 机制 |
|----|------|------|
| **L1 纯 LLM 召回** | 0.70 | LLM 看全员画像(duty/modules) 直接打分，人少单轮全量、人多分批初选+合并决选 |
| **L2 语义召回** | 0.20 | Embedding 工单 → 模块锚文本(产品-类别) → 反查工程师 |
| **L3 历史召回** | 0.10 | A路:相似工单聚人（Qdrant 向量检索）+ B路:问题域聚人（经验画像） |

任一路异常仅跳过该路，不阻断整个派单。

### Step 4 精排 + 职级折扣（`ranking/ranker.py`）
`raw_total = Σ(各路分数×权重)`，再乘 **职级惩罚系数**（job_level）。

### Step 5 负载均衡
`load_factor = 1 / (1 + 在途数 × step)`，在途越多人打折越多，查询带 **30s 缓存**。

### Step 6 LLM 综合决策（`ranking/llm_decision.py`）
LLM 综合工单 + 召回结果 + 排名，直接给出最终人选（返回 `AssignmentResult`）。

### Step 7 规则兜底（`ranking/fallback_decision.py`）
LLM 失败/为空时，按 Top-1 分数阈值：
| 阈值 | 决策类型 | 含义 |
|------|---------|------|
| ≥ 0.8 | `auto` | 直接拍板 |
| ≥ 0.5 | `recommend` | 建议确认 |
| < 0.5 | `fallback` | 兜底派单（建议复核） |

## 三、数据模型（`schemas.py`）

| 模型 | 数据来源 | 说明 |
|------|---------|------|
| `TicketContext` | 后端 `tasks` 表 | 工单上下文（含故障码、车型、Project、Agent 诊断信息） |
| `EngineerProfile` | 后端 `users` 表 | 工程师画像（部门、职级、责任模块、职责） |
| `AssignmentResult` | — | 派单结果：`engineer_id/name` + `confidence_score` + `decision_type`(auto/recommend/fallback) + `reasoning` |

派单结果写回 `tasks.assigned_to` + `metadata_info`（置信度/理由/决策类型）。

### 编号统一说明
- **主流程**：连续 `Step0`~`Step7`（原 `-1/0/0.6/1/2.5/3/4` 已规整）
- **子模块内部**：标注父步骤层级
  - 部门过滤 → `Step1-部门匹配` / `Step1-部门过滤`
  - L1 召回 → `Step3-L1` · L2 → `Step3-L2` · L3-A → `Step3-L3-A` · L3-B → `Step3-L3-B`
- 工单编号一律 `[派单:{id}]` 开头

## 五、关键配置（`assigner/settings.py` ← config.yaml）
- 三路召回权重：L1=0.70 / L2=0.20 / L3=0.10
- L3 内部 A/B 路权重：默认各 0.5
- 部门 embedding 阈值：默认 0.65
- 负载均衡 `step`：默认 0.15（缓存 30s）
- 兜底阈值：auto ≥ 0.8 / recommend ≥ 0.5 / fallback < 0.5
