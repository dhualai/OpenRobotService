# 00 - 架构总览

## 1. 系统定位

本系统是统一调度平台 (USP — Universal Scheduling Platform) 的**算法服务层**，核心职责：

- 维护仓库的**数字地图**（路网点/线/功能点）
- 为 AGV/AMR 机器人做**多车路径规划** (MAPF)
- **分配任务**（业务任务、充电任务、休息任务、避让任务）
- **预处理**地图数据（原始地图 → 算法可用数据结构）
- **AI 辅助**建图（标注 → 路网、障碍物识别、碰撞检测）

### Actor 发现方式

所有 Actor 在同一 Ray 集群中通过 `name + namespace` 互相发现：

```
namespace: "USP-ALGORITHM-SERVICES"
  ├── "DYNAMIC-MAP-SERVICES-ACTOR"      (DynamicMapServiceActor)
  ├── "TASK-MANAGER-SERVICES-ACTOR"    (TaskManagerServiceActor)
  ├── "TMS-SERVICES-ACTOR"             (TMSServiceActor)
  ├── "TMS-SERVICES-ACTOR-{map_id}"    (TMSMapServiceActor × N)
  ├── "MAP-PREPROCESS-SERVICES-ACTOR"  (MapPreprocessServiceActor)
  ├── "AI-SERVICES-ACTOR"              (AIMapServiceActor)
  └── "AI-MAP-PROGRESS-COLLECTOR"      (AIMapProgressCollector)

namespace: "USP-MAP-PREPROCESS-SERVICES"
  ├── "PROGRESS-COLLECTOR"             (ProgressCollector)
  ├── "LOAD_LEVEL_DISPATCHER"          (LoadLevelDispatcher)
  └── "PREPROCESS_WORKER_{id}_{hash}"  (DistributedPreprocessor × N)
```

## 3. 数据流向

### 主循环数据流

```
后端服务 (Java/Go)
     │
     │  POST /refreshRobotStates          (~200ms/次)
     │  POST /refreshSchedulingTasks      (有新任务时)
     ▼
DynamicMap ←───────────────────────── TaskManager ←────── TMS
  │ 维护所有机器人状态                   │ 根据任务+机器人     │ 计算全图路径
  │ 维护路径+锁区                        │ 做匹配分配          │ 通过 MAPF 算法
  │                                      │                     │
  │◄────── ray.get(get_robots_data) ─────│                     │
  │◄────── ray.get(get_functional_points)│                     │
  │                                      ├── POST /allocateRobots ──► 后端
  │◄────── ray.get(update_paths) ────────┼──────────────────────┘
  │                                      │
  │── POST /updatePaths ────────────────► 后端 ──► 机器人
  │   (下发路径)
  │── POST /createTasks ────────────────► 后端
  │   (创建避让任务)
  │
  │── 返回 trafficLocks + lineRegistration ──► 前端可视化
```

### 地图加载流

```
后端 POST /updateMaps
     │
     ▼
DynamicMap.update_maps()
     │
     ├── _load_path_planning_map_from_disk()
     │   从磁盘加载 4 档预处理数据：
     │   1. load_level_preprocessed_maps/{id}/{hash}.json  (最高精度)
     │   2. preprocessed_maps/{id}/{hash}.json              (完整)
     │   3. minimum_preprocessed_maps/{id}/{hash}.json      (最小可用)
     │   4. none_preprocessed_maps/{id}/{hash}.json         (原始)
     │
     └── 构造 PathPlanningMap → TrafficShapeManager → FunctionalPoints
```

### 路径下发流

```
TMS 算出路径
     │
     ▼
DynamicMap.update_paths()
     │  校验路径有效性 (过期检查)
     │  更新 line_registration (线路占用)
     │  更新 dependency_network (依赖网络)
     │
     ▼
DynamicMap.try_release_node()
     │  依赖满足性检查
     │  几何冲突检查 (shape_conflict_free)
     │  电梯互斥 → 等待语义
     │  释放节点 → 创建 ReservedTrafficLock
     │
     ▼
DynamicMap.extract_and_send_paths()
     │  提取需要发送的路径段
     │  POST /updatePaths → 后端
     ▼
后端 → 机器人
```

## 5. 关键技术概念

### 5.1 并发控制模式

两层并发控制：

1. **Ray Actor 级别**：`max_concurrency` 限制同时处理的请求数
2. **路由级别**：`self.listener_routes[route] = True/False` 保证同一路由单并发

```python
# service_actor.py - handle_request()
if not self.listener_routes[route]:
    return self.return_route_busy(route)  # 返回 "路径繁忙中"

self.listener_routes[route] = False  # 锁定
result = self.process_request(route, request)
self.listener_routes[route] = True   # 解锁
```

### 5.2 锁区 (Traffic Lock) 类型

| 类型 | 类 | 来源 | 生命周期 |
|------|-----|------|----------|
| 物理锁区 | RobotPhysicalTrafficLock | 机器人当前位置 | 随位置更新 |
| 预约锁区 | RobotReservedTrafficLock | 路径节点释放时创建 | 节点被释放后 |
| 定位锁区 | RobotLocatedTrafficLock | 上轨定位区域 | 随位置更新 |
| 载具物理锁区 | LoadPhysicalTrafficLock | 载具当前位置 | 随位置更新 |
| 固定限行 | RestrictedTrafficLock | 手动创建 | CRUD 管理 |
| 固定障碍 | ObstacleTrafficLock | 手动创建 | CRUD 管理 |
| 库位障碍 | StorageObstacle | 功能点初始化 | 长期 |
| 充电桩障碍 | ChargeObstacle | 功能点初始化 | 长期 |
| 设备障碍 | DeviceObstacle | 功能点初始化 | 长期 |

### 5.3 路径结构

```
path.nodes = [PathNode_0, PathNode_1, ..., PathNode_N]
              │              │
              │              └── last_node_index (车当前位置对应节点)
              └── last_released_index (已释放的最远节点)

last_released_index ≥ last_node_index

释放 = 把节点对应的边加到 reserved_traffic_locks，让其他车知道已被占用
```

### 5.4 地图预处理精度层级

| Level | 名称 | 包含内容 |
|-------|------|----------|
| 0 | none | 原始地图，无预处理数据 |
| 1 | minimum | 车型 moving_shape (最小可用) |
| 2 | fully | 车型 + Level 1 载具配置 (完整) |
| 3+ | load_level | Level 2+ 分级精化 (最高精度) |

DynamicMap 加载优先级：load_level > fully > minimum > none
